# PROP V2.1 测试风险评估文档

> 评估日期：2026-11-02
> 需求基线：`E:\proptest\spec\spec10-28\spec`，并以 `spec10-28-vs-spec9-29-变更分析.md` 识别版本增量。
> 评估方法：从业务流程闭环、跨模块事实关系、不可逆动作、历史与删除、时间口径、权限和版本差异中识别测试风险；风险等级按 Spec 复杂度、潜在业务影响和验证成本综合判断。
> 标记说明：Spec 未明确、未定稿或仍需裁决的风险统一标注 **【待确认】**；本文不补充未写明的业务规则，也不把文档存在等同于实现完成。
> 风险类型：业务逻辑风险、数据一致性风险、权限风险、回归风险、合规风险。

## 1. 评估范围

### 1.1 范围内

- FEAT-00～FEAT-20 的功能正文、业务边界、验收规则及其跨模块引用。
- 全局基线的业务流程、权限规则、身份与删除规则、日本业务日期与事件时间规则。
- Spec10-28 相对 Spec9-29 的新增、修订、取消项和“仅同步需求、未实现/未验证”的内容。
- 主业务闭环：衣体入库 → 部件组装 → 首次质检 → 订单 → 寄送准备 → 确认寄出 → 定期案内 → 受付 → 作业与报告 → 返送、回收或报废。
- 跨模块验证关注点：客户与快照、订单履约、产品身份、生命周期、编号序列、文件版本、删除历史、看板统计、权限与时间。

### 1.2 范围外

- Spec 未要求的财务、税务、收款、对账、会计和正式請求書能力。
- 具体技术架构、数据库选型、性能容量、打印机型号/驱动及网络基础设施的选型正确性；但相关行为风险仍纳入本文。
- 客户内部线下作业质量，以及系统外的物流实际投递、实纸送达和人工签署结果。
- 未被 Spec 定义的外部法规、个人信息保存期限或行业监管义务；此类事项只作为待确认风险提出。

### 1.3 评估前提

- 测试以 `spec10-28\spec` 为唯一需求基线，旧版、历史 demo、原型截图和讨论记录不能覆盖当前正文。
- 需求确认不等于代码已实现；测试前必须建立“需求/Change → 构建 → 可测页面/接口”的对应关系。
- 标注【待确认】的事项，在确认前按保守影响评估；若涉及对外文件、不可逆动作或权限，应视为发布前必须明确的事项。

## 2. 风险等级定义

| 等级 | 定义 | 典型判定 | 测试响应 |
|---|---|---|---|
| 高 | 可能导致不可逆错误、跨客户/订单/产品串用、核心事实丢失、生命周期或最终去向错误、权限越权、广泛回归，或无法通过普通业务操作恢复 | 影响主链或跨模块状态；涉及确认寄出、回收、报废、返送、序号、基准月、文件冻结、权限、日本时间等 | 发布前必须验证；P0/P1 优先；异常、并发、重试、回滚和跨模块回读均需取证 |
| 中 | 可能造成局部功能错误、可人工纠正的数据偏差、特定条件下的流程阻塞，或对外文件局部不一致 | 影响单模块或特定分支；已有可行 workaround；不直接造成跨对象串用或不可逆结果 | 验收前完成；对应场景必测；未覆盖需记录原因和残余风险 |
| 低 | 主要是显示、排序、文案、易用性或低影响一致性问题，且有明确人工绕过方式 | 不影响业务事实、权限、金额、日期和核心状态 | 可纳入回归或体验检查；不阻断主流程 |

**待确认项处理：** 【待确认】不改变风险类型；若尚未明确且潜在影响达到高等级，先按“高”或“中高”保守排期，待业务/客户确认后调整，不在测试中自行补规则。

## 4. 高风险汇总

当前风险清单共 42 项，其中高风险 26 项。高风险不是“必然缺陷”，而是表示一旦实现偏差，可能造成不可逆事实、跨对象串用、权限越权、对外文件错误或大面积回归，应优先安排验证。

| 高风险主题 | 涉及编号 | 风险原因 | 最小验证出口 |
|---|---|---|---|
| 交付、订单与生命周期主链 | B-01、B-04、B-08、D-01、D-02、D-07 | 确认寄出同时影响寄送、订单关系、履约和基准月，任何一条派生数据不同步都会把错误扩散到后续通知和受付 | 首次/分批寄出、取消、解除、回收全链路通过；页面、接口、数据库和看板口径一致；重复提交和失败回滚无残留 |
| 不可逆动作与历史保留 | B-02、B-07、B-13、D-03、D-05、C-04 | 质检、寄出、回收、报废、删除均可能产生不可逆事实；错误记录不能靠普通业务操作恢复 | 每个不可逆动作执行前后均有事实证据；错误入口不存在；正式寄出后不可删除；历史身份与文件版本可追溯 |
| 案内、报告与对外文件 | B-05、C-02、D-06、R-03、R-04 | 受付匹配、超期、报告对象和文件冻结决定客户看到的正式内容 | 同日/旧案内/删除受付组合正确；报告入口与对象正确；历史文件重看内容不变；源主档变化不影响冻结版本 |
| 权限与日本时间 | P-01、P-02、D-04、R-01、C-01 | 页面隐藏不等于服务端受控；时间口径错误会在跨日、跨月、年度边界制造系统性偏差 | 无权限直达与接口均拒绝；共享读取不扩大写权限；多时区下日期筛选、发行日、受付日和年度编号一致 |

## 6. 测试优先级建议

### 6.1 执行顺序

| 优先级 | 建议范围 | 主要风险编号 | 完成标准 |
|---|---|---|---|
| P0-A 评估前置 | 需求/Change/构建映射；测试账号和页面权限矩阵；日本时间环境；主档、部件、产品、订单、案内、受付、返送基础数据 | S-01、S-08、P-01、P-02、P-04、D-04、R-01 | 每个被测功能可定位到实现；无权限和共享读取权限可验证；多时区环境可切换；主链数据可重复准备 |
| P0-B 主闭环与不可逆动作 | 最小闭环；确认寄出；回收/报废/返送；质检；生命周期与案内；受付与作业；文件冻结与删除 | B-01、B-02、B-04、B-05、B-07、B-08、B-11、B-13、D-01～D-07、D-10、P-01、P-02、R-01、R-03、R-04、R-08、C-01、C-02、C-04、C-05 | 所有高风险有通过或被接受的残余风险记录；核心事实可跨模块回读一致；失败、重复和并发不留下部分数据 |

### 6.2 推荐最小数据包

- 一台产品覆盖 0 年目、1 年目、4 年目和 5 年目基准月边界，并至少有一台已回收、一台已报废对照。
- 一个订单覆盖分批寄送、超发阻断、取消、解除并保留基准月、解除并清空基准月。
- 一份客户同时具有公司/支店、不同納品先和请求书先，用于客户区分、快照与案内抬头核对。
- 一个受付大番号包含多个包裹和多台产品，覆盖多类型、未选类型、年度 1～4、客户确认备注、清洗和展开维修。
- 一台已完成返送后再报废、一台已回收、一台已报废、一台已返送产品，用于最终去向互斥。
- 一组同日生成多份案内、跨 30 天边界、删除受付后重算的案内数据。
- 一组同类历史租赁订单，覆盖首次交付、再次出租、已结束出租和当前占用冲突。
- 两组面单/报告数据：长名称、多产品、跨页、多张复印，用于文件版本和实纸输出。

### 6.3 进入与退出条件

**进入条件**

- 被测构建已确认包含目标 Change，或已明确哪些需求只做文档审阅。
- 测试账号具备页面级权限组合，可覆盖无权限、共享读取和页面维护场景。
- 日本时区环境、文件模板、基础主档和最小闭环数据可重复创建。
- 涉及正式文件或历史补录的待确认项已有业务负责人和临时处置口径。

**退出条件**

- 全部 P0 风险已验证通过，或高等级残余风险有明确责任人、影响范围和发布决策。
- 确认寄出、质检、回收、报废、返送、删除等不可逆动作均有前后状态和跨模块证据。
- 页面、接口、数据库、文件版本和看板之间不存在未解释的数量、日期、身份或状态差异。
- 【待确认】事项已关闭，或已明确不影响本次发布并记录为条件验收；不得用测试自行假设替代 Spec 裁决。
- 未实现功能未被误记为通过，正式文件模板/实纸参数未完成时未宣称打印验收通过。

- 本文件用于确定测试重点和发布风险，不替代业务流程图、验收用例或缺陷单。
- 风险等级可在获得明确 Spec 裁决、实现证据或业务接受后调整；调整时必须保留原依据和残余风险。
- 发现新的跨模块事实冲突时，应新增风险编号并关联受影响模块，不把问题仅记录为单页 UI 缺陷。
