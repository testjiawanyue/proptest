# ROADMAP

> 本 Roadmap 按二级导航粒度组织 Feature（FEAT-00～19，共 20 个），用于规划分期建设顺序。
> Feature 编号与 `docs/features/` 目录一一对应；业务规则以各 Feature 的 `spec.md` 为唯一基线，本文档不重复规则。
> 颗粒度原则：Feature 对应一个长期稳定的业务页面或一组强相关的同域页面；页面内的功能增强属于 Change，不新增 Feature。

## 建设阶段

### Phase 1：基础资料与客户
FEAT-02 部件资料、FEAT-03 基础数据、FEAT-04 作业选项、FEAT-01 客户管理。
建立各业务可选用的主档、字典与客户底座。

### Phase 2：产品生产与正式产品
FEAT-05 衣体入库、FEAT-06 部件组装、FEAT-07 质检工作台、FEAT-08 产品列表、FEAT-09 部件追溯。
跑通"衣体 → 部件绑定 → 质检 → 正式产品"。

### Phase 3：订单与实际履约
FEAT-10 订单管理、FEAT-11 寄送、FEAT-19 订单批量打印。
跑通"客户需求 → 订单 → 寄送 → 确认寄出建立产品订单关系"。

### Phase 4：生命周期与点检通知
FEAT-12 定期管理、FEAT-13 通知管理。
跑通"首次有效出货 → 生命周期 → 案内发行 → 受付回收跟踪"。

### Phase 5：返厂、专业作业与返送
FEAT-14 受付工作台、FEAT-15 受付履历、FEAT-16 作业管理、FEAT-17 返送、FEAT-18 返送批量打印。
跑通"返厂 → 受付 → 作业 → 报告 → 返送/回收/报废"。

### Phase 6：运营收口
FEAT-00 首页看板，并完成迁移、权限、打印/PDF 联调、全局回归与上线验证。

## 颗粒度规则

```text
Feature = 一个长期稳定的业务页面或同域页面组（对应 docs/features/ 一个目录）
Sub Function = Feature 内部功能项
Change = 对 Feature 的一次后续变化
Task / Issue = 实际开发任务
```

例如"部件组装增加批量扫码"属于 FEAT-06 的 Change，不新增 Feature。
