# FEAT-11 寄送 Validation

> **本次修订验证状态（2026-09-25）**：以下修改及新增场景为验收要求，均未执行；历史 demo 核对、旧测试结果不表示本次规则已验证。原型资产未更新，冲突表现以本次正文为准。

依据 [spec.md](spec.md) 逐页验收。本轮为静态核对稿，尚未执行浏览器实测、自动测试或构建。面单／纳品书／保障确认书／寄送通知邮件四类文件的模板与内容均为临时内容（后续以正式 spec 为准），本文件先验收入口、文件版本和业务边界。

## 1. 寄送抽屉

### VAL-01 准备中抽屉结构与底部状态（spec 4.1～4.4）

从订单详情点击「发货」打开准备中寄送抽屉，核对标题、左侧产品卡、右侧四类卡片、底部自动保存状态和三个操作按钮。

预期：标题为「寄送准备 · 订单号 · 寄送记录号」；左侧默认显示连续编号录入；底部显示自动保存或未保存状态，以及「删除」「保存」「补充运单号并确认寄出（本次 N 台）」。没有地址修改入口，没有步骤条或打印前置提示。

### VAL-02 单个编号录入（spec 4.4～4.6）

切换为「单个编号录入」，分别输入存在且可用的制造编号、空值、不存在编号、已报废产品、已关联其他订单产品、已在本次清单产品、超过订单剩余可发数量的产品。

预期：可用产品加入表格并提示成功；异常编号不加入，显示对应原因。本次清单列为 #、制造编号、产品规格、操作；删除按钮需经「从本次清单移除？」确认。

### VAL-03 连续编号录入（spec 4.4～4.6）

使用编号前缀、起始编号和结束编号录入连续范围；覆盖缺起止、起始大于结束、超过 100 台、范围内部分成功部分失败。

预期：合法编号加入清单；非法范围直接阻断；部分失败时列出失败编号和原因，已通过检查的编号保留。

### VAL-04 自动保存与保存边界（spec 4.5～4.7）

录入产品后更改快递公司、日期、箱数，关闭后重新打开；另在没有产品时尝试保存或打印。

预期：准备内容可接续；关闭不登记寄出、不建立产品与订单关系。没有产品时提示「请先至少录入一台产品」或「请先录入产品」，不能生成文件或确认。

### VAL-05 单笔生成三类文件（spec 4.4～4.8、6.1）

准备中录入产品后，分别生成面单、纳品书、保障确认书；每类至少生成两次，再关闭重开；已寄出后重复生成同类文件。

预期：已生成文件表显示每份文件独立版本行，历史版本不覆盖，面单／纳品书／保障确认书均可「继续打印」。生成文件不登记寄出、不增加订单履约数。「生成面单（N 张）」产生一个面单文件版本（N 张为复印份数、共用同一版本）并提示 N 为本次印出份数、每份使用同一份完整产品清单；保障确认书归属该笔发货，产品范围仅为生成时本次清单，不汇总同订单其他发货。

### VAL-06 已寄出抽屉结构与只读清单（spec 4.1～4.6）

打开已确认寄出的出货记录，核对标题、产品表、已生成文件、底部状态和关闭按钮。

预期：标题为「寄送详情 · 订单号 · 寄送记录号」；产品表无操作列，显示「已确认寄出」标签；底部显示「状态：已确认寄出 · 日期（寄送事实已登记，产品与订单关联不变；寄送内容可修改）」和「关闭并返回列表」。不显示删除入口，不允许增删产品。

### VAL-07 已寄出属性修改（spec 3.2、4.5～4.7）

在已寄出抽屉修改快递公司、实际寄送日期和箱数；刷新后回查订单详情出货记录和邮件正文。

预期：分别提示「快递公司已更新」「寄送日期已更新」「箱数已更新」；只保留最后修改结果和修改人员时间；产品清单、产品与订单关系、订单履约数不变。收货地址在寄送页不可修改。

### VAL-08 运单号维护与邮件版本化（spec 3.1～3.2、4.4～4.7、6.2～6.3）

在已寄出抽屉追加、修改、删除运单号并保存；点击「生成邮件正文」生成新版本，查看历史版本；测试无修改时按钮状态。

预期：行号、输入框、红色删除按钮、追加单号、生成邮件正文、保存单号均符合 spec；无修改时保存按钮不可用。保存后提示「运单号已保存」。点击「生成邮件正文」生成寄送通知邮件新版本（冻结当时正文与生成时间）并打开查看弹窗；已生成文件列表按版本逐行显示「寄送通知邮件 vN」与生成时间，操作为「查看」，弹窗显示该版本正文全文、可复制。历史版本不被覆盖；运单号修改不影响面单张数、箱数、寄送事实或订单履约数。

### VAL-08b 邮件生成时机与复制边界（spec 6.2）

确认寄出后检查已生成文件列表；随后仅修改快递公司／寄送日期／箱数／运单号但不点「生成邮件正文」，再检查列表。

预期：确认寄出后自动出现「寄送通知邮件 v1」；仅修改属性或运单号不产生新版本；文件列表中不存在按当前内容现算后直接复制的入口，复制只能从邮件版本的查看弹窗中取得。

### VAL-09 准备中删除（spec 4.5～4.7、7）

对无文件、有面单、有纳品书、有保障确认书的准备中寄送分别点击「删除」；先取消，再确认删除。随后回订单详情查找该笔。

预期：确认文案为「删除后不可恢复，是否确认删除？」；取消无变化；确认后准备、所属产品清单关联及全部所属文件和邮件版本消失（含保障确认书），不保留这些准备内容的业务历史、不要求原因、不登记寄出。产品档案、其他发货及文件、既有正式履约不变。已寄出记录无删除按钮，直接请求删除也被服务端拒绝。

## 2. 补充运单号并确认寄出弹窗

### VAL-10 弹窗字段与取消（spec 5.1～5.5）

在准备中已有产品时点击「补充运单号并确认寄出（本次 N 台）」，核对弹窗标题、说明、快递公司、运单号多行输入和按钮；点击取消。

预期：标题为「补充运单号并确认寄出」；确认按钮为「确认寄出并生成邮件（N 台）」；取消关闭弹窗，不登记寄出、不保存本次未确认输入。

### VAL-11 未选快递公司阻断（spec 5.4～5.6）

不选择快递公司，打开确认弹窗后直接点击确认。

预期：快递公司显示「未选择」，提示「请先在右侧「物流承运与寄送设定」中选择快递公司」；弹窗保持打开，不登记寄出。

### VAL-12 运单号选填与去重（spec 5.4～5.7、6.3）

分别以空运单号、一个运单号、多个不同运单号、重复运单号确认寄出。

预期：空运单号可确认；不同运单号保存为同一份运单号列表；重复时提示「运单号存在重复，请检查后合并」且不确认。确认后运单号可在已寄出抽屉继续维护。

### VAL-13 确认寄出业务结果（spec 4.7、5.7、6.4～6.5）

准备中录入多台产品，选择快递公司并确认寄出；回订单详情、产品详情和寄送抽屉复查。

预期：提示「已登记寄出 N 台」；订单详情出货记录出现该笔，订单履约数增加；产品与订单建立当前关系；已生成文件列表自动出现「寄送通知邮件 v1」。准备中生成过或未生成过文件都不影响确认；确认后产品清单冻结，快递公司、日期、箱数、运单号仍可维护。

### VAL-14 确认失败边界（spec 4.6、5.6）

在准备期间取消订单，或让产品已有关联、产品报废、产品业务属性与订单不兼容后，再尝试确认。

预期：不得确认寄出，提示对应失败原因；不建立产品与订单关系，不改变订单履约数。


## 3. 页面间闭环

### VAL-21 订单详情 → 寄送 → 打印 → 确认 → 订单结果（spec 6.1～6.6）

```text
订单详情新建寄送
→ 录入两台产品并保存准备
→ 生成面单、纳品书、保障确认书
→ 确认寄出
→ 回订单详情和产品详情核对
→ 为同一订单再建第二笔寄送
```

预期：打印阶段不计履约；确认后才建立产品与订单关系并增加履约数。同一订单可分批寄送；每笔只记录本次产品和物流资料，出货记录分笔展示。


### VAL-23 错误交付纠正边界（spec 3.2、6.4～6.5）

确认寄出后尝试在寄送页增删产品或回退状态；再从订单详情按订单模块规则解除产品关联。

预期：寄送页不提供增删、撤回、冲正、解锁或状态回退；错误交付纠正只能走订单维度解除产品关联。解除后历史寄送记录保留，寄送页仍不承担解绑入口。

### VAL-22 同订单两笔发货的保障确认书隔离

同订单建立准备 A、B，使用不同产品清单，分别生成保障确认书。改变 A 的准备清单后再次生成，再继续打印 A 的旧版本；最后删除有文件的 A。另将 B 正式寄出后尝试从界面及接口删除。

预期：A、B 文件分别只含生成时各自清单，各次版本独立且旧版不覆盖；A 删除连同其全部保障确认书、其他文件和所属关联一并删除，B 及其文件不受影响。生成／打印阶段不登记寄出、不改变履约或产品订单关系；B 正式寄出后所有保障确认书版本保留，界面无删除入口，服务端拒绝删除且数据不变。模板、版式、正文措辞不在本次定稿范围。

### VAL-09b 正式寄出后的服务端删除保护

对已正式寄出的记录直接请求删除，包括已生成多个文件版本的记录。

预期：服务端拒绝，发货、清单、全部文件及正式履约保持；不能绕过界面限制。

## 4. 回归检查清单

- 准备已生成文件仍可删除全部所属版本（含保障确认书）；正式寄出后接口拒绝删除；同订单文件不混入其他清单。

- 是否把打印、继续打印、复制邮件当成实际寄出？
- 是否要求先生成面单才能确认寄出？
- 是否在确认后把整个寄送变成只读，导致快递公司、日期、箱数或运单号不能维护？
- 是否重新加入「补录物流信息」独立入口？
- 是否把运单号数量与箱数、面单张数或产品台数互相推算？
- 是否重新出现按当前内容现算邮件正文后直接复制的旁路，或修改运单号／属性时自动生成邮件版本？
- 是否在寄送页提供收货地址修改入口？
- 是否允许准备中以外的寄送删除，或要求删除准备填写原因？
- 是否重新出现面单作废、录号、更正的旧环节？
- 是否重新出现打印编号清单？

## 6. Definition of Done

- 需求稿中所有页面字段、按钮、文案与当前页面一致；已知差异已记录并完成裁决或修正。
- 寄送抽屉准备中、已寄出两态全部通过人工验收；长内容、空态、无产品、已有文件和多运单号场景覆盖。
- 单个编号、连续编号、自动保存、删除准备、生成三类文件、确认寄出、已寄出属性修改和运单号维护均通过正反路径。
- 页面间闭环通过：订单详情新建寄送 → 录入 → 打印 → 确认 → 订单出货记录与履约数更新。
- 打印不登记寄出、运单号只影响邮件、确认后身份冻结、准备中可删除等核心边界无回归。
- 面单／纳品书／保障确认书／寄送通知邮件的正式模板样式与内容经客户确认并以正式 spec 转正；转正前不把样式与措辞视为已验收。
- 无新增的撤回、冲正、解锁或打印编号清单。

- 本次关联验收门槛：修改和新增用例须取得实际验证证据后才可判定通过；不得沿用旧级联删除、新旧衣体编号对照、订单级保障确认书的预期。
