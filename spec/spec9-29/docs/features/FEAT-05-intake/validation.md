# FEAT-05 衣体入库 Validation

> **本次修订验证状态（2026-09-25）**：以下修改及新增场景为验收要求，均未执行；历史 demo 核对、旧测试结果不表示本次规则已验证。原型资产未更新，冲突表现以本次正文为准。

本文件按 spec.md 的页面结构逐页验证，再验证「入库 → 组装 → 追溯」完整闭环与删除、更换边界。用例依据 spec 与业务理解编写，覆盖 demo 已实现与未实现部分；demo 未实现项在对应用例注明。

## 1. 衣体入库

### VAL-01 单个编号加入

选择衣体资料，单个编号输入 PTG26100 回车；再输入同一编号。

预期：第一次加入待确认列表（状态：待入库）；重复加入不重复出现，提示已在本次列表中。

### VAL-02 连续范围加入

选择编号前缀为 PTG26 的衣体资料，核对前缀自动带出且只读，输入 100～103 加入；再输入 103～105 加入。

预期：前缀 PTG26 不因包含数字被拒绝；第一次生成 4 件（前缀 + 流水：PTG26100～PTG26103）；第二次只新增 PTG26104、PTG26105，PTG26103 已在列表中不重复。

### VAL-02a 空资料前缀与临时范围前缀

选择编号前缀为空的衣体资料，在连续范围中临时输入 `PTG26`，录入 001～002 并加入待确认列表；然后重新读取该部件资料。

预期：资料前缀为空时前缀控件可编辑，使用临时值生成 PTG26001、PTG26002；临时值仅用于本次范围生成，不回写部件资料、不产生资料新版本。

### VAL-02b 临时前缀留空生成纯数字编号

选择编号前缀为空的衣体资料，临时前缀保持为空，输入 001～003 加入，再输入 003～004；确认新编号入库后重新读取部件资料。另覆盖生成编号与其他类型部件当前有效编号相同的情况。

预期：前缀不必填，首次生成 001、002、003，前导零保留；第二次仅新增 004，003 不重复加入。与任一类型当前有效部件编号重复的行标记「已有档案」，确认入库时跳过，不产生同号有效档案；其他新编号按原规则入库。资料前缀仍为空，不产生资料新版本；原位数一致、开始不大于结束及单次最多 500 件的规则不变。

### VAL-03 范围录入校验

分别输入：非数字开始／结束、开始 003 结束 3（位数不一致）、开始 005 结束 003、001～999（超过 500）。

预期：均不生成，提示具体原因。

### VAL-04 已有档案标记与跳过

加入一个已入库编号与一个全新编号，确认全部入库。

预期：已有编号标记「已有档案」并在入库时跳过；新编号入库成功；结果提示成功 1 件／失败 0 件（已有档案不计失败）；失败行保留。

### VAL-05 未选资料与空列表门禁

未选择衣体资料时确认入库；选择资料但待确认列表为空时确认入库。

预期：均提示并阻止，不产生数据。

### VAL-06 入库产生的事实

新编号 PTG26100 确认入库后。

预期：部件追溯可见衣体 PTG26100（建档来源：衣体入库）；产品列表可见製造番号 PTG26100 的产品（配发 M番号，界面不显示）；部件组装页通过范围或编号筛选可找到该行；本批生成一条入库记录（确认人、时间、包含个体）。

### VAL-07 列表清理操作

加入 5 件后：行内删除 1 件、勾选删除选中 2 件、清空本次录入。

预期：只移出待确认列表，已入库数据不受影响；清空后列表为空。

## 2. 页面间完整闭环

### VAL-23 入库 → 组装 → 质检 → 追溯闭环

> 本用例涉及 FEAT-06 部件组装与 FEAT-07 质检工作台。

1. 衣体入库：新建衣体资料（前缀 PTJ），范围入库 001～002 两件；
2. 部件组装：默认资料气囊 A型／传感器 A型＋固件 223k05／发生器 X型，逐行录入两件产品的三类部件；
3. 质检工作台：两件产品质检确认（页面规则见 FEAT-07 质检工作台）；
4. 部件追溯：查看新衣体与新部件的履历。

预期：入库后产品立即可组装；组装保存即建档并绑定；三部件齐全后质检可确认；追溯中衣体履历含入库、各部件履历含建档与安装；产品列表阶段从在制推进到已质检。

### VAL-24 删除衣体后的入库有效成员与编号复用

按 FEAT-08 删除无阻断产品及衣体，分别覆盖原入库记录仍有有效成员与已无有效成员；再以相同制造编号入库。

预期：删除成员不再计入有效数量，无有效成员的记录不作为有效记录展示；原登记信息、产品及衣体身份和已有历史仍保留可读。相同编号可登记新产品和衣体，新 M番号不复用，旧历史不转移，不恢复旧成员身份。

### VAL-25 当前有效编号查重

对当前有效衣体编号重复入库，再对已按规则删除的同编号重新入库。

预期：前者阻断，后者允许；历史身份不参与当前有效编号冲突判定，新旧身份的历史严格分离。

## 3. 回归检查

- 删除成员不再计入有效入库记录，历史登记可读，同号重入不复用身份或 M番号。

- 是否存在「产品创建」的第二个入口（组装页对产品不存在应报错并指引衣体入库，而不是自动创建）？
- M番号是否在任何界面露出（应只在数据层）？
- 删除产品后其 M番号是否被后续新建产品复用（不应复用）？
- 删除部件后同编号重新建档是否被错误拦截（应允许）？
- 部件资料停用是否影响了已建档个体（不应影响）？
- 规格文本是否被解析出颜色等结构化含义并用于拦截或推导（不应解析）？
- 页面上是否还存在部件个体停用／启用入口（应已全部移除）？
- 资料前缀为空时，范围录入临时前缀是否被错误回写为资料新版本（不应）？

## 4. Definition of Done

- 衣体入库单页可完成建资料、范围／单个录入、确认入库，入库即成立产品并绑定衣体；
- VAL-01 ～ VAL-07（含 VAL-02a／02b）、VAL-23 ～ VAL-25 全部通过；回归检查清单无命中。

- 本次关联验收门槛：修改和新增用例须取得实际验证证据后才可判定通过；不得沿用旧级联删除、新旧衣体编号对照、订单级保障确认书的预期。
