# FEAT-15 受付履历 Validation

**状态：Current Truth**

## 1. 受付履歴

### VAL-24 受付履歴筛选结构

操作：进入受付履歴，核对标题、右上按钮、关键词搜索、客户地址搜索、查询、重置和日期快捷页签。

预期：标题为「受付履歴」；右上显示「回到受付工作台」；关键词框内提示文字为「大番号 / 小番号 / 製造番号 / 客户」；客户地址框内提示文字为「客户地址（模糊搜索）」；日期页签包含全部、今天、昨天、近 7 天、本月、指定期间，默认选中全部。

### VAL-25 关键词搜索命中大番号与产品

操作：分别输入大番号、客户名、小番号、製造番号查询。

预期：大番号和客户名命中大番号本体；小番号和製造番号命中产品；产品命中时显示「产品编号命中 N 台，已自动展开对应大番号」，并自动展开、定位和高亮产品行。

### VAL-26 客户地址与日期筛选

操作：输入邮编或地址片段查询；选择今天、昨天、近 7 天、本月；选择指定期间时设置不完整起止日期、结束早于开始、合法期间。

预期：输入 7 位数字（可带连字符）时按大番号来件元信息的邮编严格匹配，其余输入按地址部分匹配；快捷日期按所选范围过滤；指定期间必须起止完整且结束不早于开始，合法后随查询生效。

### VAL-27 重置和客户详情入口

操作：设置多个筛选条件后点击重置；从客户详情关联业务快捷链接进入受付履歴。

预期：重置清空全部条件且日期页签回到全部；客户详情入口带关键词进入并立即生效。

### VAL-28 主表列与分页

操作：查询多条大番号，核对列、排序、分页和空值。

预期：主表按受付日時倒序，每页 10 条并显示总数；列为大番号、顧客、受付日時、来件元、件数、確認、操作；无客户显示「未确认客户」；確認无内容显示「—」。

### VAL-29 展开区与产品子表

操作：点击大番号行展开，核对包裹分组和产品子表；准备有未入力和需要确认的产品。

预期：展开区按包裹序号升序；包裹头显示 Package N、製品 N台、未入力 N台、⚑ 要確認 N台和 Package詳細；产品子表按小番号升序，显示小番号连写形态、製造番号、受付内容和確認・未入力；缺失项逐项以橙色标签显示，包裹和大番号层只显示未入力台数。

### VAL-30 大番号詳細与Package詳細抽屉

操作：点击「受付詳細」和「Package詳細」。

预期：大番号詳細只展示本次来件公司/客户、受付日時、受付完了日時、来件地址、联系人、电话、大番号备注和大番号图片；Package詳細只展示所属大番号、Package、产品数、Package备注和Package图片。

### VAL-31 生成批次记录表反路径

操作：对未完成首次登记的大番号悬停并尝试点击「生成批次记录表」。

预期：按钮不可用，提示「请先在受付工作台完成本批次受理」；不生成批次记录表。

### VAL-32 生成批次记录表正路径

操作：对已完成首次登记的大番号点击「生成批次记录表」，选择发行日并确认。

预期：提示「按当前事实生成新版本」；确认后新增一份版本化批次记录表并打开查看，内容包含版本号、发行日、模板版本、客户、受付时间、来件地址、联系人，以及按包裹分组的产品表。

### VAL-33 记录表历史

操作：同一大番号多次生成批次记录表后点击「记录表历史」，查看不同版本。

预期：历史弹窗列出 vN、发行日、生成时间和查看操作；查看旧版本时使用该版本生成时的批次事实，不按当前资料改写。

### VAL-34 大番号删除反路径

操作：对仍有小番号的大番号，在操作列「···」下拉中点击「削除」。

预期：提示「大番号下仍存在受付产品（小番号），请先删除全部小番号」；大番号、包裹和批次记录表均不删除。

### VAL-35 大番号删除正路径

操作：删除大番号下全部小番号后，确认删除该大番号。

预期：大番号及其全部空包裹、图片、备注一并删除；其批次记录表同步删除；小番号计数不回退、不复用。

## 2. 页面间完整闭环

### VAL-38 来件信息边界

```text
建立大番号并确认来件信息
→ 修改客户主档或当前订单资料
→ 返回受付履歴查看大番号詳細
```

预期：大番号仍显示建立时确认的公司名称、来件地址、联系人和电话；受付不回写客户或订单主数据，主数据后续变化不改写历史大番号。

## 3. 回归检查清单

- 是否出现选择类字段点击后未保存、或必须点底部「保存并扫描下一台」才保存字段的情况？
- 是否出现未点击「受付を開始」就建立单台受付的情况？
- 是否出现同一实际来件打开旧受付记录而不是取得新小番号的情况？
- 是否出现小番号按包裹重置、删除后复用或删除大番号后回退计数的情况？
- 是否出现删除包裹后其他包裹序号被重排的情况？
- 是否把受付完了日時当成作业、报告、返送、回收或报废完成状态？
- 是否把产品处理计划当成实际回收或报废事实？
- 是否让大番号来件信息回写客户或订单主数据，或被主数据后续变化覆盖？
- 是否允许员工手工增删 ⚑ 旗标？
- 是否在包裹或大番号层显示字段缺失总数，而不是未入力台数？
- 是否恢复了已明确不做的结束本包裹、小番号作废、独立来件管理、左卡次回予定、受付记录关联通知、受付履歴产品行详情入口或产品处理计划「未决定」？
- 是否允许批次记录表阻断删除大番号，或删除大番号时遗漏清理批次记录表？
- 是否允许 NG 保存多张照片？

## 4. Definition of Done

- 受付工作台初始页、前置流程、工作台、工作台弹窗和受付履歴均符合 spec.md。
- 新建受付、多台多包裹登记、保存校验、完成本批次受理、履歴查询、批次记录表和三层删除均有验收记录。
- 编号规则、未入力规则、⚑旗标、年度口径、受付类型与处理计划联动均通过正反路径验证。
- 来件信息、受付完了日時和处理计划的业务边界未被扩大。
- 删除行为符合三层删除条件和后果，且不会复用小番号或重排包裹序号。
- 批次记录表按版本保存生成时批次事实，历史查看不被当前资料改写。
- 明确不做项没有在页面、数据变化或验收用例中复活。
