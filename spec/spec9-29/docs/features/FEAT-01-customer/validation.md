# FEAT-01 客户管理 Validation

本文件按 spec.md 的页面结构逐页验证，再验证页面间完整闭环与「各业务保存当时信息」的边界。用例依据 spec 与业务理解编写，覆盖 demo 已实现与未实现部分；demo 未实现项在对应用例注明。

## 1. 客户列表

### VAL-01 编号／名称搜索

分别输入：系统分配编号（C 号）、导入客户的原编号（例：NS-0001）、公司名片段、支店名片段。

预期：均命中对应公司／支店行；公司命中时展开显示其支店行；支店命中时自动展开所属公司并只显示命中支店。

### VAL-02 地址搜索

输入邮编数字片段、地址 1 片段、地址 2 片段；再分别使用带和不带 ASCII 连字符 `-` 的同一邮编条件（例：`123-4123`／`1234123`）查询。

预期：命中拥有该地址的公司／支店；大小写不敏感。邮编查询先移除输入中的 `-`，再按邮编数字做部分匹配，因此带／不带连字符的查询结果一致；查询不改变数据库中保存的 7 位数字邮编。

### VAL-03 联系人搜索

输入联系人姓名、电话、传真、邮箱片段。

预期：命中对应公司／支店。

### VAL-04 客户区分筛选

选择「直販」。

预期：列表只保留默认客户区分为直販的公司；支店行随所属公司过滤（支店自身不存区分）。

### VAL-05 展开与收起

无搜索条件时，所有公司行默认收起支店；有搜索条件时命中项自动展开。

### VAL-05b 列表列构成与两行语义

核对列表各列：

- 客户编号：单行，等宽字体；导入客户显示原编号（例：NS-0001），系统新建客户显示 C 号；
- 客户：第一行公司或支店名称，第二行客户区分（直販／代理；支店行读所属公司值）；
- 地址信息：第一行该主体第一个地址的邮编（〒 前缀），第二行地址 1 + 地址 2；支店行显示支店自身的第一个地址；无地址显示 —；
- 联系资料：地址 N 条／联系人 N 名；
- 列中不出现「历史编号」第二行，不出现「默认請求書先」文案。

### VAL-06 分页按公司

构造 11 个公司 + 若干支店，使公司创建时间有先后且至少两个公司创建时间相同；同一公司下的支店／现场也同时覆盖不同创建时间和相同创建时间。客户编号混用 C 号、不同前缀和不规则历史导入格式。

预期：先对完整公司结果按创建时间倒序、公司 ID 倒序排序，再形成第 1 页 10 个公司、第 2 页 1 个公司；同一公司及其支店行不拆到两页。每个公司下的支店／现场按创建时间正序、支店 ID 正序排列。客户编号格式不影响排序；分页 `total` 仍为公司数，工具栏 `rowTotal`／「共 N 条」仍为筛选结果公司与支店合计行数。

### VAL-06b 筛选与编辑后的稳定排序

1. 在未筛选列表记录公司和支店／现场顺序，再使用能命中多个公司的编号／名称、地址、联系人或客户区分条件查询；
2. 编辑其中一个公司或支店／现场的名称及其他允许修改的资料后重新查询；
3. 核对数据库中该主体的创建时间和最近修改时间。

预期：筛选结果仍按公司创建时间／ID倒序、公司内支店创建时间／ID正序；编辑只更新最近修改时间，不改变创建时间，因此不改变其相对于同一结果集其他主体的排序位置。客户编号和最近修改时间均不参与排序。

### VAL-07 查询与重置

输入条件后必须点击「查询」或回车才生效；「重置」清空全部条件并恢复未筛选列表。

### VAL-08 空结果

输入不存在的编号。预期：统一空状态，无报错。

## 2. 客户详情

### VAL-09 公司卡字段

核对公司卡：客户编号（等宽）、公司名称、默认客户区分、资料存放路径（空值显示 —）。

预期：不出现创建人、创建时间、修改人、修改时间字段。

### VAL-10 支店卡结构

支店卡标题统一为「支店／现场」，不出现具体支店名；支店／现场名称为内容区第一个字段，其次是客户编号、资料存放路径。

### VAL-11 联系人描述列表

查看有完整资料的联系人、只有姓名的联系人。

预期：带边框的描述表格，三列等宽排列；职称、电话、传真、邮箱、备注、时间六字段常显；无值字段显示 —，不整行隐藏。

### VAL-12 联系人时间尾

从未编辑过的联系人显示「新建 + 创建日期」；编辑过的显示「最近更新 + 更新日期」。

### VAL-13 删除支店级联

支店含 2 个地址、共 3 名联系人时点击「删除」。

预期：确认弹窗写明「将同时删除其下 2 个地址、3 名联系人，删除后不可恢复；已生成的订单、通知、受付等历史业务记录不受影响（业务保存的是当时的信息）」；确认后支店、地址、联系人一并删除；已生成的订单等业务记录中保存的当时信息不变。

### VAL-14 关联业务快捷跳转

依次点击「订单」「受付」「通知」三个链接。

预期：分别跳转订单管理、受付履歴、通知管理列表；目标列表搜索词已带入本公司名并立即生效；链接区不显示件数统计。

### VAL-15 空地址与空联系人

无地址的公司卡显示统一空状态；地址下无联系人时显示「暂无联系人」。

## 3. 客户编辑工作区

### VAL-16 新建公司一次提交

填写公司名称，添加 2 个地址，地址 1 下添加 2 名联系人、地址 2 下不添加联系人，保存。

预期：一次提交建立公司 + 2 地址 + 2 联系人；客户编号系统生成（C + 连续数字），不与任何现有编号重复；保存后跳转新公司详情，全部资料可见。

### VAL-17 新建支店

从公司详情「新建支店／现场」进入，首行显示只读所属公司；填写支店名称与地址保存。

预期：建立支店（客户编号与公司共用同一条连续序列）及其地址；支店无客户区分字段；详情页出现新支店卡。

### VAL-18 地址非成立前置

只填公司名称、不添加任何地址直接保存。

预期：保存成功，详情页地址区显示空状态。

### VAL-19 必填校验与错误定位

- 公司名称为空保存 → 阻止并提示公司名称必填；
- 地址 2 只填邮编不填地址 1 → 提示「地址 2 缺少邮编或地址 1」；
- 地址 1 的联系人 2 不填姓名 → 提示「地址 1 的联系人 2 缺少姓名」。
- 地址 1 邮编填 12345（不足 7 位）、371-081a（含字母）或 371-0817（含连字符）→ 提示「地址 1 的邮编应为 7 位数字」。

预期：任一校验失败整体不提交，草稿保留。

### VAL-19b 邮编严格录入与统一展示

输入「〒371-0817」「371 0817」「371-0817」「３７１０８１７」（全角数字）尝试保存。

预期：均不允许保存并提示邮编应为 7 位数字；输入 3710817 可保存，详情页与列表统一显示 〒371-0817。

### VAL-20 编辑 diff 一次提交

编辑已有公司：更正公司名称、修改地址 1 的邮编、删除地址 2（含 1 名联系人）、删除地址 1 的联系人 1、新增地址 3（含 1 名联系人），保存。

预期：一次提交完成：公司更正 + 地址 1 更正 + 地址 2 连同其联系人一并删除 + 联系人 1 删除 + 地址 3 与联系人建立；被删数据在详情页消失；客户编号不变。

### VAL-21 移除已有主档地址先确认

编辑模式下点击移除一个已存在的地址（含 2 名联系人）。

预期：先弹确认，说明连带删除 2 名联系人、且不影响历史业务中保存的当时信息；确认后仅从草稿移除，保存时才真正生效；确认前取消不影响主档。

### VAL-22 新增草稿地址移除不确认

同一会话中先「添加地址」再移除该新增地址。

预期：直接移除，无确认弹窗。

### VAL-23 取消不写数据

修改若干字段后点「取消」。

预期：弹窗关闭，主档无任何变化。

### VAL-24 资料存放路径归一

资料存放路径输入前后带空白的值保存；只输入空白保存。

预期：trim 后保存；纯空白归一为空，详情显示 —。

### VAL-25 默认客户区分

新建公司时不改动客户区分直接保存。

预期：公司默认客户区分 = 直販。

## 4. 客户主体选择器

### VAL-26 选择公司与支店

在订单表单中打开选择器，分别选择公司（不选支店）、某支店。

预期：分别按「该公司」「该支店」生效；弹窗左侧为「公司 → 支店」两级列表，右侧显示所选主体资料；可按名称、编号搜索。

### VAL-27 选择器不写业务数据

完成选择后检查客户主档。

预期：主档无任何新增或修改；地址与联系人由调用模块自行处理，选择动作本身不写业务数据。

## 5. 页面间完整闭环

### VAL-28 主档维护闭环

```text
列表「新建公司」
→ 详情自动跳转，公司卡正确
→ 「新建支店／现场」→ 支店卡出现
→ 支店卡「编辑」修改名称 → 详情刷新显示新值
→ 支店卡「删除」确认 → 支店及其地址、联系人消失
→ 返回列表，该公司行下不再有支店行
```

预期：全程客户编号不变、不重复；每步结果在列表与详情一致可见。

### VAL-29 主档更正不影响历史业务

先创建一张引用该客户的订单（订单保存当时的名称与地址）；随后在工作区更正公司名称与地址；再回到订单详情。

预期：订单仍显示下单时保存的信息；客户详情显示新值；两边互不干扰。

### VAL-30 关联跳转闭环

详情点击「订单」→ 订单列表按公司名过滤出 VAL-29 的订单；再点击「受付」「通知」验证同样生效。

## 6. 回归检查

每次修改客户管理至少检查：

```text
是否出现一条地址同时属于公司和支店？
是否提供了公司删除入口？
是否重新出现启用／停用概念或状态列？
是否重新出现更正履历、变更事件 Drawer？
主档更正是否回写了订单／受付／通知中保存的当时信息？
支店是否开始保存自己的客户区分？
客户编号是否可编辑、是否出现重复（含导入原编号与 C 号之间）？
删除支店时是否遗漏一并删除地址或联系人？
分页是否把同一公司的支店行拆到两页？
客户列表是否仍按公司创建时间/ID倒序、公司内支店创建时间/ID正序，且筛选或编辑后保持同一规则？
是否在选择器里写入了业务数据？
邮编是否保存了 7 位数字以外的内容（保存后应统一展示为 〒XXX-XXXX）？
```

## 7. Definition of Done

- 所有页面行为符合 spec.md；
- 新建／编辑一次提交满足全成或全不成；
- 删除级联与确认文案符合 spec；
- 主档与历史业务中保存的当时信息双向隔离通过验证；
- 列表搜索、展开、分页行为符合 spec；
- 关联业务三链接跳转并自动搜索通过验证；
- 关键规则（一次提交、一并删除）有自动测试或明确人工验收记录；
- 无未说明的临时状态、旁路逻辑和重复事实源。
