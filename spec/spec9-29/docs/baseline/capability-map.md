# PROP V2.1 系统能力地图

> 这份文档回答三个问题：系统管什么、20 个页面（FEAT-00～19）各自解决谁的什么问题、页面之间的数据怎么流动。
> 给谁看：业务方确认范围、开发分工、AI 划定上下文。
> 页面字段、按钮、校验的细节以 `../features/FEAT-NN/spec.md` 为准；本文档不重复规则，只做全景索引。

## 1. 系统边界

覆盖：客户、部件、生产、订单与寄送、点检与通知、受付、作业、报告、返送。

不在范围内：金额、收付款、记账及财务审批。

## 2. 业务主线

一台气囊产品的一生：

```
衣体入库 → 部件组装 → 质检 →（成品在库）→ 订单 → 寄送出货
                                    │
                                    ↓
                          生命周期（年度点检 / 5年目报废）
                                    │
                                    ↓ 通知寄回 / 临时来件
                          受付（大番号→包裹→小番号）
                                    │
                                    ↓
                          作业（縫製/センサ/組立/展開修理/クリーニング）
                                    │
                                    ↓
                          返送 / 回收 / 报废
```

箭头表示常见业务衔接，各业务的前置条件以对应功能需求为准：订单可以不经过通知直接来件；返厂不自动解除订单关系；报告不是返送的硬前置。

## 3. 能力清单

按业务阶段分组；每组内列出页面，每个页面三列：谁用 / 解决什么 / 结果给谁。

### 阶段 0 · 基础资料（各业务的可选用主档与字典）

| 页面 | 谁用 | 解决什么 | 结果给谁用 |
|---|---|---|---|
| FEAT-02 部件资料 | 管理人员 | 建立与维护四类部件（衣体/气囊/传感器/发生器）的可复用资料与完整资料版本 | 衣体入库、部件组装、作业换件 |
| FEAT-03 基础数据 | 管理人员 | 维护对外产品名称、传感器固件版本等系统级字典 | 订单管理、作业管理 |
| FEAT-04 作业选项 | 管理人员 | 按工作组维护作业 NG 描述与处置内容清单，及受付 NG 快捷选项 | 作业管理、受付工作台 |
| FEAT-01 客户管理 | 营业/事务 | 公司-支店/现场-地址-联系人的层级主档；关联业务跳转 | 订单、通知、受付、寄送 |

### 阶段 1 · 产品形成（从衣体到可出货的成品）

| 页面 | 谁用 | 解决什么 | 结果给谁用 |
|---|---|---|---|
| FEAT-05 衣体入库 | 生产人员 | 新到衣体批量建档：衣体个体 + 产品成立（製造番号=衣体编号、配发 M番号）+ 绑定 | 部件组装、产品列表 |
| FEAT-06 部件组装 | 生产人员 | Spreadsheet 式录入气囊/传感器/发生器编号并绑定；资料可逐台更正 | 质检工作台 |
| FEAT-07 质检工作台 | 质检人员 | 批量登记线下质检通过；通过后获得出货资格 | 产品列表、订单寄送 |
| FEAT-08 产品列表 | 全员 | 查询全部产品（在制/待质检/已完成质检），进入详情；按既有四类阻断条件删除产品 | 所有下游 |
| FEAT-09 部件追溯 | 全员 | 查部件个体的当前资料、归属与完整履历；删除未绑定部件 | 排查问题 |

### 阶段 2 · 销售与出货

| 页面 | 谁用 | 解决什么 | 结果给谁用 |
|---|---|---|---|
| FEAT-10 订单管理 | 营业 | 按客户/日期/要求建订单；核对需求、配送、出货历史与产品关联；变更与取消 | 寄送 |
| FEAT-11 寄送 | 事务/出货 | 单笔订单寄送的准备、文件生成（面单/纳品书/保障确认书）、确认寄出、运单号维护；确认寄出时建立产品与订单关系 | 产品生命周期、定期管理 |
| FEAT-19 订单批量打印 | 事务 | 多笔准备中寄送按统一快递公司模板连续生成面单 | 寄送（写回快递公司） |

### 阶段 3 · 生命周期与通知

| 页面 | 谁用 | 解决什么 | 结果给谁用 |
|---|---|---|---|
| FEAT-12 定期管理 | 营业/事务 | 按年度月历查看定期点检/5年目报废候选，勾选产品后生成正式案内（一次生成即永久保留，内容有误时以新番号重新生成） | 通知管理 |
| FEAT-13 通知管理 | 事务 | 查询/查看 FEAT-12 生成的正式案内，跟踪发行后受付情况与超期未受付；不建立案内，仅可更正内部備考 | 受付工作台（来件依据） |

### 阶段 4 · 返厂与作业

| 页面 | 谁用 | 解决什么 | 结果给谁用 |
|---|---|---|---|
| FEAT-14 受付工作台 | 受付人员 | 来件登记：大番号→包裹→扫描产品建小番号；异常/NG、处理要求、临时装箱 | 作业管理、受付履历 |
| FEAT-15 受付履历 | 全员 | 按大番号/客户/地址/产品/日期查受付批次；生成批次记录表；按规则删除 | 受付工作台（切回） |
| FEAT-16 作业管理 | 各工作组 | 按批次连续作业：检查○×、处置、备注、换件；按统一业务口径显示完成情况；生成点检/回收/报废报告；确认回收/报废 | 返送 |
| FEAT-17 返送 | 受付负责人 | 按大番号管理返送：逐台看计划与作业完成情况、生成/查看报告、维护返送面单并确认寄出（产生正式返送事实）；回收/报废确认在作业管理完成，本页不修改作业/报告/回收/报废及订单关系 | 返送批量打印 |
| FEAT-18 返送批量打印 | 事务 | 多家大番号准备中返送面单连续打印 | 返送（写回快递公司） |

### 阶段 5 · 全景

| 页面 | 谁用 | 解决什么 | 结果给谁用 |
|---|---|---|---|
| FEAT-00 首页看板 | 全员 | 打开即见：今天要做什么（待办/逾期）、厂内流转（作业/受付/返送）、库存与生产进度、订单概况；一键进入对应模块 | 各模块入口 |

## 4. 数据依赖速查

只列主要读写关系（「读」= 页面展示或选择时引用；「写」= 页面操作产生的事实）：

| Feature | 读（上游） | 写（产生的事实）给谁用 |
|---|---|---|
| FEAT-01 客户管理 | — | 客户主档 → 订单/通知/受付/寄送（快照） |
| FEAT-02 部件资料 | — | 部件资料与版本 → 入库/组装/换件 |
| FEAT-03 基础数据 | — | 字典 → 订单/作业 |
| FEAT-04 作业选项 | — | NG/处置清单 → 作业/受付 |
| FEAT-05 衣体入库 | 部件资料 | 衣体个体 + 产品 + 绑定 → 组装 |
| FEAT-06 部件组装 | 部件资料、衣体入库的产品 | 部件个体 + 绑定 + 操作记录 → 质检 |
| FEAT-07 质检工作台 | 组装的产品 | 质检通过事实 → 产品列表/寄送资格 |
| FEAT-08 产品列表 | 全部产品事实 | 产品与衣体退出当前有效范围，原身份及可读历史保留；非衣体档案不随删 |
| FEAT-09 部件追溯 | 部件个体与绑定历史 | 部件退出当前有效范围，原历史保留，编号可复用但新身份不继承历史 |
| FEAT-10 订单管理 | 客户主档 | 订单 → 寄送 |
| FEAT-11 寄送 | 订单、产品库存 | 寄送记录、本笔文件版本（含仅本次清单的保障确认书）、确认寄出事实（产品与订单关系）→ 生命周期 |
| FEAT-19 订单批量打印 | 寄送准备中记录 | 面单版本、快递公司写回 → 寄送 |
| FEAT-12 定期管理 | 生命周期（寄送建立）、客户关系、点检实绩 | 正式案内及 PDF → 通知管理 |
| FEAT-13 通知管理 | FEAT-12 生成的正式案内 | 案内内部备注更正；不建立案内 |
| FEAT-14 受付工作台 | 产品（录入制造编号识别）、案内 | 大番号/包裹/小番号/正式NG → 作业管理 |
| FEAT-15 受付履历 | 受付数据 | 批次记录表；删除大番号 |
| FEAT-16 作业管理 | 受付（小番号）、作业选项、部件资料 | 作业记录、报告版本、回收/报废确认 → 返送 |
| FEAT-17 返送 | 作业报告、受付 | 返送面单版本、确认寄出事实（正式返送事实 + 寄送通知邮件）→ 返送批量打印 |
| FEAT-18 返送批量打印 | 返送准备中面单 | 面单版本、快递公司写回 → 返送 |
| FEAT-00 首页看板 | 全部模块（只读统计） | 不产生业务数据 |

## 5. 使用原则

- 本文档只做全景索引与边界声明，不定义字段、不规定交互。
- 新增页面或调整能力归属时先更新本文档，再改对应 feature spec。
- 与 feature spec 冲突时以 spec 为准，并回修本文档。

- 身份、编号复用、正常衣体更换与准备删除的跨模块边界见 [规则摘要](identity-history-rules.md)，不得将不同对象的历史保留规则混用。
