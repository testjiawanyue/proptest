# PROP 气囊管理系统 V2.1

## 1. 项目概述

PROP 气囊管理系统 V2.1 用于承接客户、部件、产品生产、正式产品、订单与出货、生命周期与点检、受付、作业、报告及返送等核心业务，并逐步替代当前分散在 Excel、纸张和既有系统中的业务记录。

本文档描述业务范围、操作结果和规则边界。技术方案选型与架构设计在后续开发中根据业务需求确定，不在需求文档中预设。

## 2. 系统功能

系统按二级导航粒度拆分为 20 个 Feature（FEAT-00～19），与 `docs/features/` 目录一一对应。各 Feature 的业务规则以其 `spec.md` 为唯一基线。

## 3. 核心业务流程

整体业务流程、返厂闭环与各业务阶段作用以 `baseline/business-flow.md` 为准（含正式流程图，已按 20 个 Feature 对齐）。此处不再重复 ASCII 流程，避免两份漂移。核心线索：

- **产品形成**：衣体入库（FEAT-05）→ 部件组装（FEAT-06）→ 质检（FEAT-07）→ 正式产品（FEAT-08）。
- **订单出货**：订单（FEAT-10）创建时不直接绑定具体产品；寄送（FEAT-11）确认寄出时才建立产品订单关系，并把首次出货月登记为生命周期基准月。
- **返厂闭环**：定期管理（FEAT-12）/通知（FEAT-13）→ 受付（FEAT-14，大番号→包裹→小番号）→ 作业（FEAT-16，五组登记+报告+回收/报废确认）→ 返送（FEAT-17）。闭环三种出口含义不同：返送回客户（关系不变）、确认回收（结束订单关系）、确认报废（生命周期终结）。

箭头只表示常见业务衔接，各业务的前置条件以对应功能需求为准：订单可以不经过通知直接来件；返厂不自动解除订单关系；报告不是返送的硬前置。

## 4. 系统范围与边界

系统负责客户主档及业务快照、部件与产品组成追溯、产品生产与首次质检、正式产品、订单与现实出货、生命周期与通知、返厂受付、专业作业、正式报告、原产品返送以及运营统计与业务概览。

系统不负责正式請求書、收款、对账、会计、税务，也不在系统内执行逐项生产质检。

核心边界：

- 产品生命周期与受付、维修、返送的业务进度应清楚区分，不能混为同一业务含义；
- 产品显示的当前订单必须与其有效、未结束的订单关联一致；
- Reception 不等于 Work 已完成；
- WorkExecution 只记录实际专业作业；
- 报告与回收/报废实际处理完全独立：生成报告不等于已回收/已报废；
- 正式物流事实、已发生的部件与产品关系事件及原身份历史保留，文件版本生成后不覆盖；但出货／返送准备删除时其全部所属文件和邮件版本随删，不保留该准备业务历史（含单笔发货保障确认书）；
- 同一业务记录在不同页面展示时，内容与业务口径必须一致。

## 5. 详细设计索引

```text
docs/baseline/
├─ capability-map.md                    系统能力地图（20 个页面全景索引）
├─ business-flow.md                     整体业务流程与返厂闭环（含图）
├─ PROP_V2.1_领域模型与初版数据库设计.docx  领域模型与初版数据库设计
└─ assets/                              流程图源文件与图片

docs/features/
└─ FEAT-NN-*/                           20 个 Feature（FEAT-00～19）
   ├─ spec.md        业务规则（状态：Current Truth）
   ├─ validation.md  验收用例
   └─ assets/        截图与附件
```

Spec 定义业务能力、业务流程、规则和验收要求，不预设技术架构、状态存储或计算方式。后续开发根据业务需求进行技术方案选型和设计，并遵循项目开发规范。现有领域模型、初版数据库设计及相关图表仅作为分析参考，不作为必须沿用的技术方案；业务规则以各 Feature 的 spec.md 为准。


删除、编号复用、衣体实物更换与文件归属的现行约束索引见 [身份与历史规则](docs/baseline/identity-history-rules.md)。
