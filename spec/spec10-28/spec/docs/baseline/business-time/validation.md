# 系统日本业务日期与事件时间 Validation

依据 [spec.md](spec.md)。以下按2026-10-04最新日本部署裁决修订，五项目标保留，均未执行；此前UTC/JST其他口径下的测试不能自动计为当前规格通过。

## TIME-VAL-01 接口拒绝含义不明（正文 §1）

1. 逐字段登记类别、来源、格式、精度、空值含义及接口，覆盖实体 DTO 与 Map 返回链路。
2. 对允许输入事件时间的接口，输入 `2026-10-04T02:47:46Z` 与 `2026-10-04T11:47:46+09:00`。预期表示同一实际时刻，响应统一为 `2026-10-04T11:47:46+09:00`，日本展示为 `2026-10-04 11:47:46`。
3. 输入无时区事件值 `2026-10-04 11:47:46`，预期明确拒绝，不依赖默认时区，不产生业务写入；原接口身份仲裁和重放规则仍成立。
4. 日期 `2026-10-04`、月份 `2026-10` 往返不变。非法日期、给日期字段附加时刻等不被静默截断；可空返回 `null`，必填缺失拒绝。
5. 服务端操作时间不采用客户端伪造的当前时刻。页面、导出和新模板可明确识别日本时间。仅格式相同不算语义一致。

## TIME-VAL-02 同事件多表一致（正文 §2）

1. 确认寄出后读回寄出事件和由此次确认建立的关系，预期对应同一日本事件时刻，无八／九小时偏差；重复确认及请求重放不刷新原事件时间。
2. 随后解除，预期记录独立的实际解除时刻。以执行证据核对先寄出、后解除，跨表与页面顺序一致。
3. 更正寄送业务日期，预期按业务规则联动基准，不改变原确认时刻。
4. 覆盖实际 Java 写入、数据库时间生成及连接池新建／复用连接的适用路径；保留参与表、字段及读回证据。模拟事务测试不代替实库结果。

## TIME-VAL-03 按真实时刻排序、按日本时间展示（正文 §3）

1. 使用已知先后的生产、寄出、解除等跨类型事件，核对全部及分类历史的倒序与完整性。
2. 覆盖跨日、同秒不同小数精度、完全同时间、空时间及不同来源 ID，检查稳定次序，不补造时间或精度。
3. 在日本、中国及 UTC 浏览器时区下查看同一记录，预期日本显示及排序一致；配合不同 JVM、数据库会话默认时区核对JVM/连接日本配置实际生效、存储、带偏移JSON及页面无重复偏移；不同服务器默认区不能改变配置明确后的结果。
4. 日期与月份始终保持原值。分别记录离线类型测试、真实映射及浏览器验证，不能互相替代。

## TIME-VAL-04 日本日期筛选及日历边界（正文 §4）

1. 查询日本 `2026-10-04` 的事件，东京DATETIME预期范围为 `[2026-10-04 00:00:00, 2026-10-05 00:00:00)`；对于时间点类型，其等价边界为 `[2026-10-03T15:00:00Z, 2026-10-04T15:00:00Z)`；起点纳入、终点排除、末秒小数精度事件不遗漏。
2. 纯业务日期按日期值查询，不套用上述事件换算；覆盖跨月、跨年日期区间。
3. 日本午夜前后核对“今天”和日期默认值；在 `2026-12-31T15:00:00Z` 前后核对以当前年度为依据的编号切换至日本 2027 年。既有编号、旧请求重放及已用序列不得重置。
4. 基准月取指定业务日期的月份，不因操作发生于另一日或另一月改变；日期更正按功能规则联动。
5. 对适用任务列明调度时区及预期日本执行时刻；原语义不明的任务不得自动改时区并记为通过。

## TIME-VAL-05 历史修正有据、冻结内容不变（正文 §5）

1. 准备可靠来源的 UTC、中国时间、日本时间及未知来源样本。预期分类有据，未知项保持待核实，不一律加减小时。
2. 获批修正前后核对对象清单、原值、依据及结果，仅影响批准范围，并验证不会重复转换。
3. 核对寄送日期、首次出货业务日期和基准月未参加按小时平移；若日期本身有误，另列证据及处置，不借本次时间转换修改。
4. 比对既有冻结邮件、文件版本与快照，预期无未授权变化。新版本按新契约验证，不覆盖旧版本。
5. 未知来源、未授权修正及未验证范围明确留在交接缺口，不宣称全量历史正确。

## 证据登记

五项要求映射到若依系统模块、C01／C02／C03及后续适用场景，不适用项说明原因。在当前 Change 记录字段／接口、源码版本、环境时区、输入、库值、接口值、页面结果及执行方式；实际执行、引用证据、离线测试、运行验证与待办分别登记。

## 系统模块补充映射（不另建验证体系）

- TIME-VAL-01：BaseEntity及SysUser/SysOperLog/SysLogininfor/SysJob/SysJobLog注解、DTO/Map/在线登录epoch等响应；允许输入事件的绑定严格偏移，日期范围不误作无区事件输入。
- TIME-VAL-02：业务同事件共享时刻；系统异步审计落盘/任务开始结束为独立事实，不要求强行与业务同秒。确认新/复用池会话+09:00、Java/SQL/default一致。
- TIME-VAL-03：系统用户/角色/字典等审计、登录/操作日志、在线用户、任务日志及文件列表显示，Excel导出、控制台/文件日志口径；不同浏览器同一日本显示；既有格式化别名及直接输出均覆盖。
- TIME-VAL-04：操作/登录日志日本日期末日、用户/任务日志筛选，日期组件默认、系统导出日期、Quartz实际触发/下一次时间一致；原任务语义先核实。不改变缓存TTL或epoch真实时刻。
- TIME-VAL-05：系统历史审计来源同样分类，不能改公共配置后伪称旧日志已日本化；冻结内容及纯日期不动。

配置替代项（如驱动强制会话与Druid初始化）只对采用路径验证，不为两套冗余实现凑证据。切换后新建/复用连接均须检查，切换前停止旧写入者。
