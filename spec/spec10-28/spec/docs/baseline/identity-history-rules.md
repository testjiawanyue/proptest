# 身份、删除、实物更换与发货文件规则

状态：现行需求摘要，2026-09-25。功能正文及 validation 为直接验收依据，本摘要不替代对应模块正文；需求评审已由用户确认通过；业务验收场景均未执行，不预选数据库实现。

## 修订依据

| 原条款 | 冲突 | 现行要求 |
|---|---|---|
| FEAT-05／06／09 删除清除全部历史 | 与安装等历史追加规则冲突 | 当前有效档案移除，原身份及可读历史保留 |
| FEAT-08 产品删除级联清除历史 | 删除会破坏其他产品和部件已发生事实 | 仅产品及衣体退出当前业务范围，非衣体档案及原历史保留 |
| 领域模型编号删除后不释放 | 与错误建档纠正后编号复用冲突 | 当前有效范围内唯一，复用编号产生独立身份；M番号不复用 |
| FEAT-08 换衣体后绑定新衣体、旧编号→新编号 | 将实物更换误作身份更换 | 身份和绑定不变，只登记“更换衣体” |
| FEAT-11 订单级保障确认书及删除例外 | 混合多笔发货范围 | 单笔发货归属，生成时清单，随准备删除 |
| 准备文件版本保留原则未注明删除边界 | 容易将已生成文件误作删除阻断 | 出货／返送准备含文件可删，正式寄出后前后端禁止删除 |

## A 纠错路径

- 正确部件绑错产品：结束错误绑定再绑定正确产品，保留同一身份及甲、乙产品历史（FEAT-06 §5、FEAT-09 §3.8）。
- 编号正确而资料错误：沿用既有资料更正，保留原采用版本和更正记录（FEAT-02、FEAT-06、FEAT-09 §3.8）。
- 误建档或编号录错：解除当前绑定后删除错误档案，按需重新登记。只检查当前有效绑定，不以曾绑定、安装或固件历史增加阻断。

## B 部件身份与编号

删除对象不在当前有效列表、选择、安装和其他业务操作范围，不可继续资料更正或固件升级；记录删除时间和操作人。原身份及历史数据继续保留；仍存在的产品或其他业务记录中的安装、拆除、更换、资料更正、固件变化等既有历史继续显示原对象当时的编号、采用资料及事件内容，足以理解发生过什么，不能只保留孤立 ID 或删除日志。业务编号仅在当前有效档案内全系统唯一；同编号新登记为独立身份，不继承旧固件、绑定或更正记录，旧历史不能按编号转向新档案（FEAT-09 §3.4～3.8）。不要求新增已删除档案查询页、历史检索或指向已删除档案的导航入口；不新增恢复、回收站、档案启停。

## C 产品与入库成员

删除阻断仍为当前气囊／传感器／发生器绑定、质检记录、出货记录、受付记录；“出货记录”包含准备记录，不限于正式寄出，不增其他条件。产品和衣体退出当前列表、选择及业务操作范围，原身份及历史数据保留；仍存在的部件或其他业务记录中的既有历史继续显示原对象当时的编号、采用资料和事件内容，非衣体档案不随删。已删除衣体不计入入库记录有效成员；无有效成员的入库记录不作为有效记录展示，历史登记保留。同制造编号重新入库产生新产品及新衣体，历史不继承、不改指新对象，M番号不复用（FEAT-05 §5、FEAT-08 §4.6～4.7／§6）。不要求新增已删除产品查询或导航入口；不新增产品作废、恢复、回收站。

## D 正常更换衣体

实物更换事件保持产品身份、制造编号、系统衣体身份及绑定不变。不新建衣体，不解绑，不产生可删除旧衣体；线下旧实物报废不登记、不触发产品报废。历史仅显示“更换衣体”，时间及操作人沿用原规则；详情确认实际登记事件，不引导组装绑定。FEAT-16 保留“ジャケット交換済”处置痕迹；衣体资料不自动变化（FEAT-08 §5.5～5.8、FEAT-16 §4.5／4.7）。

## E 准备删除边界

出货／返送准备无论是否已有文件均可二次确认删除，取消无变化。准备、所属清单关联、全部所属文件和邮件版本不保留业务历史；不删产品或其他记录、不改变正式履约。返送解除该准备占用，按原资格恢复可选；正式寄出后界面及服务端均禁止删除。不新增作废、取消、恢复流程（FEAT-11 §4.5～4.7／§6.7、FEAT-17 §6.5～6.7／§7.6）。这与部件历史保留属于不同对象规则，不得全局混用。

## F 保障确认书

归属于单笔发货，产品范围为生成时该笔清单。同订单不同发货各有独立不可覆盖版本；删除准备连同其保障确认书一并删除，正式寄出后版本随发货保留。生成和打印不登记寄出、不改变履约及产品订单关系；模板、版式和正文措辞本次未定稿（FEAT-11 §4.7／§6.7，FEAT-10 §7.4）。

领域模型 DOCX 及三张领域图同步已确认的业务约束；既有表名或字段示例不是本次指定的数据库技术方案。原型图片保持不变，用户已确认衣体更换弹窗中的“新衣体”指实物，删除阻断弹窗亦无需修改。
