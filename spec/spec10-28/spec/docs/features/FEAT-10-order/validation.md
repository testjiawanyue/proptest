## 1. 订单列表

### VAL-01 页面字段、入口与分页（spec 4.2～4.4）

从「订单管理」进入列表，逐项核对八个筛选、七列表格及工具栏；准备超过十张订单，翻页并打开一张详情，再返回。另查询不存在的订单。

预期：标题为「订单列表」，字段与列序符合 spec；每页 10 条、总数正确，无列排序入口；缺失客户订单号和预计发货日按规定展示；无匹配时显示空态。查看详情不建立订单；新建进入订单表单；订单列表不显示批量打印快捷入口，批量打印通过同级导航独立进入。

### VAL-02 关键词与客户入口（spec 4.4～4.6）

分别输入注文管理番号、客户订单号、下单方、納品先的完整值和部分值；通过查询按钮及回车查询。改变输入但不提交，然后重置。另从客户详情关联业务进入。

预期：仅支持上述四项的部分匹配，不要求按产品名称或颜色匹配，英文大小写及首尾空格不影响正常匹配；修改未提交时保留上次结果。重置清空条件并恢复全列表；客户入口的查询条件与显示结果一致。历史同号订单分别展示，不合并；不因提示含「案件番号」而要求建设案件功能。

### VAL-03 制造番号查询（spec 4.4）

对已寄出、准备中、已解除关联的产品分别用完整／部分製造番号查询；比较有无已生成文件时的结果；输入不存在的编号。

预期：相关订单可追溯，空查询不限范围，不存在编号得到空结果；解除关联不删除历史追溯结果。准备中即使未生成任何文件也须命中；生成或打印文件不改变查询范围。

### VAL-04 组合条件与日期边界（spec 4.4～4.5）

分别切换销售／租赁／替代、直販／代理、三种履约进度以及有效／已取消，再组合关键词、受注日和预计发货日；选取恰好在起止日及日期缺失的订单。全部重置。

预期：组合条件同时满足才展示；日期含起止日，预计发货日为空的订单在该日期筛选生效时不出现。订单状态筛选只保留所选状态；重置清空可见日期并恢复全部。当前状态筛选问题不得记为通过。

## 2. 订单详情

### VAL-05 区块、字段与空态（spec 5.3～5.4）

分别打开未发货、部分发货、已完成、已取消订单及不存在的订单；核对公司和支店配送场景，并对空值、长名称、长地址、备注和十条以上操作记录检查展示。

预期：八个卡片顺序、字段与 spec 一致；页头为下单方；公司与支店配送行分组正确，地址和邮箱可复制。操作记录为倒序表格，可分页；产品关联包含历史，出货计数仅数已确认记录。无 M番号，无独立行编辑、库存对比、规格及特殊要求字段。不存在订单显示「订单不存在」。桌面及 iPad 上主要信息与操作应可见，待实际验收。

### VAL-06 出货记录展开与抽屉（spec 5.4～5.5）

展开有产品及无产品的出货记录，打开待确认与已寄出记录的「查看」；有剩余需求时点击「发货」，对已发足及已取消订单核对入口。

预期：展开只显示製造番号及本次发货采用的订单产品名称，不将产品对应到颜色需求行；无产品时显示「尚未录入产品」。有剩余需求的有效订单可发货，其他两类不显示新建发货入口。「查看」打开对应寄送，已确认记录按寄送规则保留资料更正能力；关闭返回当前上下文，不产生额外出货。

### VAL-07 抽屉确认发货（spec 5.5～5.7）

打开待确认、未放弃的寄送抽屉，点击「补充运单号并确认寄出」，先选择「再检查一下」，再尝试确认；分别覆盖缺少必要寄送条件、条件齐全、订单已经取消的情况。

预期：返回检查不产生事实；符合寄送条件时仅登记一次实际寄出与产品关联；缺少条件和已取消订单不得确认成功。表格内不提供直接确认入口，统一从抽屉确认。
### VAL-08 取消订单及取消原因（spec 5.5～5.7、7.3）

对有效订单打开取消弹窗，先留空或仅空格提交，再填写原因。分别验证未出货、部分出货、已发足订单；对有历史出货但有效交付已为零的订单核对提醒。再尝试重复取消。

预期：空原因提示「请填写取消原因」，不改变订单；合法原因确认后显示「订单已取消」，操作记录包含原因、人员、时间。当前有效交付大于零时显示不撤销历史出货的提醒；仅历史出货大于零的提醒缺口按第 6 节终审。取消后不能编辑或新增／确认出货，重复取消不增加记录；原数量、出货、关系均保留。关闭弹窗或点「返回」无变化。

取消前另准备有产品占用及文件的未确认寄送。取消后占用释放，产品可用于其他有效订单准备；原准备和文件仍可查看、删除，但不能继续确认寄出或重新占用。正式寄出关联保持不变。

### VAL-09 解除关联弹窗与结果（spec 5.5～5.7）

在当前关联行点击「解除关联」，核对製造番号、三条后果、正常回收提示及「保留基准月／解除基准月」选项；先取消，再分别选择两种处理方式确认解除。后续另一笔解除也须提供本次选择。

预期：无解除原因选择，但每次均可选择基准月处理方式，危险色按钮为「确认解除」；取消不变更。保留时首次出货日及生命周期基准月不变；解除基准月时两者同时清空。确认后提示「已解除关联」，原行保留且变为已结束，结束原因为「解除关联」，该产品不再作为本单当前关联；有效交付减少，剩余需求可能恢复，历史累计出货和历史清单不减少；产品进入成品在库，可按出货条件重新选用。

### VAL-10 解除边界与正常回收（spec 5.6、7.2～7.3）

检查已结束关系、无当前关系及多条当前关系异常；检查已取消订单仍存在的当前关联。另通过受付办理正常回收或租赁结束。

预期：已结束关系没有解除按钮；无当前关系或关系异常时拒绝重复／不明确的解除，不随意处理别的关系。取消订单不自动解除，但错误交付仍可从其当前关系行纠正。受付正常回收不否定原交付，不使原单重新欠发；普通收件、点检、维修不自动结束关系。

### VAL-11 操作记录（spec 3.4、5.4、6.7）

创建订单、修改备注、改变总数量、取消订单，逐次回到详情；另单独解除关联。

预期：创建、编辑、取消各留记录；数量变更说明准确写明前后台数，非数量编辑可显示「—」；取消保留原因。解除事实由产品关联记录承载，不要求凭空多一条订单操作日志。无人工完成确认新记录。

## 3. 新建／编辑订单

### VAL-12 默认值与必填（spec 3.1～3.2、6.4、6.6）

新建订单核对当天受注日、销售类型、直販客户区分、一条空需求行。逐项缺少受注日、客户区分、下单方、納品先、配送地址、产品名称或数量保存；再补全必要资料，联系人、预计发货日、备注留空。

预期：缺少必要资料不得成立订单，显示相应提示并保留输入；合法且只缺选填资料时可创建，生成一张订单并进入详情。不建立受注案件、实际出货或产品关联。

### VAL-13 三方主体选择与默认联动（spec 6.4～6.5）

搜索并浏览公司及支店／现场，先取消弹窗，再确认选用。覆盖本单direct／agency × 主档direct／agency × 公司／支店八种组合，再分别更换下单方、切换本单区分、手选納品先和請求書先。

预期：树节点浏览不即刻替换主体；无选择不能确认。选择／更换公司或支店均保留本单customerType，主档类型缺失也不覆盖。按本单direct让納品先同下单方，agency则清空待选；更换下单方后請求書先恢复同下单方。

- 切换本单区分重新确定納品先，清理旧地址／联系人；完整预览中的单地址／单联系人自动采用，多候选等待选择；编辑加载的采用快照无候选时，切换后清空配送并等待既有选择入口，不把未加载当作主档不存在；未选下单方时也不得残留旧配送。先前另选請求書先及其采用模式保留；清除請求書先恢复默认。
- 两种区分均允许手选其他納品先／請求書先，提交时不强制回退。无匹配、无地址及无联系人显示对应空态。未保存切换不写客户主档。
- 编辑加载已保存本单区分，即使客户采用快照或当前主档类型与其不同也保留；更换客户不覆盖区分。核对新建／编辑提交payload、保存后重开映射、列表按本单区分筛选；销售／租赁／替代类型均独立。旧订单未编辑不被批量改写，已寄出快照及文件不变。
- 迟到地址／联系人读取在区分切换或更换主体后不得恢复旧选择；提交在途／结果未知时原有锁定和安全退出继续有效。

### VAL-14 地址、联系人归属与单候选（spec 3.3、6.5）

准备公司及两个支店各自地址，包含零个、一个、多个地址及联系人。更换納品先、切换地址、清除地址或联系人。

预期：地址只列当前主体自身资料，不混入所属公司或其他支店；联系人只列所选地址下资料。唯一候选自动采用，多候选待选择；更换地址不残留旧联系人，清除地址同时清联系人，单独清联系人不清地址。缺地址不能存订单，无联系人可继续。

### VAL-15 就地维护及保存边界（spec 6.5～6.7）

在选择弹窗新增、编辑地址及联系人，分别尝试缺少邮编／地址1、缺少姓名、无地址新增联系人；合法保存后关闭订单表单，再去客户管理查看。另取消一个尚未保存的弹窗编辑。

预期：缺必填项拒绝保存并给出对应提示。成功后客户资料建立／更正，新记录自动选用；即使随后取消订单表单，已保存客户资料仍存在。取消弹窗内未保存修改不改变主档；既有历史订单和正式寄送文件不因主档更正而变化。新增后再次打开选择列表应能找到新资料，编辑后的详情即时可核对。

### VAL-16 多订单行与数量（spec 3.2、6.5～6.6）

选择一个对外产品名称，添加两行不同颜色及数量，保存；再测试空颜色、空数量、零、负数、小数和字母。

预期：一个订单可有多个订单行（每个颜色细节一行），但所有订单行的产品名称必须相同。颜色选填，不要求来自字典。数量只能为正整数，整单需求总数量不得低于整单当前有效交付数量；允许调整颜色行及其数量，只要各行数量为正整数且整单总数满足底线，不按颜色或实物规格拦截。

### VAL-17 客户订单号保存、修改与查找（spec 3.1、4.4、6.7）

新建时输入客户订单号并保存，回详情和列表查看，再编辑更改、清空；每次用对应值查询。

预期：新建值被保留，详情与列表首行显示，查询可命中；修改后显示新值，清空后显示「—」。全过程注文管理番号保持不变，不因客户订单号相同合并订单。当前新建保存缺口见第 6 节。

### VAL-18 编辑入口与交付数量底线（spec 5.4、6.4～6.7、7.2）

对未发货、部分发货、已发足的有效订单进入编辑；尝试低于已履约数量、减少到恰好已履约数及追加数量。检查已取消订单。

预期：有效订单始终有编辑入口，全字段可编辑，已发足仍可追加。数量低于已履约数量不得保存；恰好等于底线可保存，追加后出现剩余可发，历史不变。已取消无编辑入口且不能靠直接进入表单保存。

### VAL-19 已交付后更换配送资料（spec 3.3、6.5～6.7）

部分出货后，更换納品先、配送地址、联系人及請求書先保存，返回详情再进入编辑，并打开剩余需求的新寄送；同时查看之前已确认出货与文件。

预期：当前订单与后续寄送采用本次保存的新资料，详情和编辑一致；原已寄出内容与已生成文件保留当时资料，不被覆盖；不重复建立订单或产品关系。当前详情采用资料未同步的问题必须实际复验后修正。

客户资料删除补充验收：订单采用资料后，在客户管理分别删除其支店、地址或联系人。订单历史仍可读；未更换相应客户／配送选择，仅改备注或数量时可沿用完整快照保存，并可继续新建寄送。配送必填快照不完整时不得新建可确认的发货；更换选择时，已删除对象及伪造跨主体地址／联系人不得通过校验。既有已寄出资料与文件不被回写，不重建已删除主档。

### VAL-20 历史多名称订单（spec 5.4、6.7）

打开一张各行名称不同的历史订单，核对明细；进入编辑只改备注并保存，再查看各行名称及交付归属。

预期：详情保留逐行原名称；只改备注不得把所有行替换为第一行名称，不丢行、不改变已有交付的来源。当前表单的单名称提交与此保护边界冲突，终审前不得执行为正式验收通过。

### VAL-21 保存、返回与身份（spec 6.2、6.5～6.7）

历史多名称继续发货补充验收：新建寄送时须明确从本订单已有名称中选一项，本笔产品统一采用该名称；未选择或伪造其他名称不得成立寄送。不同笔可选不同已有名称，不改写原订单行、旧寄送及文件，不把履约按名称或颜色拆分。普通同名订单无需额外选择。

分别在新建、编辑中改变内容后点返回或取消，再执行一次合法保存；比较订单数量、编号及操作记录。

预期：未保存新建不出现订单，未保存编辑不改原单；新建取消回列表、编辑取消回详情。成功创建只新增一张，编辑保留原身份并新增一次编辑记录；订单表单取消不撤销已单独保存的客户主档资料。

## 4. 编号与页面间完整闭环

### VAL-22 编号前缀、共用序列与年度重置（spec 7.1）

以未使用正常订单的新库为起点，无需执行订单号初始化SQL，分别模拟2026年及其他年份首次使用；依次创建销售、租赁、替代订单，再进入下一日本年度。分别在首次正常创建之前、之后补录更大标准格式号、与新号相同的历史号、重复号和后缀号。既有年度序列分别使用0、1000及其他合法已用值，重启／重新部署后继续创建。

预期：首次使用年度前三张尾号为1001、1002、1003，I/R/D共用序列；后续新年度首张尾号0001。年份取日本环境的生成年度而非受注日期，不按月重置。已有序列从原值加一，不强制改成1000；历史补录顺序和历史编号不影响上述结果。编辑、取消不改号、不复用取消号。

失败与并发：两个不同请求首次竞争不得各自重置序列或取得同一系统号；成功键重放不取新号。初始化后的业务写入失败时，序列、请求及订单数据同事务回滚。已有正常系统订单但其本年度序列缺失时拒绝；完全丢失订单序列但保留正常订单时也拒绝。仅有历史补录订单不触发此拒绝。非法序列值或9999耗尽沿原规则拒绝，不扫描历史最大号或自动修复。模拟测试不能代替真实数据库竞争、回滚及部署验证。

### VAL-23 历史原值保护（spec 7.1）

查询历史重复号、含后缀和错录变体的订单，逐张打开详情；编辑允许更改的普通资料后重查。

预期：重复号各自保留独立订单，可结合受注日、客户和数量区分；原编号不自动修复或替换。没有子单创建入口，也不因订单类型与历史前缀不一致而强制重编号。

### VAL-24 订单 → 发货 → 产品列表（spec 5.7、6.7、7.2）

```text
创建两行共三台的订单（一种产品名称，两个颜色细节）
→ 订单详情发货，录入两台产品并保存准备
→ 返回订单详情及产品列表核对
→ 确认寄出
→ 订单详情核对已交付两台、剩余一台
→ 产品列表／详情核对製造番号与当前订单
→ 返回订单继续寄出剩余一台
```

预期：准备不计交付，确认后才建立各产品当前订单关联；同一产品不同时属于两个当前订单，不重复增加出货数量。全部满足后页面显示「已完成」，无人工完成步骤，仍可编辑追加。打印本身不增加交付。正式打印输出另按寄送目标稿验收。

### VAL-25 错误交付解除后重新出货（spec 5.5～5.7、7.2）

```text
订单甲已交付一台
→ 订单甲详情解除该产品关联
→ 产品列表查看成品在库及无当前订单
→ 为订单乙选择该产品并确认寄出
→ 回查订单甲、订单乙及产品历史
```

预期：订单甲有效交付减少、历史出货不减；订单乙取得新的交付事实；产品身份不变，仅乙为当前订单，甲的历史关系及寄送仍可追溯。重新发货仍须满足寄送模块条件，解除不自动免除报废、占用等限制；不按产品业务类型限制订单类型。

### VAL-26 取消后受付与历史（spec 5.7、7.3）

```text
订单部分寄出
→ 填原因取消订单
→ 产品仍显示原订单来源
→ 实物寄回，在受付识别并记录
→ 按实际回收／后续处理登记结果
```

预期：取消不撤销历史、不自动回收、不自动报废；受付不因订单取消而阻断，回收由其自身动作记录。订单不能新增寄出，既有寄送准备也不能绕过取消继续确认。

### VAL-27 分次发货文件与履约隔离

同订单分别建立发货准备 A、B 并生成各自保障确认书；删除 A，再将 B 正式寄出。

预期：A、B 保障确认书仅含各自生成时清单；删除 A 同时删除其所属清单关联及全部文件、邮件版本，B 不受影响。准备及生成／打印不改变履约或产品订单关系；正式寄出后 B 版本保留，不允许删除。

## 5. 回归检查

- 同订单多次发货保障确认书各自独立，删除准备不删除其他发货或改变正式履约。

- 是否出现人工「确认完成」、待完成确认或完成后整单自动冻结？
- 是否出现受注案件、父子订单或自动拆单入口？
- 是否将订单侧「打印编号清单」或已取消的批量打印快捷入口重新加入？
- 是否在列表、详情、出货记录及解除弹窗重新展示 M番号？
- 是否因保存准备、生成／打印文件、复制邮件而重复增加交付或建立产品关联？
- 是否把正常回收当成错误交付，使原单重新欠发？
- 是否取消订单就自动解除关联、删除寄送或建立回收、报废？
- 是否修改客户主档或当前订单就覆盖已寄出资料和正式文件？
- 是否仅改历史订单备注就改变原行名称、编号或交付归属？
- 是否出现颜色必填、实物规格强匹配或额外确认审批？
- 是否把多张历史同号订单合并为同一记录，或不同类型分别从同一年度序号起号？
