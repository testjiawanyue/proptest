## 1. 作业管理

### VAL-01 批次行与行顺序

操作：进入「作业管理」，核对主表行的排列；上下滚动内容区；横向滚动。

预期：每个大番号第一条产品前出现批次行，单行显示大番号、進捗（已完成/有效总台数）、製品数量、受付日時四项，无其他内容；同一大番号产品连续显示，顺序为批次先后 → 批内受付先后 → 製造番号升序；内容区滚动时当前批次行吸附在表头下方，滚动到下一批次时被下一批次行替换；批次行为不透明浅灰底，横向滚动时内容不透视错位。

### VAL-02 Tab 按批次归类

操作：切换「进行中」「已完成」Tab，核对括号内数字与批次归属。

预期：数字为大番号批次数；批次内只要有一台未完成，整批（含已完了产品）显示在「进行中」；全部完成后整批进入「已完成」；同一大番号不拆到两个 Tab。
### VAL-02A 单台完成口径的边界

操作：对同一台产品分别验证：組立三项全部选 ○；三项中有一项选 × 其余选 ○；仅两项有结果；組立三项未完成时直接确认回收（处理计划 PROP回收）。

预期：三项全部有结果时该台显示「完了」——其中含 × 也算完了（× 是已填写的异常结果，不是未完成）；仅两项有结果时仍为「作業中」；組立未完成时确认回收，该台直接显示「完了」；以上变化同步反映到批次进度与整批 Tab 归属。


### VAL-03 筛选与搜索

操作：依次使用清洗／展开维修／客户确认筛选；分别输入大番号、小番号（原始整数、4 位补零、大番号-小番号连写）、製造番号片段、客户名片段搜索，并尝试带首尾空格、全半角与大小写差异的输入；点击重置。

预期：三项是否筛选选择即时生效；关键词需点击查询或按 Enter 生效；客户确认默认「不需要确认」；关键词对大番号、小番号（三种形态均可命中）、製造番号、客户名部分匹配（忽略首尾空格、字符宽度与英文大小写）；筛选后剩余行仍按原顺序且同批连续；批次行仍显示完整批次真实进度与总台数（如真实 3/5，即使只筛出 1 台仍显示 3/5、製品5台）；重置恢复默认筛选，且不改变作業グループ选择。

### VAL-04 工作组聚焦

操作：依次选择作業グループ的全体／縫製／センサ／組立／センサ+組立。

预期：全体显示縫製、センサ、組立三列；单选只显示对应列；センサ+組立同时显示两列；聚焦只隐藏列，行数据与行顺序完全不变，批次行不受影响；无清洗、展开维修聚焦项。

### VAL-05 製品情報列内容

操作：核对一台产品的製品情報列。

预期：第一行为製造番号｜受付类型｜单台状态（完了绿／作業中橙）；第二行为小番号连写（大番号-小番号4位）；第三行为清洗／展开维修／客户确认要求标签（需要醒目、不需要中性）；有 NG 或受付备注时以浅色分隔线进入异常区；不显示 M番号与客户公司名；大番号与受付日時只出现在批次行。

### VAL-06 检查登记与全部OK

状态：2026-10-14按钮常驻及重试文案切换增量待定点验证；其他已通过证据按实际版本复用，具体状态见当前Change验证记录，不将本次文档更新记为运行通过。

操作：在某组检查区为部分项目选 ○／×；选择 × 后填写 NG 内容与检查备注；点击「全部OK」；将 × 改回 ○。

预期：选择即保存到本组当前作业记录；× 展开 NG 内容多选（可选择或现场输入；现场输入的新值只保存到该台作业记录，**不进入**该组常用 NG 清单，下次打开清单时不出现该值）与备注框（按 Enter 保存）；全部OK 将当前产品本组三项（包括已有 ×）统一为 ○，清除对应NG内容和检查备注，保留工作组备注、处置和其他组；入口持续显示，有未检查、×或待处理检查变更时可点击，三项均已保存为 ○ 且无待处理检查变更时保留按钮并置灰、不重复提交；× 改回 ○ 后该项 NG 内容与备注清除。三组的检查项目按页面原文核对——縫製：エアバッグ／ジャケット／バックル；センサ：動作特性／ケーブル断線確認／電源電圧特性；組立：ケーブル接続確認／外観確認／動作确认。

补充操作与预期（2026-10-14裁决）：
- 混合未检查／○／×并填写NG及两类备注后点全部OK：三项为○、NG内容和检查备注清除，工作组备注／处置保留；清洗、展开维修及其他产品不变。
- 全部OK后再选某项×并输入备注：较早响应不得覆盖新选择或文字，备注仍按Enter保存；反向顺序（先×后全部OK）则以全部OK为准。
- 全部OK明确失败后，同一入口显示「重试全部OK」；仅新增未保存文字时仍保留重试文案。点击重试视为最新操作，三项为○并清对应附属内容；重试成功恢复「全部OK」，按当前检查状态决定是否置灰。
- 全部OK明确失败后，选择某项×并成功保存：同一入口恢复普通「全部OK」，不要求保留专用重试按钮；普通入口可点击，再点击则统一三项并清对应附属内容。切换入口不能静默丢失尚未提交的草稿。
- 其他组或仅工作组备注／处置保存成功，不应结束本组全部OK的重试状态；在途、结果未知及版本冲突仍按既有保护处理，不因入口持续显示而绕过。
- 重试全部OK发出后再新增×或备注：响应不能抹掉后续输入，待保存文字仍为草稿；后续明确提交按顺序成立。使用最新服务端revision，冲突仍须核对，不以“最新操作”为由强制覆盖他人修改。

### VAL-07 处置与备注登记

操作：在某组处置输入中选择一个常用值，再现场输入一个新值；填写工作组备注按 Enter；修改后再次保存。

预期：处置多选选择即保存；现场输入的新值只保存到该台作业记录，**不进入**该组常用处置清单，下次打开清单时不出现该值（清单内容固定）；备注按 Enter 保存；重复修改直接覆盖当前值，页面无「查看作业历史」入口，不产生历史条目。

### VAL-08 清洗登记（寄宿縫製列）

操作：对需要清洗的产品，在縫製列下方清洗区勾选「已完成清洗」，填写备注按 Enter；再取消勾选，随后修改备注按 Enter。另核对：要求不需要清洗但已有清洗记录的产品、要求不需要且无记录的产品。

预期：清洗区标题与状态标签同行；勾选登记清洗完成事实，取消勾选清除该事实回到待清洗；取消勾选后修改备注，完成状态不会被恢复；登记内容属于清洗组作业记录（不并入縫製）。要求不需要但已有清洗记录时清洗区仍显示；要求不需要且无记录时清洗区不显示。

### VAL-09 展开维修登记（寄宿センサ列）

操作：对需要展开维修的产品，在センサ列下方先填写工作组备注，再输入目录文本按 Enter；随后修改备注按 Enter；再清空目录输入按 Enter。另核对：要求不需要但已有展开维修记录的产品、要求不需要且无记录的产品。

预期：登记前填写的备注随目录登记一并保存；登记后状态标签变为「已登记」，内容属于展开维修组作业记录；登记后修改备注只更新备注，目录登记状态不变；清空目录回车后撤销登记回到「需要」；要求不需要但已有记录时展开维修区仍显示，要求不需要且无记录时不显示；页面不提供打开本地文件或校验路径功能。

### VAL-10 更换衣体

操作：点击縫製部品情報中的衣体编号，在确认弹窗中确认。

预期：弹窗说明线下实物更换且身份、制造编号、绑定不变；取消无数据变化；确认后实际登记“更换衣体”事件，縫製作业记录保留「ジャケット交換済」处置痕迹。产品及系统衣体身份、PTG26001 编号、绑定均不变；无新衣体、旧衣体解绑或线上报废记录，不触发产品报废，衣体资料不自动变化。历史事件仅显示“更换衣体”，不出现编号对照，时间与操作人沿用原规则；普通处置编辑不抹除已发生事件。

### VAL-11 更换部件校验

操作：点击气囊／传感器／发生器编号，分别输入不存在的编号（现场新入库）、类型不匹配的部件编号、已绑定其他产品的部件编号、空闲但资料与所选不一致的部件编号、有效未绑定部件编号；并改选部件资料后再确认。

预期：弹窗部件资料默认带出原部件资料、可改选（传感器更换同时选择固件版本）。不存在的编号按所选资料现场建档入库后更换；类型不匹配、已绑定他人的编号弹窗内提示原因且不执行更换，失败后部件绑定与作业记录均无变化；空闲但资料不一致时弹窗内确认「以所选资料为准」后更换并更正该部件资料；有效部件确认后部件绑定更换（旧关系保留为历史），本组作业记录登记换件事实。

### VAL-11A 补录部件（气囊／传感器／发生器）

操作：对某台产品未绑定的气囊／传感器／发生器（部品情報区显示「—」）点击「—」打开补录弹窗；分别测试：不选资料直接确认、输入已绑定其他产品的编号、输入空闲但当前资料与所选不一致的编号、输入不存在的编号（现场新入库）、正常补录；传感器另选固件版本。

预期：点击「—」打开补录弹窗；未选部件资料时提示必选；已绑定其他产品的编号提示「该部件已安装在 XX」且不执行；空闲但资料不一致时弹窗内提示「以所选资料为准」二次确认；不存在的编号以所选资料现场新入库再绑定；确认后该台该组作业记录登记补录事实（无 → 新部件），部品情報区显示编号与资料标签（可点击更正资料）。衣体无补录入口。

### VAL-12 固件升级

操作：在センサ部品情報的バージョンNo 下拉选择新版本；再选择当前版本。

预期：选择新版本后传感器固件事实更新（历史版本保留），本组作业记录登记升级事实（原版本 → 新版本）；选择当前版本不产生新记录。

### VAL-13 报告生成与类型

操作：分别使用返回客户、PROP回收、报废及空计划，生成单台点检报告。

预期：均固定提供履歴及生成点检报告；回收／报废计划在弹窗顶部提示但不阻断。不出现单台回收／报废报告入口。不要求作业完成或实际处理；生成新版本后不锁作业、不产生处理事实。

### VAL-14 报告列与履歴

操作：无报告时打开履歴；生成两次点检报告，再查看历史与预览。

预期：无历史为空列表；履歴按生成时间倒序列出单台点检版本，操作仅查看，预览内下载／打印。生成按钮始终保留，旧版本不可变、不失效。

字段、空值、比较与排版分别按下文VAL-IR系列核验；旧原型字段不覆盖2026-10-16裁决。

### VAL-15 回收／报废确认

操作：对处理计划为 PROP回收的产品点击「回収確認」；对处理计划为报废的产品点击「廃棄確認」；核对弹窗内容后确认。

预期：弹窗显示製造番号、大番号、客户与操作结果说明，明确提示不可逆，需二次确认；确认回收后形成回收事实、产品与当前订单关系结束（历史保留）、该台视为完了、処理列显示「回収済」，且这是结束当前关系而非取消履约——订单有效履约数不扣减、不取消订单（区别于订单侧「解除关联」否定原交付）；确认报废后形成报废事实、产品生命周期终结、该台视为完了、処理列显示「廃棄済」，且气囊／传感器／发生器部件个体不随之报废（解除绑定后可继续用于其他产品，仅产品与衣体编号终结）；只有尚无实际回收／报废事实且计划为返回客户或空时，処理列显示「—」；已有实际事实的标签不因改计划消失。

### VAL-16 NG 详情只读

操作：点击製品情報中的正式 NG 内容。

预期：只读弹窗显示 NG 内容、图片、备注；页面不提供修改正式 NG 的入口。

### VAL-17 多人编辑冲突

操作：两人同时编辑同一台同一组的作业内容并先后保存。

预期：后保存者看到冲突弹窗，显示对方已保存的内容（保存时间、操作人、内容）；可选择「放弃我的修改」或「保留我的内容并保存」；系统不静默覆盖。

### VAL-18 分页

操作：在批次超过 3 个时翻页；切换筛选后再观察分页。

预期：每页 3 个大番号，同一大番号不跨页；总数显示「共 N 个大番号」；匹配批次不超过 3 个时不显示分页条（含 3 个边界），第 4 个批次出现时分页条出现；查询、筛选、重置、Tab 切换后回到第 1 页。

## 2. 端到端闭环

### VAL-E1 批次作业到回收

操作：受付工作台完成一批 3 台受付（处理计划 PROP回收）→ 作业管理「进行中」出现该批次 → 各组登记检查与处置 → 組立三项全部有结果后单台变「完了」→ 批次进度变为 3/3 → 整批进入「已完成」→ 在作业管理大番号头部勾选本批产品生成大番号回收报告 → 逐台确认回收。

预期：批次进度随作业实时变化；报告生成不受作业完成状态限制；确认回收后订单当前关系结束（履约数不扣减、非取消履约）、该台作业视为完了；全过程行顺序与批次连续不变。

### VAL-E2 报废路径

操作：处理计划为报废、尚未确认报废、組立检查尚未全部完成的产品进入作业管理 → 在作业管理大番号头部勾选生成大番号报废报告（不确认报废）→ 核对作业状态 → 确认报废。

预期：仅生成报告时作业状态不因此变完了、产品未终结；确认报废后该台视为完了、処理列显示「廃棄済」、产品禁止再次受付。

## 3. 回归检查清单

- 普通作业编辑不覆盖衣体更换等已发生事件；“ジャケット交換済”保留，实物更换不自动更改资料。

- 同一大番号产品在任何 Tab、筛选、聚焦、分页下都连续且顺序不变。
- 批次行进度始终为完整批次真实进度，与筛选结果无关。
- 单台完成只看：組立三项全有结果、或已回收、或已报废；无人工完成或人工修改完成状态的入口。
- 报告与回收／报废严格分离：报告可多次生成、不可变、不锁作业；实际处理确认才形成事实。
- 确认回收是结束当前订单关系，不是取消履约：订单有效履约数不扣减、不取消订单；与订单侧「解除关联」（否定原交付、扣履约）是两个动作。
- 检查 NG／处置的现场输入新值只进该台作业记录，不回写进该组常用清单（清单固定）。
- 报废不级联部件：仅产品与衣体编号终结，气囊／传感器／发生器部件个体保留可再用。
- 未绑定部件（气囊／传感器／发生器）可点击「—」补录，编号可现场新入库，已绑定他人拦截；衣体无补录。
- 清洗／展开维修登记内容属于各自组的作业记录，页面列寄宿不改变事实归属。
- 本页不出现 Package、临时装箱信息及相关筛选。
- 本页无「查看作业历史」、无报告版本号显示、无「作业后追加」标记。

预期：内容字段无必填阻断，包括抬头、报价号、起始值、NG、检查、日期、下次年月和展开经过；缺失按空白，不以零、当天（指定默认日期除外）、历史来源或○造值。两入口使用同一字段规则、同一小番号版本序列和历史，不各自产生一套报告。

### VAL-IR-19 冻结与再次生成不继承

操作：v1中覆盖抬头、請求先、名称、販売年月日、报价号、起始补录、四项可编辑勾选、展开经过、报告日期和下次年月；随后修改大番号、产品、当前订单／出货、受付年目／NG、各组作业、绑定／固件、清洗／目录及字典，生成v2并重新查看v1。

预期：v1所有采用内容及比较结果不变，预览／下载／打印不按当前源资料重算。v2每项按规定来源重新读取、默认日期重新带出；人工项重新填写，不继承v1的补录／覆盖／勾选；历史起始记录仍是小番号成立时的值，不被当前业务修改。v1、v2不可变，不标记旧版过期、需更新或修正版。

### VAL-IR-20 取消与真实生成失败

操作：填写报告后取消；另在已有版本情况下，覆盖明确的来源读取失败、文件生成失败或保存失败，再查看历史和删除保护状态；与内容字段缺失的可生成场景对照。

预期：取消不生成版本；真实技术失败如实反馈，不把读取失败伪装成业务空值、不提示成功、不留虚假正式版本或新增报告删除阻断，旧版本仍保留。明确未成功时可保留本次输入供重试；不以字段缺项冒充生成失败，也不以“内容不要求必填”掩盖真实技术失败。不为本用例预建故障平台。

### VAL-IR-21 作业与删除边界接续

操作：成功生成单台点检报告，随后继续编辑作业、尝试删除对应小番号；对照同批无自身阻断的小番号和空包裹；核对实际回收／报废／返送事实。

预期：真实报告生产与对应小番号删除保护同批接入；报告保护本小番号，其他小番号、空包裹沿各自规则，不额外扩大阻断。生成不锁定作业、不认定实际回收／报废／返送、不改变单台完成口径。已有正式报告的大番号保护仍按FEAT-14／15既有规则；不引入批次记录表的正式报告保护。

### 2026-10-16 新旧验收要求替代说明

本专项及正文§5.8取代单台PDF“内容待正式需求”的历史验收缺口。撤回展开经过条件必填，所有内容缺项不阻断生成；原字段表、旁注和旧原型冲突项按模板README排除。此处只增加可核验场景，未执行数据库、编译、接口、页面、PDF或打印验收；其他报告与打印模板不因本专项自动定稿。

### VAL-BATCH-REPORT 大番号报告完整流程（待实施）

在作业管理进行中／已完成Tab核对大番号头部两个生成按钮始终显示；无对应计划产品时提示本批次无报废／回收产品。准备同批不同计划产品，弹窗仅列对应类型全部候选、默认全选，包含已实际处理但计划仍符合者。取消不生成，取消全部选择不得生成；发行日默认当天可修改。

打开后将所选产品计划更改或合法删除，再确认：提示重新确认，不自动剔除或生成部分报告。正常勾选生成后预览为大番号及本次产品清单。先后生成回收v1、报废v1、回收v2，分别连续计版，其他批次独立；作业管理大番号头部报告历史弹窗只含两类大番号报告，返送详情无这两类生成或历史入口，查看之外无下载／打印按钮，预览内提供下载／打印。

修改发行日不改变实际生成时间顺序；随后修改计划、追加或合法删除小番号，旧版内容及清单不变。已无候选时旧版仍可查看。无自身阻断的小番号可删、空包裹可删，但存在正式报告的大番号即使清空产品也不可删。生成不登记实际回收／报废／返送、不锁作业；已返送后首次报废及双事实显示规则保持。单台点检报告在任意计划下仍可生成，不出现旧单台回收／报废入口。以上为待实施验证，未运行通过。

### VAL-RR-01 抬头与身份（待实施）

### VAL-RR-02 发行日与系统元数据（待实施）
