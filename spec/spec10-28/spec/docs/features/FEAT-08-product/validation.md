正常角色配置回归：通过现有角色页仅选产品列表，或仅追溯，或两者；产品列表页面授权应覆盖所属隐藏详情，无需额外选择隐藏详情菜单。保存、重开、再次保存后必要目录关系保留，未选兄弟页面不新增授权。不能要求选择整个目录；取消子页后不回选。与系统既有按钮及独立树选择语义共同验证，真实登录结果仍需取得证据。

导航补充验收（待运行）：仅产品权限、仅追溯权限、双页面权限分别登录，产品管理目录下分别只见产品列表、只见部件追溯、同时见两页；详情不出现在菜单。点击、刷新、标签切换/关闭及详情返回列表正常，无独立一级追溯入口，不能访问未授权页面/API。菜单迁移不得丢失原角色子页授权。

对无任何阻断的产品执行删除并确认：仅当前衣体绑定，非衣体绑定均已结束，无质检、出货及受付记录；预置历史安装、拆除、组装和衣体资料更正记录。分别覆盖所属入库记录还有其他有效成员、删除后没有有效成员两种情况。

- 产品与衣体不在当前有效列表、选择和后续业务范围；
- 原产品及衣体身份和完整历史数据保留；仍存在的关联业务历史继续在其原有展示位置显示原本关联的原对象编号、采用资料及事件内容，能理解发生过什么，不因同编号重建而改指新对象；不要求将原对象的全部历史新增展示到其他产品、部件或业务页面。原身份与完整历史的数据保留另行通过数据验证确认；不要求新增已删除产品查询页、历史检索或导航入口；
- 非衣体部件档案及其在本产品、其他产品上的历史不受影响；
- 该衣体不计入原入库记录有效成员；还有有效成员时继续展示，没有有效成员时不作为有效记录展示，历史登记信息保留；
- 同制造编号可重新入库，但新产品与新衣体均为独立身份，不继承原历史；原 M番号不复用；
- 正常更换衣体并不产生另一个需要保留或删除的系统旧衣体对象。

2. 部件组装完成三类必需部件（见 FEAT-06 部件组装 VAL-09）；
3. 质检工作台确认质检（见 FEAT-07 质检）；

5. 进入详情查看基本信息、生命周期、相关业务历史。

预期：入库后产品即在列表（在制）；组装完成后变为待质检；质检后变为已完成质检；详情显示完整部件构成与历史事件。

### VAL-27 删除后衣体重入闭环

删除一台无阻断产品后，用同一衣体编号重新入库。

预期：入库不命中「已有档案」；新产品配发新 M番号（不复用旧值）；新产品的相关业务历史只包含本次新建产品的事件（建立产品等），不继承被删除产品的旧历史。仍存在的关联业务历史继续以原对象当时的编号、采用资料和事件内容表达旧产品及衣体事实，不能按相同编号改指新对象；数据验证确认原身份及历史行仍保留。新衣体为新入库记录的成员，原已删除成员不恢复；不要求为旧对象新增查询页或导航入口。

### VAL-08c 删除阻断保留出货记录原范围

对仍有准备中出货记录的产品请求删除；另覆盖正式出货记录。其余阻断条件按现有状态记录，不以是否打印文件缩小出货记录判定范围。

预期：两类出货记录均命中出货记录阻断；不将条件改为仅“正式寄出”，不新增其他阻断条件。

## 5. Definition of Done

- 更换衣体为确认制，不改变製造番号；
- 删除产品与衣体退出当前范围且原历史保留，非衣体档案不随删；M番号不复用，衣体编号重入建立独立身份；
