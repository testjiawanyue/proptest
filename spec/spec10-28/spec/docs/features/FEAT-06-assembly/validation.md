# FEAT-06 部件组装 Validation

> **本次修订验证状态（2026-09-25）**：以下修改及新增场景为验收要求，均未执行；历史 demo 核对、旧测试结果不表示本次规则已验证。原型资产未更新，冲突表现以本次正文为准。

本文件按 spec.md 的页面结构逐页验证，再验证「入库 → 组装 → 追溯」完整闭环与删除、更换边界。用例依据 spec 与业务理解编写，覆盖 demo 已实现与未实现部分；demo 未实现项在对应用例注明。

## 1. 部件组装

### VAL-08 初始空白与筛选查询全部 Product

打开页面；不筛选直接观察表格；再分别用范围筛选和编号筛选查询。

预期：初始表格为空，提示「请通过製造番号范围或编号筛选产品」；范围筛选在不超过100件时显示该编号范围内全部 Product（含在制、待质检、已完成质检）；编号筛选显示匹配到的 Product；三部件齐全但发生器位置 2 为空的产品仍出现在结果中，位置 2 格保持空白可补录。

### VAL-09 录入保存与默认资料绑定

默认资料选气囊 A型，在一行气囊列输入新编号 AQ-26999，Enter。

预期：保存成功；编号旁显示资料 Tag「气囊 A型」（可点击下拉）；该编号首次使用自动建档（部件追溯可见，来源：组装建档）；底部显示三部件齐全计数变化。

### VAL-10 Enter / Tab / ↑ 分工

补充空格回归：不选默认资料/固件，原本为空且未修改的四类格按Enter到下一行同列、Tab到右格（行末到下一行），保存API调用为0；末行Enter/末格Tab不越界。保存中、失败或待确认不能以空格为由跳过门禁。已保存编号清空后不能跳格或标记成功，原基准保留，不隐式拆除；恢复编号或明确拆除仍按既有流程。

在某行气囊列输入后按 Enter；再输入后按 Tab；空格按 ↑。

预期：Enter 保存并聚焦下一行气囊列；Tab 保存并右移到传感器列（行末移到下一行气囊列）；↑ 带出上一台同槽位编号。最后一行按 Enter 只保存不跳格并显示提示。

### VAL-11 传感器固件

在 FEAT-03 中保持 223k05、223k03 启用，默认固件选择 223k05，录入新传感器编号保存；再在该格固件 Tag 下拉选 223k03。随后停用当前已采用的 223k03，刷新并再次打开固件选择。

预期：新选择均只来自 FEAT-03 启用的传感器固件版本；保存后固件 Tag 显示 223k05；下拉更新后显示 223k03；停用后当前 Tag 和历史仍显示 223k03，不清空、不替换、不要求重新选择，但新的下拉选择不再包含 223k03。部件追溯该传感器履历应出现两条固件记录（首次设定 223k05 → 更新 223k03；当前 demo 履历尚未展示固件记录，属待实施项）。

### VAL-12 资料不一致确认

编号 AQ-26001 已建档为「气囊 B型」，默认资料为「气囊 A型」；在某行气囊列输入该编号保存。

预期：行内出现确认条（说明当前资料 B型、默认资料 A型）；Enter 确认 → 以 A型更正并保存，资料 Tag 显示 A型；Esc 取消 → 放弃保存。重复用例：确认后再查部件追溯，履历有一条资料更正记录（B型 → A型）。

### VAL-13 更换确认

某行气囊列已保存 AQ-26011，改为另一新编号 AQ-26099 保存。

预期：出现更换确认（说明原编号与新编号）；确认 → 原绑定结束、新编号绑定（操作记录为更换）；取消 → 还原为 AQ-26011。

### VAL-14 行内资料更正不影响其他产品

两台产品使用同一编号体系的不同部件：产品 A 气囊格资料 Tag 从 A型改为 B型。

预期：仅该部件的资料归属被更正（追加更正记录）；其他产品的部件不受影响；底部提示已更正。

### VAL-15 默认资料切换范围

顺序补验：气囊资料→传感器资料→传感器固件→发生器位置1资料→位置2资料；确认/取消、草稿保护、鼠标/键盘及loading门禁与原规则一致。

一行已保存气囊（A型）后，顶部默认气囊资料切换为 B型；再在新行录入另一编号。

预期：已保存行资料保持 A型；新录入编号按 B型绑定。有未保存输入时切换先二次确认。

### VAL-16 录入校验

分别在气囊列输入：传感器编号（类型不符）、已安装在其他产品的气囊编号、不存在产品的衣体行（通过编号筛选定位不存在产品时）。

预期：行内红色错误说明原因；未选择默认资料时录入提示先选择默认部件资料。

### VAL-17 范围筛选严格匹配

前缀 PTG，范围 26014~26015 筛选；再以 014~015（位数不足编号全长）筛选。

预期：严格按输入内容匹配——26014~26015 命中该范围内全部 Product；014~015 因编号不以 PTG014 形态存在而不命中。范围内没有衣体时提示「该范围内暂无衣体」；重置后回到空白状态。

### VAL-18 页面级动作门禁

制造一个保存失败（如类型不符），未处理时重新筛选／重置。

预期：提示「有数据保存失败或待确认，请先处理」，动作不执行；处理后恢复。

## 2. 页面间完整闭环

### VAL-21 列宽稳定（人工验收新增，待验证）

同视口连续Enter/Tab录入短/长编号，制造失败、待确认和保存中状态。预期：五列边界不移动；长资料/固件与错误可完整读取，按钮可达，窄视口仅表内横滚；↑和最后一行焦点不变。

### VAL-23 入库 → 组装 → 质检 → 追溯闭环

> 本用例涉及 FEAT-05 衣体入库与 FEAT-07 质检工作台。

1. 衣体入库：新建衣体资料（前缀 PTJ），范围入库 001～002 两件；
2. 部件组装：默认资料气囊 A型／传感器 A型＋固件 223k05／发生器 X型，逐行录入两件产品的三类部件；
3. 质检工作台：两件产品质检确认（页面规则见 FEAT-07 质检工作台）；
4. 部件追溯：查看新衣体与新部件的履历。

预期：入库后产品立即可组装；组装保存即建档并绑定；三部件齐全后质检可确认；追溯中衣体履历含入库、各部件履历含建档与安装；产品列表阶段从在制推进到已质检。

### VAL-24 更换衣体口径一致性

在产品管理与作业管理两处分别执行更换衣体。

预期：两处均为确认制弹窗，说明线下实物更换且产品、系统衣体身份、制造编号与绑定不变；无新编号输入框。确认后均实际登记“更换衣体”事件，不创建新衣体或解绑旧衣体，不引导组装绑定；无编号对照，时间与操作人沿用原规则；作业入口保留「ジャケット交換済」。

### VAL-25 绑定纠错与资料纠错

S001 正确档案误绑甲，结束绑定后安装到乙；另对编号正确但选错资料的部件执行既有资料更正。

预期：绑错时不删除正确档案，甲、乙历史属于同一身份；资料错误不要求删除重建，更正记录及原资料版本保留。

### VAL-26 删除后的同编号首次使用

S001 原档案 A 有安装、拆除、资料更正和固件历史，在无当前绑定时按 FEAT-09 删除；组装时重新登记 S001 为 B。

预期：A 不可再被选择或安装，旧历史可读保留；B 为独立身份，仅采用本次登记资料和固件，不继承 A 的记录；不得按编号将甲产品的旧历史转向 B。

## 3. 回归检查

- 绑错保留身份；资料纠错保留版本；删除后同号新档案不继承原固件或关系。

- 是否存在「产品创建」的第二个入口（组装页对产品不存在应报错并指引衣体入库，而不是自动创建）？
- M番号是否在任何界面露出（应只在数据层）？
- 删除部件后同编号重新建档是否被错误拦截（应允许）？
- 部件资料停用是否影响了已建档个体（不应影响）？
- 规格文本是否被解析出颜色等结构化含义并用于拦截或推导（不应解析）？
- 组装的更换流程是否出现过未经确认直接覆盖绑定（必须确认）？
- 页面上是否还存在部件个体停用／启用入口（应已全部移除）？
- 发生器位置 2 是否被当作必填（应为可空）？

## 4. Definition of Done

- 部件组装单页同屏录入四类槽位，Enter／Tab／↑ 分工如规范，保存即建档并显示可更正的资料与固件 Tag；
- 更换与资料不一致均有确认，未确认不覆盖；
- VAL-08 ～ VAL-18、VAL-23、VAL-24 全部通过；回归检查清单无命中。

- 本次关联验收门槛：修改和新增用例须取得实际验证证据后才可判定通过；不得沿用旧级联删除、新旧衣体编号对照、订单级保障确认书的预期。

### VAL-19 百件上限、无分页与保存保护

分别查询0、20、21、100、101件；清单中产生草稿、保存失败、待确认；延迟保存期间尝试改输入、筛选和重置。

预期：21件和100件完整可达且无分页；101件明确拒绝并保留旧清单及摘要，不静默截断。保存中相关操作禁用，成功才更新保存状态；失败/待确认/草稿先处理或明确取消才能替换清单，输入及错误不丢失。

### VAL-20 空前缀范围不丢失

准备001、002、003、999、A001及不同位数编号；以空前缀和001～003查询，另测有前缀、半填、非数字、位数不等及倒序。

预期：空前缀仅命中001～003，不包含999、A001或不同位数编号；非法范围明确拒绝，不变成无范围查询。产品列表count与分页结果一致；组装/质检仍执行100件上限。
