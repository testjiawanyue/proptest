> 最新裁决：删除受付完了时间及完成状态，保留完成按钮作查漏提示与返回初始页；批次记录表不再依赖完成按钮。下文涉及首次完成时间、完成标记及生成门槛的旧核对结论仅为历史记录，以当前spec／validation为准。

## 2. 本轮直接修正

1. FEAT-16原“计划为空显示—”没有区分已有历史报告，可能遮蔽永久有效的旧报告。按既有历史保留要求明确：计划空时不生成／再生成，但有历史仍提供查看入口，补VAL-13及23。
2. FEAT-17报告列原“已有报告就显示再生成”与计划空不生成冲突。同步为按当前计划类型生成／再生成；旧类型与计划空情况下历史仍可查看，补VAL-04、R2。这里不变更文件版本规则。
3. FEAT-16作业完了原用“该产品已回收”容易继承其他受付的历史处理；依据FEAT-14新受付不继承原状态，明确只读本条受付的完成事实，补VAL-23。
4. FEAT-17 VAL-08仍用旧称“留存”，修正为正文“PROP回收”。
5. FEAT-14／15历史核对记录明确不覆盖当前裁决，正文“已完成年度”的说明改为“已登记年度”；不删除历史证据。

## 3. 复核发现（F01、F02寄出前校验已由下方用户裁决关闭）

### F01 待返送统计与可返送条件不一致（待确认）

[FEAT-00 §3.3](../../FEAT-00-dashboard/spec.md)及VAL-03明确：待返送排除已回收、已报废；FEAT-17 §7.3只写计划返回客户且未实际返送，未排除已实际处理。FEAT-17 §7.1又禁止已回收／报废产品进入面单。

触发：已回收或报废后把计划改成返回客户。当前条款可导致首页不计入、返送页计入待返送、但无法勾选。之前的建议尚未获裁决，本轮不修改计数公式。

建议：FEAT-17待返送统计同步排除本条受付已回收／报废，和首页、实际可寄送事实一致；仍允许修改计划和生成对应报告。计数单位仍各自保持首页批次数、返送页台数。

### F02 已选入准备中面单后再执行回收／报废（待明确动作边界）

FEAT-17 §7.1、6.6定义勾选时不能选已回收／报废；FEAT-16实际处理入口目前不以准备中面单为阻断。可以先选入面单，再在作业管理实际回收／报废，随后返回原面单确认寄出。正文尚未明确此时怎样检查原已选清单。

建议：确认寄出时重查现有不可返送条件，发现已处理产品则提示并阻止本次寄出，员工在准备中面单手动移除该产品后继续；不自动删除面单或移除产品，不因单纯计划变化阻止混装。已确认寄出之后是否仍允许这条受付首次执行回收／报废，现有正文也未给出跨事实先后限制；本轮不自行加锁或解除冻结。需要用户按实际工作确定。

### F03 首页验证中的入口旧称（非业务裁决项）

FEAT-00 VAL-05操作步骤仍称“受付侧确认回收”，但当前实际确认生产者是FEAT-16作业管理处理列。应由首页材料维护者改为对应入口，不把它解释为FEAT-14可以直接确认回收。本轮未修改首页文件。

## 4. 不构成冲突、无需重新设计

- 已回收产品再次来件建立新小番号，与同一条受付仅一次实际处理不是同一范围；不因此禁止所有未来来件。
- 空批次可完成、仍允许后续追加，不代表空批次产生了单台受付或作业事实。
- 点击下一台检查缺项，与允许未点按钮就切换／返回并保存现有合法内容并不冲突。
- 受付单人不做冲突弹窗，不取消FEAT-16工作组多人编辑的既有冲突规则。
- 旧批次新增产品沿用旧日期，对案内匹配的影响已记录在[C04交接补充](c04-handoff-date-impact-20261011.md)，不自动改用新建小番号时间。
- 实际处理完成不可逆与受付信息可持续修改不冲突；报告类型仍按计划，实际结果仍按确认事实。
