# 给C04 WP4的交接补充：旧批次追加日期

> 最新裁决：删除受付完了时间及完成状态，保留完成按钮作查漏提示与返回初始页；批次记录表不再依赖完成按钮。下文涉及首次完成时间、完成标记及生成门槛的旧核对结论仅为历史记录，以当前spec／validation为准。

2026-10-11用户明确裁决：旧批次允许追加后来新收到的产品，追加受付沿用所属大番号原受付日期，不调整旧日期，不判断同次来件或后来新来件，不新增改期入口。小番号按所属大番号年度取号。

生产依据：[FEAT-14 spec](../spec.md) §3.1、6.1及末尾后续裁决；消费依据：[FEAT-13 spec](../../FEAT-13-notice/spec.md) §6.5。有效受付仍是已建立且未删除／作废的小番号，不要求填齐或完成批次。

## 明确影响（不修改算法）

若大番号日期9月1日，案内9月10日发行，产品9月20日追加到该大番号，消费者仍取得9月1日。按现行“案内发行日不晚于受付日期”规则，这条受付不能满足9月10日案内；其他匹配事实不存在时，案内继续按现有规则判断未受付／超期。系统消费的是批次登记口径日期，不保证它等于后来追加产品的真实到货日期。

不得为修正这一结果偷偷把日期换成小番号建立日期、扫描日期或当天日期；不得自动重配案内。本交接不修改匹配算法，不把批次日期等同小番号实际建立时刻；FEAT-13涉及“受付发生时”的事件边界仍由C04按自身正式规则处理。
