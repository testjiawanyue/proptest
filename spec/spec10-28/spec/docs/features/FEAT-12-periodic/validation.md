# FEAT-12 定期管理 Validation

**状态：Current Truth**

## 1. 定期管理年度日历

### VAL-01 年份切换与 12 个月卡片（spec 4.2～4.4）

从顶部导航进入「定期管理」，点击上一年、下一年和「今年」，核对标题年份、12 个月卡片及当前业务月标签。

预期：页面显示 12 个月卡片；年份切换后卡片随所选年度刷新；「今年」回当前年；仅当前业务月显示「本月案内对象」。无对象月份仍显示卡片且置灰。

### VAL-02 生命周期统计口径（spec 3.2、4.4、8.4）

准备首次出货月分别对应第 0、1、4、5、6 年目的产品，覆盖有基准月、无基准月、已报废、同月多客户和同客户两类对象。

预期：第 1～4 年目计入定期点検台数，第 5 年目计入 5年目廃棄台数；第 0 年目、第 6 年目、无基准月和已报废产品不计入。对象客户数按该月存在对象产品的客户去重，两类合计。

### VAL-03 进入月度候选（spec 4.5～4.7）

点击有对象产品的月份卡片和空月份卡片。

预期：均可进入对应月度通知需求页；年度日历本身不建立或修改任何案内。

## 2. 月度通知需求页

### VAL-04 页头、筛选和列结构（spec 5.2～5.4）

从年度日历进入某月，核对返回图标、年月、四个筛选条件、查询和重置按钮，以及列表列顺序。

预期：页头为返回图标＋「YYYY年M月」，不显示「返回年度日历」副标题；返回按钮保留可访问名称，点击返回对象月份所属年度；筛选固定为顧客名、製造番号、通知種別、案内履歴；列表列为顧客、通知種別、対象製品、案内履歴、操作；客户名称与公司／支店类型标签保持8px横向间距。

### VAL-05 顧客名与製造番号筛选（spec 5.4～5.6）

分别输入客户名、製造番号、M番号和不存在的文字查询，再重置。

预期：顧客名按客户主档当前名称部分匹配，不扩展匹配订单旧名称；製造番号按製造番号部分匹配；输入 M番号不命中仅按製造番号才能命中的候选；不存在的文字显示「YYYY年M月没有符合条件的通知候选」。重置恢复默认条件。

### VAL-06 通知種別与案内履歴筛选（spec 5.4～5.6、8.8）

同一客户同月准备定期点検候选、5年目廃棄候选、无案内履歴、有一份案内履歴和多份案内履歴的场景，分别筛选 すべて、定期点検、5年目廃棄、なし、あり。

预期：一行表示一个客户 × 一个案内種類；同一客户两类候选显示两行。なし 只显示该客户、对象月、案内種類没有任何案内的行；あり 显示至少 1 份案内的行；案内履歴列显示 なし 或 N件。

### VAL-07 无当前客户关系只读详情（spec 5.4～5.7、6.8）

准备当前无业务关系的对象产品，进入月度通知需求页并尝试操作。

预期：该产品集合归入「（当前无业务关系）」行；操作列显示可点击的「詳細」。打开后只显示产品列表及製造番号查询、重置操作；列表为製造番号、商品名、年次、前回実績，已回收且未再派发的产品显示「已回收」。不显示数据统计、案内履歴、納品先筛选或列、底部通知操作区；无勾选框、全选和通知创建入口。查询、重置及关闭详情不建立或修改业务记录。

### VAL-08 打开通知创建抽屉（spec 5.5～5.7、6.2）

点击有当前客户关系行的「詳細」。

预期：打开通知创建抽屉，抽屉标题固定为该客户、该月份和案内種類；月度通知需求页本身不建立或修改案内。

## 3. 通知创建抽屉

### VAL-09 抽屉结构与固定上下文（spec 6.1～6.4）

从有当前客户关系的月度候选行打开抽屉，核对标题、三张卡片、底部汇总和可见操作。无当前客户关系的详情按 VAL-07 验收。

预期：抽屉显示客户名、月份和案内種類，且不可切换；卡片顺序为数据统计、案内履歴、筛选及候选产品；底部显示候補 N 台、今回対象 M 台和「通知を作成（M 台）」。

### VAL-10 数据统计和案内履歴（spec 6.4～6.6、8.1～8.3）

分别准备无历史、一份历史、多份历史案内的客户、对象月和案内種類，打开抽屉并操作历史行。

预期：数据统计以两列显示候補製品、直近3か月実績。无历史时显示「案内履歴はありません」且区域不隐藏；有历史时按实际创建时间倒序、同时间按案内ID倒序列出案内番号、発行日、通知作成日時、対象製品、操作；通知作成日時按日本业务时区显示YYYY/MM/DD HH:mm。历史行仅提供「表示」，下载／打印在预览弹窗内提供，不能修改、删除、作废、覆盖或设为当前。

### VAL-11 候选产品列与年次（spec 6.4、8.4）

分别打开定期点検和 5年目廃棄的抽屉，核对产品表所有列、年次、前回実績和最新案内。

预期：列为勾选框、製造番号、商品名、納品先、年次、前回実績、最新案内。定期点検年次为第 1～4 年目，5年目廃棄为第 5 年目；前回実績无值显示「—」；最新案内无值显示「—」，有值可查看案内番号与発行日提示。

### VAL-12 勾选、默认选择和全选范围（spec 6.4～6.6）

准备未被本月同类型案内包含的产品、已被包含的产品，分别进行勾选、取消、筛选后全选、重置筛选。

预期：首次打开以及关闭后重新打开客户详情抽屉，所有候选产品均不勾选，今回対象为0台，创建按钮不可用；不区分是否已被本月同类型案内包含。两类产品均可手动勾选。筛选、翻页和取消创建返回抽屉保留已有手动选择，不自动补选。取消勾选不要求原因。全选只作用于当前可见行；不可见行保持既有勾选结果。今回対象统计全部已选产品，不限当前可见行。

### VAL-13 抽屉内筛选与创建按钮（spec 6.4～6.7）

输入製造番号和納品先筛选，覆盖有结果、无结果、重置，以及取消全部勾选。

预期：納品先显示及部分匹配搜索均取产品当前关联订单保存的所选主体名称（快照 name）；选公司显示公司名，选支店只显示支店名，不附加所属公司名称。缺少该名称时显示「—」，不以所属公司名称替代；只输入额外所属公司名不应命中，除非文字本身也匹配所选主体名称。该规则不改变按下单方主体ID归组及客户主档当前名称搜索。筛选只影响展示，不清空已选产品。今回対象为 0 台时，「通知を作成（0 台）」不可用；大于 0 时可打开创建确认弹窗。抽屉本身不产生案内。

## 4. 创建确认弹窗

### VAL-14 弹窗字段与取消（spec 7.1～7.4）

在抽屉中选择若干产品并点击「通知を作成」，核对弹窗标题、摘要、字段和按钮，再点击取消。

预期：桌面弹窗居中，超高内容仅正文内部滚动，标题和底部操作保持可见；标题为案内種類 +「を作成」；摘要显示客户名、月份和対象製品 N台；字段包含顾客、納品先、発行日、備考；点检另有可编辑的製品名称和費用説明，默认值及冻结按VAL-R05验证，廃棄不显示这两个字段；不出现寄送地址、联系人填写入口，不出现追記事項。発行日默认当天，过去日期不可选择。取消关闭弹窗，不生成案内，返回抽屉继续选择。

### VAL-15 顾客只读与下单方校验（spec 7.4～7.6）

从顾客分组进入生成弹窗，核对顾客显示，并在提交前变更某选中产品的订单下单方。

预期：顾客取当前分组的下单方，只读，无选择器、编辑入口或重复注文者。产品下单方已变更时阻止生成并提示返回重新查询，不得混入其他顾客的产品。

### VAL-16 无已有案内提示与再次创建新番号（spec 7.4～7.7、8.1～8.2）

对同一客户、对象月和案内種類先生成一份案内，再回到同一组合重新创建。

预期：创建弹窗不提示客户已有案内数量或编号，也不新增产品重复包含提示；抽屉案内履歴与产品最新案内仍按原规则展示。员工可再次选择产品并创建，确认后取得新的案内番号；旧案内仍可查看、下载、印刷，不被覆盖或作废。

### VAL-17 納品先与「貴社」规则（spec 7.4、8.7）

选择納品先为「すべて（不限制单一納品先）」和单一納品先；准备納品先与顾客相同和不同的产品，生成案内后查看正式 PDF 与通知详情。

预期：正式PDF只使用本次所选抬头；与下单方同主体显示「貴社」，不同显示所选名，未选留空，不逐项替换产品納品先；通知详情的対象製品表始终显示完整公司名称，不显示「貴社」。

### VAL-18 備考与寄送信息（spec 3.1、7.4～7.7、8.6）

创建时填写備考后生成案内；随后修改客户主档地址、联系人和产品资料，再查看既有案内。

预期：创建弹窗及详情均不显示寄送住所、連絡先・担当者，不显示对应空白项目；客户或产品资料后续变化不影响案内。创建时填写的備考成为该案内備考初始值，仅内部使用；正式 PDF 不出现追記事項区域，PDF版式及字段按FEAT-12 §8.9执行。

### VAL-19 创建时资格校验（spec 7.6～7.7）

打开创建确认弹窗后，让某些已选产品不再属于当前客户、当前对象月或当前案内種類，再尝试创建。

预期：不得生成案内，并提示员工重新核对候选。通过校验时，一次确认只生成一份新案内和正式 PDF，不产生半成品。

### VAL-20 创建成功结果（spec 7.2、7.5～7.7）

合法创建案内后，分别验证成功弹窗直接「閉じる」，以及「表示」进入PDF预览、下载／打印并关闭预览。覆盖预览失败、下载失败、关闭／取消打印窗口后继续下载与再次打印，以及保留抽屉后主动再次创建。

预期：校验、首次渲染及快照／模板绑定提交成功即案内成立；成功弹窗显示案内番号、「表示」「閉じる」，不提供直接下载／打印。表示先关闭成功弹窗再打开只读PDF预览，成功后在预览内下载／打印，采用该次PDF及冻结文件名。关闭预览直接返回当前抽屉，不重现成功提示；失败可重试读取，不撤销案内、不换号、不重新POST。即使未预览或取消打印，案内仍成立。成功弹窗「閉じる」仅关闭提示，抽屉、筛选、分页及手动选择保留，案内履歴和最新案内刷新。主动再次创建重新准备数据并使用新requestId；原请求结果未知时仍须按原身份确认／安全重试，不能绕过恢复保护。关闭或取消打印窗口后可继续下载同次PDF及再次打印，不出现技术恢复提示或要求手动恢复；设备实际出纸另验。

## 5. 页面间完整闭环

VAL-33 的生成后查询与详情验证继续见 FEAT-13 通知管理。

### VAL-33 年度日历 → 月度候选 → 创建案内 → 列表 → 详情（spec 4～8）

```text
定期管理年度日历选择对象月份
→ 月度通知需求页筛选客户和案内種類
→ 打开通知创建抽屉并勾选対象製品
→ 创建确认弹窗确认只读顾客、选择納品先、発行日并填写内部備考
→ 生成新案内
→ 通知管理列表查询案内
→ 通知详情查看快照、正式 PDF 和対象製品受付情况
```

预期：全链路只建立一份新案内和一份正式 PDF；案内番号符合 `AN-YYYY-NNNNNN`；既有案内不修改、不覆盖、不作废；详情展示生成当时的信息和対象製品受付情况。

### VAL-34 纠正通知内容（spec 7.4～7.7、8.1～8.3）

```text
已生成一份案内
→ 发现内容需要纠正
→ 回到同一客户、对象月、案内種類重新勾选并创建
→ 分别查看两份案内
```

预期：第二次创建取得新案内番号；第一份案内仍永久保留，可查看、下载、印刷。系统不出现修正版、版本历史、当前有效版、作废或恢复动作。

### VAL-39 实绩与月度筛选（spec 5.4、6.4）

一个客户分组含多台候选产品，月度按其中一个製造番号搜索；准备任意类型有效受付（点检、维修、租赁结束、报废）、类型尚未选择、尚未完成作业、同产品多次受付、仅生产质检及空批次等对照事实。

预期：分组显示全组台数，详情仍展示全组产品。任意类型有效受付建立后即计入实绩，类型尚未选择也计入，不等待作业完了。对象月为 9 月时，直近3か月実績按所属大番号受付日期统计7～9月有任意类型有效受付的候选产品去重数，同一产品多次受付只计一台。前回実績按小番号实际建立时间选择最近一次有效受付，显示该条所属大番号受付日期与已选择类型，不展示次数；最新受付未选择类型时仍显示该次受付，不回退更早记录或编造类型。客户详情及无当前关系详情使用同一口径。仅生产质检、仅扫描识别、空批次不算，回收／报废动作本身也不代替受付。抽屉筛选及分页不改变实绩汇总。

补充边界：同一产品先点检后维修，只展示最近的维修受付，统计期间两条均存在也只计一台；最新一条在统计期间外但另有有效受付在期间内时，卡片仍计一台，前回実績仍展示最近一条。单条选择点检及维修时显示全部类型，例如「2026/10/11 点検・修理」，统计仍只计一台；报废类型仅为受付类型，未正式确认报废时不使候选退出。修改／清空类型不改变该产品的统计资格。9月1日建立的旧批次在10月追加产品，实绩日期仍为9月1日，不改用追加日期或作业完成日期；合法删除受付后按剩余有效事实重新计算，作业撤销完成／重新完成不改变受付实绩。验证日本日期7月1日／9月30日纳入，6月30日／10月1日排除。本用例为待实施验证要求，不表示已运行通过。

### VAL-40 納品先与产品范围（spec 7.6）

勾选同一下单方、多个納品先的产品，核对只读顾客，选择一个納品先再生成。

预期：顾客不可修改，選中产品不因納品先抬头变化而改变；产品当前订单、客户和納品先不被改写。无有效下单方或下单方已改变时阻止生成，提示返回重新查询。不同下单方应分别进入各自分组创建。

### VAL-41 生成失败与重试（spec 7.6）

生成过程中失败后重试，并重复点击作成。

预期：保留输入与勾选，提示失败，不显示虚假成功；同次操作不意外生成重复案内，明确再次创建才生成另一份。

## 6. 回归检查清单

- 是否把一份案内改成可修改、可覆盖、可作废或可恢复？
- 是否出现修正版、版本历史、当前有效版、有效状态或作废状态？
- 是否把定期点検案内和 5年目廃棄案内混入同一份正式文件？
- 是否在月度页或抽屉加入 M番号筛选、商品名筛选或直近実績筛选？
- 是否在月度页或列表页重新加入类型页签？
- 是否重新出现「案内作成状況」列、「初回案内」列、「未受付」统计项或页头「通知を表示」按钮？
- 是否把案内あり解释为当前有效、最终正确、已完成或已发送？
- 是否误用产品任意历史受付解除全部案内的超期？是否将一次受付同时计入多份案内，或用新案内覆盖旧案内的超期？是否把固定 30 天误算为一个自然月？
- 是否在正式 PDF 以外的位置显示「貴社」，尤其是详情页対象製品表？
- 是否因保存備考而改变正式 PDF、対象製品或案内番号？是否在创建确认弹窗重新出现寄送地址／联系人填写入口或追記事項字段？正式 PDF 是否出现追記事項区域？
- 是否新增跳过原因、永久排除、草稿、审批、发送状态、已读状态、未读状态或追加日志？
- 是否在多份案内之间判断哪份正确、当前有效或已被替代？
- 是否重新引入产品主档作废状态？是否让已报废产品重新出现在案内候选或计入台数？是否漏掉已回收未再派发产品的「已回收」标识？

## 8. Definition of Done

- 年度日历、月度通知需求页、通知创建抽屉、创建确认弹窗、通知管理列表和通知详情的字段、按钮、文案与 spec.md 一致。
- 生命周期候选口径通过验收：首次出货月、第 1～4 年目定期点検、第 5 年目 5年目廃棄、仅基准月份产生候选、已报废及无基准月产品不进入候选。
- 案内创建闭环通过：候选筛选、勾选、确认、生成案内番号、正式 PDF、案内履歴刷新、列表查询和详情查看均符合 spec.md。
- 案内事实边界通过：已生成案内不修改、不覆盖、不作废；纠正只生成新案内番号；无版本、无有效状态、无作废状态。
- 受付口径通过：按受付发生时最新已发行案内匹配，受付日期不早于发行日；按发行日加 30 天判断超期，旧案内可以持续超期，列表和详情一致。覆盖 VAL-35A、VAL-35B；当前实现差距不视为验收通过。
- 生成内容保留规则通过：客户、地址、联系人、产品资料后续变化不改写旧案内，正式 PDF 使用生成时保存内容。
- 「貴社」规则通过：仅正式 PDF 中按納品先与顾客关系显示，详情页対象製品表显示完整公司名称。
- 内部備考通过：保存只覆盖当前内部備考，不改变报告冻结内容、対象製品、案内番号或其他历史数据。
- 明确不做项无回归：无草稿、审批、发送状态、已读状态、跳过原因、永久排除、追加日志、案内作成状況、初回案内、未受付统计项或页头通知表示入口。
