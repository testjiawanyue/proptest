# FEAT-07 质检工作台 Validation

> 本文件是质检模块的完整业务验收标准。依据 spec.md 与业务理解编写，覆盖 demo 已实施与未实施部分；demo 未实施部分在 spec 对应章节已标注「目标稿（待转正）」。

## 1. 质检工作台

### VAL-01 默认查询待质检产品（最多100件）

打开质检工作台，不执行任何筛选。

预期：待检总数不超过100件时右侧清单完整显示当前待质检产品（满足最低构成且未通过）；清单标题显示「待质检清单（N 件）」；已质检通过或仍缺部件的产品不在清单中。

### VAL-02 范围筛选

在筛选区选择「連続入力」，前缀 PTG26，开始 001，结束 005，点击【筛选】。

预期：右侧清单只显示製造番号 PTG26001～PTG26005 范围内的待质检产品；清单标题显示「筛选结果（N 件）」；范围外或已质检通过的产品不显示。

### VAL-03 单件筛选命中

在筛选区选择「番号入力」，输入完整製造番号（如 PTG26003），回车。

预期：右侧清单只显示该件（若满足质检条件且未通过）；清单标题显示「筛选结果（1 件）」。

### VAL-04 单件筛选未命中

输入不存在的製造番号（如 PTG99999），回车。

预期：提示「未找到该製造番号」；右侧清单不变化。

### VAL-05 单件筛选不满足最低构成

输入一个已建立但缺少气囊／传感器／或充气发生器位置 1（无论位置 2 是否安装）的製造番号，回车。发生器位置 1 有安装即满足构成；仅位置 2 有安装、位置 1 空缺时不满足构成。

预期：提示「不满足质检最低构成，无法登记」；右侧清单不显示该产品。

### VAL-06 单件筛选已质检通过

输入一个已质检通过的製造番号，回车。

预期：提示「已质检通过」；右侧清单不显示该产品。

### VAL-07 重置筛选

执行范围或单件筛选后，点击筛选卡标题行右侧「重置筛选」。

预期：清空筛选条件，按100件上限重新查询默认清单，超限拒绝且保留原清单和选择。

### VAL-08 勾选与确认质检通过

在清单中勾选 2 台待质检产品，点击底部「确认质检通过（2 台）」。

预期：弹出最终确认框，列出 2 台製造番号，提示「确认后产品将标记为质检通过，无法撤回」；点击「确认质检通过」后，服务端重新校验最低构成，并为每台产品在同一事务中把主档“首次生产质检已通过”标记置为通过、保存只含产品／确认人／确认时间的质检通过事实并记录对应历史事件，不保存确认时五个槽位、资料、固件或显示快照；任一步失败时该台三项均回滚，其他产品不受影响；2 台产品从待质检清单消失；产品列表中该 2 台生产阶段变为「已完成质检」；底部提示「成功 2 台，失败 0 台」。

### VAL-09 确认质检取消

勾选 1 台产品，点击「确认质检通过」，在确认框中点击「取消」。

预期：确认框关闭，清单与勾选状态不变，不产生质检事实。

### VAL-10 确认质检部分失败

勾选多台产品，其中一台在确认前被其他操作移除部件导致不满足构成（或通过测试构造失败场景），执行确认。

预期：成功的产品建立质检事实并消失；失败的产品保留在清单中，状态列显示红色失败原因；底部提示「成功 N 台，失败 M 台」。

### VAL-11 筛选与勾选联动

先范围筛选出 3 台，勾选其中 2 台；再执行单件筛选定位另一台。

预期：更换前确认取消旧勾选；取消不改变清单。确认后仅在单件查询成功时替换并清空旧勾选，不保留隐藏选择；超限或请求失败保留原清单与勾选。

## 2. 跨页面闭环

### VAL-16 自适应左右工作台（人工验收新增，待验证）

高/矮桌面视口及窄屏核对左筛选右清单、标题及底部操作可达，表格内部滚动、不可撤回说明清晰；不分页。结合VAL-07～11/14回归筛选重置、勾选、更换清单失败/超限保留及部分成功只移除选中成功项。旧上下布局的视觉证据不代表本次调整通过。

### VAL-12 衣体入库 → 组装 → 质检 → 产品列表

衣体入库建立新产品 → 在部件组装页录入气囊、传感器、发生器位置 1 → 打开质检工作台 → 勾选确认质检通过 → 打开产品列表。

预期：新产品主档的“首次生产质检已通过”初始为未通过，质检工作台清单中出现该产品；确认后标记为通过，产品列表中生产阶段为「已完成质检」，首次质检通过日显示质检事实的日期；产品详情中可见原质检事实。之后拆件、更换、返厂、维修或报废不自动撤销该标记，也不使生产阶段倒退。

### VAL-12a 标记、质检事实和事件原子一致

分别令产品标记更新、质检事实写入或质检事件写入失败，并执行包含多台产品的批量确认；另对同一产品并发或重复确认。

预期：单台产品的标记、质检事实和事件只能共同成功或共同回滚，不出现任意两项不一致；失败产品保持未通过，批量中的其他产品可独立成功；重复或并发确认不产生第二条质检事实或重复事件。资格、待检候选、生产阶段和统计直接读取产品标记；确认人、确认时间和首次质检通过日仍读取原质检事实。

### VAL-12b 历史认定与正常质检边界

适用范围：本条真实业务历史认定及未来 FEAT-20 断言保留。本次01A结构同步不执行历史分类回填样例；目标库须确认无产品，开发测试样例不作为生产历史认定清单。未执行的历史断言不能标记为通过，具体环境初始化及验收范围在本次Change另记。

准备已有真实质检、经 FEAT-20 批准建立的历史质检认定、正常在制／待检、无完整质检记录但有交付或事件矛盾、以及已删除／报废的产品。

预期：已有有效完整、可关联原产品身份的真实质检原样保留并认定通过；即使缺对应质检通过履历事件，也只列履历差异，不降级、不要求逐项批准、不补造事件。批准的历史认定按 FEAT-20 同时建立产品资格且业务日期与登记审计分离；有可靠正常来源且可确认未通过的在制／待检保持未通过，新产品默认未通过不能替代旧数据调查；仅有订单、出货、当前构成完整或日期值不能自动认定。无依据、事实不完整或矛盾对象列入核实，不静默设为通过或未通过；未判定对象未解决时不开放依赖新资格标记的业务版本。已删除／报废对象仍按原身份核对首次事实，不因当前状态自动撤销或补造，同号重建身份分开。

### VAL-13 质检通过不可撤回

对已质检通过的产品，在产品详情、产品列表、质检工作台寻找撤回或取消质检入口。

预期：系统不提供任何撤回质检的入口；质检通过事实保留在产品档案中。

## 3. 回归检查清单

- 是否存在「质检不通过」或「返工登记」的入口？（不应存在）
- 是否存在「打印编号清单」按钮？（不应存在）
- 不满足最低构成的产品是否出现在待质检清单中？（不应出现）
- 已质检通过的产品是否仍出现在待质检清单中？（不应出现）
- 发生器位置 2 为空但位置 1 已安装的产品，是否被正确视为满足最低构成？
- 筛选条件是否影响质检事实本身？（不应影响，只影响清单显示）

## 4. Definition of Done

- 质检工作台默认查询待质检产品，不超过100件完整展示，超限提示筛选且不截断；
- 范围筛选与单件筛选行为符合 spec 4.5；
- 确认质检通过有最终确认框，逐台建立事实，失败行保留并显示原因；
- 质检通过事实包含确认人、确认时间；
- 产品主档持久保存明确的首次生产质检通过标记；正常新产品默认未通过，正常确认时与质检事实、历史事件逐台原子提交；
- 资格、生产阶段、待检候选和首页统计不再以质检记录是否存在代替产品标记；质检记录仍用于确认人、确认时间、首次通过日、删除阻断和历史追溯；
- 质检通过事实不包含确认时部件构成、资料或固件快照；
- 质检通过后产品生产阶段变为「已完成质检」；
- 系统不提供质检撤回入口；
- 无「打印编号清单」功能；
- 与 FEAT-05～08、FEAT-08 产品管理的生产阶段口径一致。

## 2026-09-28 评审整改补充验收（待实施、待验证）

### VAL-14 百件上限与请求锁定

首次进入分别有0、100、101件待检；执行超限范围和重置；已有勾选后更换清单并选择确认/取消；延迟查询和批量确认。

预期：100件完整显示，101件首次进入提示缩小范围且清单为空；后续超限/失败保留原清单和选择，成功替换才清空旧选择。请求中禁止筛选、勾选、重置及重复提交；批量只移除已选成功项，失败与未选项保留、不补入其他产品。

### VAL-15 空前缀范围不丢失

准备001、002、003、999、A001及不同位数编号；以空前缀和001～003查询，另测有前缀、半填、非数字、位数不等及倒序。

预期：空前缀仅命中001～003，不包含999、A001或不同位数编号；非法范围明确拒绝，不变成无范围查询。产品列表count与分页结果一致；组装/质检仍执行100件上限。

本轮DoD包含以上补充场景；历史通过记录不能代表本次规则已验证。
