## 1. 已结束出租必须填写实际回收日

已结束租赁必须确认已实际回收并填写YYYY-MM-DD；无法确定日期或回收事实则暂不补录。不提供日期未知选项，不用登记日、出货日或下一次出租日填补。仍在出租不填写实际回收日，服务端拒绝该状态携带回收日。

实际回收日不得早于本单出货日，出货日和回收日均不得晚于日本业务当天；同日允许，不采集时分秒。不检查跨订单历史期间重叠。

已结束关系不占用当前产品、保留有效交付，不新建正常受付/作业回收事实，不修改当前订单、部件和状态。实际回收DATE与系统登记时间独立：现有ended_time用于系统结束登记，不冒充历史实际回收日；历史履历分别展示业务日期和登记时间。生命周期需识别历史结束来源，有当前关系时不得被旧回收记录覆盖。字段及消费者适配仍待实施验证，不执行DDL。

## 2. 基准变更与通知

源码和正式需求核对：FEAT-12 §产品勾选允许已被案内包含产品再次通知；FEAT-13正式文件纠正通过新案内编号，旧案内保留。PropNoticeService.create仅按requestId防重复提交，qualify核对当前资格，不设每产品每周期只能生成一次的业务限制。PropNoticeMapper.history按对象月/类型/客户查询；PropLifecycleMapper latestNotice按产品/类型取历史最新，不限定当前基准或对象月。

保留现有机制：基准前移后新候选按新基准计算，已存在案内不阻止人工生成新案内；同一请求重试仍返回原次结果。补录不自动生成/发送，不自动重做旧月份案内；已生成案内、PDF及受付匹配保持原冻结事实。旧案内不代表新基准下已经通知或已经完成点检。历史最新案内仍作为参考，不能标成新周期已完成；变更确认提示已有案内可能采用旧基准。旧案内跟踪、超期状态按原规则保留，不新增替代/作废平台。

基准变化可能改变周年、对象月及点检/报废案内类型，甚至使产品不再落入普通候选区间；须按当前生命周期公式核对，不承诺自动补发所有漏期。基准变化不自动报废产品。

## 3. 历史质检日期的含义

真实质检日期来自真实质检事实，永不因后来补录更早订单而改写。历史补录认定日期是按照当时提供的真实首次出货日采用的日期，不等于已证实当日进行了原厂质检；应明确标为“历史合格认定依据日”，保留原首次依据和登记审计。

例：先按2020-08-10出货建立历史合格认定，后补2019-10-15真实更早交付。产品首次日/月/来源经明确确认改为2019-10-15及2019-10，原认定记录仍保留2020-08-10并显示其为当时采用依据；首次生产质检资格仍1，不新建第二次质检、不改原确认人/时间、不假造2019年的实际质检。履历记录前后首次日期、依据、操作人和登记时间。

据此修订旧“历史认定日始终等于当前首次日”的理解：只要求创建认定时采用当时确认首次日，不要求未来始终相等。日期差异本身不算资格字段与事实矛盾。已有真实事实与更早出货明显矛盾时提示人工核对，不以最早日期算法消除矛盾或强行认定通过。尚无质检事实/标记异常沿01A和正式历史认定规则处理。
