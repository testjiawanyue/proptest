## 1. 共通采用规则

- 归属一个已存在的包裹，仅包含该包裹产品；所属大番号作为关联信息，不把全大番号产品加入本份记录表。唯一生成入口在受付履歴页面对应包裹区域，工作台不生成；暂不提供记录表历史查看。每次明确生成取当前已保存事实并新增版本，系统内部版本按包裹分别保存，不覆盖旧版。只保留大番号、公司、地址、联系人、包裹照片及下表仍有效的产品字段；保留本包裹需清洗、需展开维修两项台数汇总，按BR22采用。下表有效字段全部自动带出、只读，不提供本次覆盖；受付内容需要更正时先修改源资料。原字段编号保留，标为撤回的行不再参与输出或新增版本的采用。
- 来源为生成时已保存的对应事实；BR18只用小番号成立时起始事实，BR17只用本次成立之前的历史，不用当前值冒充历史。
- 缺失留空，不补其他来源、不阻断生成；清洗／展开维修未登记留空，不自动视为無。冻结有效采用值及空值、日期、历史三项内容和包裹照片内容，后续修改及原包裹照片删除不改旧版；不回写业务、不锁定受付。NG图片、大番号／产品照片及其他撤回字段不因冻结要求而重新加入PDF。
- 点击生成后直接采用已保存资料生成并打开预览，不先弹出字段修改／补充或发行日选择窗口。发行日取生成当天，不要求员工填写、选择或清空；预览字段只读。版本历史、生成时间、查看元信息及大番号合法删除时同步清理规则保持，不增设文件技术存储规则。
- 业务版本、发行日、生成时间、模板版本均仅保留在系统预览／内部版本记录中，不进入PDF或纸面。使用系统实际已有的包裹标识，展示名称为「包裹号」；不新设包裹业务编号或自定义名称，虚构示例不作为真实编号规则或需求缺陷。
- 公司名称、地址、联系人及清洗／展开维修两项台数汇总，仅在首次对应区域展示，后续产品续页不重复；续页保留已确认的识别信息。该裁决只明确重复策略，来源、空值、只读及冻结规则不变，全部有效内容仍完整输出；逐台清洗／展开维修需求不撤回，替代此前相应待定状态。
- 同一产品字段仅保留有效的一份内容，去掉一览、详情「本次受付要点」及标题间的重复，仍保留用于对应产品的必要编号。BR11～21、BR26～27各项内容继续完整展示，不因去重减少字段、截断备注或限制历史条数。业务版本及发行日不在纸面出现；大番号、包裹标识不无必要地重复，包裹照片下的重复归属说明删除；不据此裁定分页版式。
- 不在纸面输出取值来源、编号组成／补零及只读／冻结／业务边界等规则长说明；业务规则及系统必要提示保持。缺失留空，不自动填「留空。」「未登记」或「本次为首次受付」等解释，不以無／正常／已完成代替空值，不删改源备注中原有文字。
