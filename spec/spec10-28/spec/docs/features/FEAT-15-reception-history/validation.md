## 1. 受付履歴

### VAL-24 受付履歴筛选结构

操作：进入受付履歴，核对标题、右上按钮、关键词搜索、客户地址搜索、查询、重置和日期快捷页签。

预期：标题为「受付履歴」；右上显示「回到受付工作台」；关键词框内提示文字为「大番号 / 小番号 / 製造番号 / 客户」；客户地址框内提示文字为「客户地址（模糊搜索）」；日期页签包含全部、今天、昨天、近 7 天、本月、指定期间，默认选中全部。

### VAL-25 关键词搜索命中大番号与产品

操作：分别输入大番号、客户名、小番号、製造番号查询。

预期：大番号和客户名命中大番号本体；小番号和製造番号命中产品；产品命中时显示「产品编号命中 N 台，已自动展开对应大番号」，并自动展开、定位和高亮产品行。

### VAL-26 客户地址与日期筛选

操作：输入邮编或地址片段查询；选择今天、昨天、近 7 天、本月；选择指定期间时设置不完整起止日期、结束早于开始、合法期间。

预期：输入 7 位数字（可带连字符）时按大番号来件元信息的邮编严格匹配，其余输入按地址部分匹配；快捷日期按所选范围过滤；指定期间必须起止完整且结束不早于开始，合法后随查询生效。

### VAL-27 重置和客户详情入口

操作：设置多个筛选条件后点击重置；从客户详情关联业务快捷链接进入受付履歴。

预期：重置清空全部条件且日期页签回到全部；客户详情入口带关键词进入并立即生效。

### VAL-28 主表列与分页

操作：查询多条大番号，核对列、排序、分页和空值。

预期：主表按受付日時倒序，每页 10 条并显示总数；列为大番号、顧客、受付日時、来件元、件数、確認、操作；无客户显示「未确认客户」；確認无内容显示「—」。

### VAL-29 展开区与产品子表

操作：点击大番号行展开，核对包裹分组和产品子表；准备有未入力和需要确认的产品。

预期：展开区按包裹序号升序；包裹头显示 Package N、製品 N台、未入力 N台、⚑ 要確認 N台、Package詳細及本包裹的记录表生成入口，暂不提供记录表历史查看；产品子表按小番号升序，显示小番号连写形态、製造番号、受付内容和確認・未入力；缺失项逐项以橙色标签显示，包裹和大番号层只显示未入力台数。

### VAL-30 大番号詳細与Package詳細抽屉

操作：点击「受付詳細」和「Package詳細」。

预期：大番号詳細只展示本次来件公司/客户、受付日時、来件地址、联系人、电话、大番号备注和大番号图片；Package詳細只展示所属大番号、Package、产品数、Package备注和Package图片。

### VAL-31 批次记录表不依赖完成按钮

操作：对未点击完成按钮的大番号中的包裹生成记录表；另点击完成按钮返回后对同一包裹再生成。

预期：两者均可按当前已保存事实生成，不提示先完成受理，不读取或生成受付完成状态／时间；历史版本仍按既有规则保留。

### VAL-32 生成批次记录表正路径

操作：在受付履歴页面（/reception-history）已有大番号下的指定包裹区域点击「生成批次记录表」。

预期：按当前已保存事实新增一份版本化批次记录表并直接打开预览，不出现字段修改／补充或发行日选择弹窗，不要求再次确认字段。发行日取生成当天；系统保留「按当前事实生成新版本」提示及生成时间、模板版本等元信息，业务版本、发行日、生成时间及模板版本均不进入PDF／纸面，系统预览查看本次元信息，内部版本记录继续保存旧版元信息。业务字段按spec §4.8及字段对照核对且只读，只包含所选包裹及其产品并展示所属大番号信息，使用系统实际已有包裹标识，不新设包裹业务编号或名称。该包裹内单台显示完整受付编号；不再把本用例旧字段简述当作全部内容。查看折叠结构不规定文件版式。

### VAL-33 内部版本保留与暂不开放历史查看（2026-10-22替代）

操作：从受付履歴对同一大番号下包裹A、B分别生成，并在源资料保存更改后对A再次明确生成；核对页面及后续获授权的内部版本证据。

预期：仅受付履歴提供生成，工作台不提供生成；页面暂不提供记录表历史按钮、列表或历史预览选择。A内部保存自身v1／v2，B保存自身v1，不混入彼此版本、不覆盖旧版；A再次生成采用当前事实并预览新版本，旧版冻结内容保持。成功UUID重放／PDF读取重试不得额外增版。原历史弹窗与版本选择的验收要求由此条替代，不表示本轮已执行验证。

### VAL-34 大番号删除反路径

操作：对仍有小番号的大番号，在操作列「···」下拉中点击「削除」。

预期：提示「大番号下仍存在受付产品（小番号），请先删除全部小番号」；大番号、包裹和批次记录表均不删除。

### VAL-35 大番号删除正路径

操作：准备无正式点检／回收／报废报告的大番号，删除其全部小番号后确认删除；可保留批次记录表作为对照。

预期：大番号及其全部空包裹、图片、备注一并删除；其批次记录表同步删除；小番号计数不回退、不复用。

## 3. 回归检查清单

- 是否出现选择类字段点击后未保存、或必须点底部「保存并扫描下一台」才保存字段的情况？
- 是否出现未点击「受付を開始」就建立单台受付的情况？
- 是否出现同一实际来件打开旧受付记录而不是取得新小番号的情况？
- 是否出现小番号按包裹重置、删除后复用或删除大番号后回退计数的情况？
- 是否出现删除包裹后其他包裹序号被重排的情况？
- 是否仍生成受付完成时间／状态，或把完成按钮当成下游放行门槛？
- 是否把产品处理计划当成实际回收或报废事实？
- 是否让大番号来件信息回写客户或订单主数据，或被主数据后续变化覆盖？
- 是否允许员工手工增删 ⚑ 旗标？
- 是否在包裹或大番号层显示字段缺失总数，而不是未入力台数？
- 是否恢复了已明确不做的结束本包裹、小番号作废、独立来件管理、左卡次回予定、受付记录关联通知、受付履歴产品行详情入口或产品处理计划「未决定」？
- 是否允许批次记录表阻断删除大番号，或删除大番号时遗漏清理批次记录表？
- 是否允许 NG 保存多张照片？

## 4. Definition of Done

- 受付工作台初始页、前置流程、工作台、工作台弹窗和受付履歴均符合 spec.md。
- 新建受付、多台多包裹登记、保存校验、完成本批次受理、履歴查询、批次记录表和三层删除均有验收记录。
- 编号规则、未入力规则、⚑旗标、年度口径、受付类型与处理计划联动均通过正反路径验证。
- 来件信息和处理计划的业务边界未被扩大，完成按钮不产生完成时间或状态。
- 删除行为符合三层删除条件和后果，且不会复用小番号或重排包裹序号。
- 批次记录表按包裹独立版本保存生成时的采用事实，内容按最新精简范围，内部旧版内容不被当前资料改写，页面暂不提供历史查看。
- 明确不做项没有在页面、数据变化或验收用例中复活。

### VAL-BR-02 编号、每台名称及本次类型／年目（BR11～14）

预期：每台采用自己的当前对外名称，不统一取首台。完整受付管理No.为大番号-小番号，至少4位补零、超长完整显示；製造No.取对应产品的製造番号，不补其他编号。本次受付类型及年目读本次保存内容，缺失不推算或补登记；全部只读并冻结，缺失留空不阻断。大番号原受付日不再作为本文件字段输出，不以小番号建立日或生成日另补；不改变源日期或原查看界面元信息。

### VAL-BR-03 包裹照片、NG文字与备注层级（BR10、BR19～20）

操作：分别保存包裹备注／照片、单台NG文字／照片、单台多条受付备注（有录入人和日期），并使大番号备注、作业备注内容不同。

预期：只输出当前包裹已保存照片，包裹备注及原預かり品组合栏不输出，不设独立随附物品输入。异常・NG仅输出本次单台受付NG文字，NG图片、NG录入人及NG日期不进入PDF且不留图片占位，原受付NG资料不删除或改变；只有图片而无文字时文字处留空，不默认OK／きれい，不解释成完整外观检查。单台備考完整展示全部本次受付备注正文，不输出录入人、日期，不混入其他层级备注；源受付备注及其元信息仍保留。无记录留空不阻断，不填「留空。」等解释文字。

### VAL-BR-04 逐台清洗、展开维修需求及两项台数（BR15～16、BR22）

操作：在同一包裹分别登记清洗、展开维修、其他作业和未登记作业的产品，并使实际作业完成情况与受付选择不同。

预期：两项目独立按受付本次作业判断：选中为有，已登记其他作业但未选该项为無，未登记作业留空，不自动输出「未登记」解释文字。逐台展示，并分别汇总本包裹对应需求为有的需清洗、需展开维修台数，仅两项需求台数，不统计其他包裹或输出其他分类汇总；未登记不计为無；只表示需求，自动只读并冻结，不读取完成结果替代，不新增等待清洗状态。

### VAL-BR-05 历史与起始固件（BR17～18）

操作：产品在本次受付成立前后均有其他受付，历史记录中同时有日期、类型、年目及作业明细、维修／换件过程、备注和照片；当前固件已升级，与本次成立时保存版本不同；另有旧记录未保存起始固件。

预期：検／修履歴仅展示本次成立前的历史受付日期、类型及已登记年目，不加入成立之后的受付，不展示历史作业明细、维修／换件过程、备注或照片，不将年目说成实际作业完成；不新增历史条数、排序或截取规则。无可展示历史时留空，不自动写「本次为首次受付」。传感器版本读取本次成立时起始事实，旧记录缺失留空不阻断，不补当前版本、不新增补录入口；采用内容只读并冻结。

### VAL-BR-06 临时装箱箱数（BR21）

操作：各台受付保存不同临时装箱箱数，并有暂缺箱数的情况。
