# 核心硬性规则（必须严格遵守，违反则重写）
1. 用例拆分粒度：**一个用例只能对应一个测试点，严禁将多个不同业务场景合并到同一个用例**。每个用例只验证单一目标。
2. 用例字段固定，严格使用下面Markdown模板，不允许增减字段；【测试结果】字段为执行阶段使用，**用例设计阶段必须留空，禁止填写任何Pass/Fail内容**。
3. 预期结果必须独立成块，每一条测试步骤，对应一条明确的预期结果；禁止把预期结果写在测试步骤行内。
4. 用例编号规则：`<功能点名称>-<三位自增序号>`，序号从001开始，例如：字典新增-001；同一功能点下序号连续。
5. 业务逻辑必须来自提供的文档/原型/源码，**禁止自行脑补不存在的业务规则**；文档信息不足的地方，在【备注】中标注【待确认，需核对产品/后端】。

# 4类测试覆盖策略定义，生成用例时按4个维度完整覆盖场景
## 1. 正常流程（正向场景）
基于不同前置存量数据环境，覆盖主流业务正向路径，完整覆盖业务状态流转；验证功能在合法输入、正确权限下可正常完成业务动作。
## 2. 边界值输入测试
验证字段输入临界场景：字段最小长度、最大长度、刚好超限、空集合、最大多选数量、最少选择数量、数值上下限等临界条件。
## 3. 异常输入测试
非法输入场景：未登录访问页面、角色无权限访问、空输入、非法格式输入、数据库唯一键重复值、非法关联ID、不符合业务约束的参数。
## 4. 错误猜测测试（风险类场景）
重点覆盖：越权访问、页面缓存未刷新、级联删除误删关联数据、并发操作数据覆盖、历史存量旧数据兼容、筛选条件误匹配、事务异常、前端提示文案错误。

# 优先级判定标准
- 高：主流程、核心业务、权限越权、存在数据损坏风险，对应P0/P1场景
- 中：次要业务流程、边界输入、普通报错分支
- 低：UI展示细节、极少触发的边缘场景
