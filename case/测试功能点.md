> 数据来源：PROJECT、ROADMAP、capability-map、整体业务流程说明、领域模型、FEAT-02 spec/validation。
> 编写原则：只写原文已定义内容；原文没有的页面字段 / 枚举一律写"待确认"，不推测。
> 场景标识：【正常】=按标准操作可直接成功的场景；【联动】=由上游数据变化、状态派生、跨模块读写触发的场景。

## 阅读说明（每个测试点包含的 5 项信息）

1. 所属模块与能力：模块名 + 该测试点用到的能力（新增 / 删除 / 修改 / 查询 / 数据创建 / 页面渲染展示 / 数据联动）。

5. 页面展示明细：弹窗 / 列表 / 详情页展示的字段。

# 三、FEAT-02 产品生产

> 模块范围：从衣体完成入库到首次生产质检通过。首次质检通过前归本模块。

## TP-02-01 衣体入库 — 单个编号
- 所属模块与能力：FEAT-02 产品生产；数据创建 / 页面渲染展示。
- 功能操作描述：把现场已经完成物理编号的衣体登记进系统。选择有效的衣体资料，输入一个完整编号，点击加入后进右侧待确认清单，点击确认全部入库才正式建档。预期：建立一个衣体部件个体，保存资料版本、建档人、建档时间；不建立产品、不建立安装关系、不建立质检事实；成功后成为三个组装工作台的候选。【正常】
- 数据溯源：衣体资料（名称、厂商、当前版本、颜色、编号前缀）来自基础设置部件资料；颜色来自衣体资料版本，不从衣体编号反推。
- 数据枚举清单：建档来源 = 衣体入库；部件类型 = 衣体；状态 = 待确认 / 成功 / 失败。
- 页面展示明细（衣体入库工作台，路径：产品生产 → 衣体入库）：左侧展示部件资料名称、厂商、当前资料版本、颜色、摘要参数、其他要求、编号前缀；右侧待确认清单至少显示选择框、制造番号、颜色、规格摘要、状态；按钮含单个编号、连续范围、加入、删除选中、清空本次录入、确认全部入库。

## TP-02-02 衣体入库 — 连续范围
- 所属模块与能力：FEAT-02；数据创建。
- 功能操作描述：用编号前缀 + 开始号 + 结束号一次生成连续编号集合。预期：前缀由所选衣体资料带出；系统不自行猜测年份、补零位数或流水规则；正式确认前不产生正式衣体个体。【正常】
- 数据溯源：前缀来自所选衣体资料；编号集合仅在确认后建档。
- 数据枚举清单：录入方式 = 单个编号 / 连续范围。
- 页面展示明细：编号前缀、开始、结束字段；生成结果进入右侧清单。

## TP-02-03 衣体入库 — 重复 / 已有编号校验
- 所属模块与能力：FEAT-02；查询校验 / 页面渲染展示。
- 功能操作描述：录入与本清单重复、或系统已有档案的编号。预期：页面内重复不重复加入并提示"该编号已在本次列表中"；系统已有编号行标红提示"已有档案"，正式确认时不重复建档；连续范围不合法时阻止加入。【联动：与已存档案实时比对】
- 数据溯源：比对数据来自已建档衣体个体及本次清单。
- 数据枚举清单：错误类型 = 页面重复 / 已有档案 / 范围不合法。
- 页面展示明细：失败行标红并显示原因。

## TP-02-04 衣体入库 — 确认全部入库与部分成功
- 所属模块与能力：FEAT-02；数据创建。
- 功能操作描述：点击确认全部入库正式建档。预期：返回成功 N 件、失败 M 件；成功项从清单移除，失败项保留并显示原因；允许部分成功，不因少数失败回滚全部成功项。【正常】【联动】
- 数据溯源：确认后建立衣体部件个体；下游供组装工作台筛选。
- 数据枚举清单：处理结果 = 成功 / 失败。
- 页面展示明细：成功 / 失败计数；失败行及原因。

## TP-02-05 气囊组装 — 默认清单加载
- 所属模块与能力：FEAT-02；查询 / 页面渲染展示 / 数据联动。
- 功能操作描述：进入气囊组装工作台。预期：默认只加载已入库、未作废、当前尚未安装气囊的衣体，不要求传感器或发生器已完成。【联动：上游衣体入库 + 已装气囊状态共同决定清单】
- 数据溯源：候选来自衣体入库产生的衣体个体；过滤条件读取当前安装关系。
- 数据枚举清单：行状态 = 待录入 / 已录入 / 错误。
- 页面展示明细（路径：产品生产 → 气囊组装）：列含衣体番号、气囊番号、规格、状态；左侧范围筛选（连续范围 / 单件番号、筛选、重置）、本次作业设置（气囊资料、厂商、摘要、要求）；底部显示本页已录入 N/20、已自动保存。

## TP-02-06 气囊组装 — 范围筛选与清单快照
- 所属模块与能力：FEAT-02；查询 / 页面渲染展示。
- 功能操作描述：按连续范围或单件番号筛选。预期：范围内 20 件、8 件已完成时提示"筛选范围 20 件 · 待处理 12 件 · 已完成 8"，加载 12 件；清单快照稳定：已录入行原地保留标记完成，不动态删除、不自动补位，只有重新筛选 / 重置 / 刷新才重算。单件查询若已完成本工序则不进表格，只提示已完成。【正常】【联动】
- 数据溯源：筛选基于衣体编号范围和各衣体当前工序状态。
- 数据枚举清单：筛选方式 = 连续范围 / 单件番号。
- 页面展示明细：范围 / 待处理 / 已完成计数提示。

## TP-02-07 气囊组装 — 连续录入与提交
- 所属模块与能力：FEAT-02；数据创建 / 修改。
- 功能操作描述：员工只编辑气囊番号，按回车、Tab 或失焦即提交。预期：成功显示已录入；失败显示错误及原因；不存在保存本页或完成本批按钮；存在失败 / 待确认数据时，筛选、重置、翻页不能直接离开。【正常】【联动：三种动作触发自动保存】
- 数据溯源：气囊资料来自本次作业设置；新编号在保存时建档。
- 数据枚举清单：提交触发 = 回车 / Tab / 失焦；提交结果 = 成功 / 失败。
- 页面展示明细：成功标记、错误标记加原因。

## TP-02-08 气囊组装 — 冲突处理
- 所属模块与能力：FEAT-02；查询校验 / 数据创建 / 数据联动。
- 功能操作描述：录入不同状态的气囊编号。预期按情况处理：新编号→建立部件个体；已存在且空闲、资料一致→直接建立安装；已绑定当前产品、资料一致→不做处理；已绑定其他产品→红色错误禁止保存；停用 / 作废→红色错误；同编号资料不一致→黄色确认，确认后只追加资料更正、安装关系不变；当前快照内改编号→识别为更换，原子执行拆除旧件 + 安装新件，取消则恢复原编号。【联动：依部件当前绑定状态分支】
- 数据溯源：部件个体及其当前安装关系、部件资料版本。
- 数据枚举清单：冲突类型 = 新编号 / 空闲一致 / 已绑当前产品 / 已绑其他产品 / 停用作废 / 资料不一致 / 快照内换号。
- 页面展示明细：红色错误、黄色确认弹窗；更换需二次确认。

## TP-02-09 气囊组装 — 首次安装的数据结果
- 所属模块与能力：FEAT-02；数据创建 / 数据联动。
- 功能操作描述：正常完成首次安装。预期：必要时建立部件个体 → 必要时建立产品 → 建立产品—部件关系 → 记录安装操作；即产品在第一次真实组装成功时建立。【联动：产品首次生成节点】
- 数据溯源：衣体来自衣体入库；产品由本动作首次创建。
- 数据枚举清单：操作类型 = 安装（INSTALL）。
- 页面展示明细：在制品列表随后可查到该产品。

## TP-02-10 充气发生器组装
- 所属模块与能力：FEAT-02；数据创建 / 查询 / 页面渲染展示。
- 功能操作描述：连续录入发生器位置1（必需）、位置2（可选）。预期：完成后不自动跳质检，质检资格由当前组成自动派生；位置2可留空，留空不创建占位假记录；每个位置独立安装关系；当前位置已有其他发生器时识别为更换，不形成两个当前有效关系。【正常】【联动】
- 数据溯源：发生器资料来自基础设置；候选衣体同气囊工作台规则。
- 数据枚举清单：位置 = 位置1（必需）/ 位置2（可选）；制表位顺序 = 第1行位置1 → 第1行位置2 → 第2行位置1 → 第2行位置2（Z 字形跳格）。
- 页面展示明细（路径：产品生产 → 充气发生器组装）：衣体番号、发生器位置1、发生器位置2、规格、状态。

## TP-02-11 传感器组装
- 所属模块与能力：FEAT-02；数据创建 / 查询 / 数据联动 / 页面渲染展示。
- 功能操作描述：连续录入衣体、传感器编号、固件版本。预期：固件版本来自基础设置，现场不能新建；切换左侧固件版本后，已保存行保持保存时版本、未录入行使用新版本；空闲且版本相同直接建立安装；空闲但版本不同→追加传感器固件记录，不覆盖旧版本。【正常】【联动：固件版本切换、固件记录追加】
- 数据溯源：传感器资料、固件版本均来自基础设置。
- 数据枚举清单：录入要素 = 衣体 + 传感器编号 + 固件版本。
- 页面展示明细（路径：产品生产 → 传感器组装）：左侧范围筛选、传感器资料、固件版本；右侧衣体番号、传感器番号、固件、规格、状态。

## TP-02-12 在制品列表 — 列表渲染与状态派生
- 所属模块与能力：FEAT-02；查询 / 页面渲染展示 / 数据联动。

# 七、FEAT-06 受付工作台

> 受付识别和绑定的是产品，不是订单；结构为大番号 → 包裹 → 产品受付（小番号）。

## TP-06-01 大番号建立
- 所属模块与能力：FEAT-06；新增 / 页面渲染展示 / 数据联动。
- 功能操作描述：客户寄回一批来件时建立大番号，记录来源客户快照、收到日期。预期：同一来源的一批现实来件归同一大番号。【正常】【联动：客户信息取自客户管理并存快照】
- 数据溯源：客户资料来自客户管理。
- 数据枚举清单：—。
- 页面展示明细：大番号（业务识别番号）、客户快照、收到日期、备注。

## TP-06-02 来件包裹登记
- 所属模块与能力：FEAT-06；新增 / 查询。
- 功能操作描述：在大番号下逐件登记实际收到的物理包裹。预期：包裹只描述来件阶段，不作为返送装箱实体；返送出库不沿用包裹做装箱。【正常】
- 数据溯源：所属大番号来自 TP-06-01。
- 数据枚举清单：—。
- 页面展示明细：所属大番号、包裹序号 / 编号、实际收件时间、备注。

## TP-06-03 产品识别与产品受付（小番号）
- 所属模块与能力：FEAT-06；数据创建 / 数据联动。
- 功能操作描述：扫描或识别具体产品，建立本次返厂的产品受付（小番号）。预期：扫描本身只是识别动作，不是独立业务事实；同一台产品每次真实返厂都新建一条产品受付；不建立"当前受付编号""受付状态=处理中/关闭"等字段；登记来件原因、处理要求、备注、实际受付时间。【联动：识别产品 → 建立受付事实】
- 数据溯源：产品来自产品管理（按制造番号 / M 番号识别）；包裹来自 TP-06-02。
- 数据枚举清单：来件原因（具体枚举原文未列，待确认）。
- 页面展示明细：所属包裹、小番号、产品、来件原因、处理要求、备注、实际受付时间。

## TP-06-04 无通知临时来件受付
- 所属模块与能力：FEAT-06；数据创建 / 数据联动。
- 功能操作描述：对临时维修、未关联点检通知的来件直接建立受付。预期：同样可正常建立大番号 / 包裹 / 产品受付，不强制要求来源通知。【联动：无上游通知亦可成立】
- 数据溯源：产品识别即可，来源通知可为空。
- 数据枚举清单：来源 = 有通知 / 临时来件。
- 页面展示明细：同 TP-06-03。

## TP-06-05 正式 NG 登记
- 所属模块与能力：FEAT-06；新增 / 查询 / 数据联动。
- 功能操作描述：受付负责人对判断后确认的问题登记正式 NG。预期：正式 NG 只属于受付（事实所有者为产品受付）；作业可以读取 NG，但不得另建一套"作业 NG"；NG 选项来自基础设置。【正常】【联动：NG 选项读取基础设置，作业侧只读】
- 数据溯源：NG 选项来自 FEAT-08；归属产品受付来自 TP-06-03。
- 数据枚举清单：NG 项（具体条目待确认）。
- 页面展示明细：所属产品受付、NG 项、具体说明、证据图片、登记人、登记时间。

## TP-06-06 受付与作业边界
- 所属模块与能力：FEAT-06；边界校验 / 数据联动。
- 功能操作描述：核对"受付完成"是否等于"作业完成"。预期：受付只记录收到什么、需要做什么；作业记录实际做了什么，两者不能合并；产品受付自身不负责"完成"，整体完成属于大番号。【联动：作业进度不回写受付状态】
- 数据溯源：作业数据来自 FEAT-07。
- 数据枚举清单：—。
- 页面展示明细：受付页不展示作业完成结论（具体展示待确认）。

## TP-06-07 大番号处理完成
- 所属模块与能力：FEAT-06；数据创建 / 数据联动。
- 功能操作描述：整体事项（含返送 / 回收 / 报废）处理完毕后，由负责人确认大番号完成。预期：不保存简单"状态=关闭"，而是生成大番号完成事件；完成不表示整个大番号数据不可再更正。【联动：各最终处理完成后才确认】
- 数据溯源：依据返送 / 回收 / 报废结果（FEAT-07 / 出货领域）。
- 数据枚举清单：是否完成由"是否存在有效完成事件"派生。
- 页面展示明细：完成事件含所属大番号、完成人、完成时间。

# 八、FEAT-07 作业管理

> 对象是每次产品受付（返厂番号）；作业不是线上任务流。

## TP-07-01 专业作业记录
- 所属模块与能力：FEAT-07；数据创建 / 查询。
- 功能操作描述：各专业组针对一次产品受付记录实际完成的检查与处理。预期：每条作业必须明确属于哪一次返厂；一次产品受付可对应 0 到多条作业记录。【正常】【联动：上游必须有产品受付】
- 数据溯源：产品受付来自 FEAT-06；可读正式 NG 但不复制。
- 数据枚举清单：专业组 = 缝纫（SEWING）/ 传感器（SENSOR）/ 组装（ASSEMBLY）/ 展开维修（EXPANDED_REPAIR）/ 清洗（CLEANING）。
- 页面展示明细：所属产品受付、专业组、本组实际检查 / 处理结果、作业备注、实际操作人、作业时间。各组纸面检查项的详细字段待对应 Feature Spec 确认。

## TP-07-02 禁止任务流建模
- 所属模块与能力：FEAT-07；边界校验。
- 功能操作描述：核对是否存在任务分派、认领、任务状态、下一工作组等线上流程。预期：不建立任务（WorkTask）、分派（Assignment）、认领（Claim）及待办 / 已分派 / 进行中 / 暂停 / 关闭、下一工作组等状态；工作组在线下如何传递产品不由系统状态机控制。【联动：无状态机】
- 数据溯源：—。
- 数据枚举清单：—。
- 页面展示明细：无任务流页面元素。

## TP-07-03 正式产品部件更换 / 拆除作业
- 所属模块与能力：FEAT-07；数据创建 / 数据联动。
- 功能操作描述：返厂后由专业组对产品部件进行更换、拆除等处理。预期：正式产品的换件在本环节以实际作业形式记录；具体部件关系如何同步写入待确认（open-questions Q7）。【联动：基于产品受付发起】
- 数据溯源：受付来自 FEAT-06；部件资料来自 FEAT-08。
- 数据枚举清单：作业处置选项来自基础设置（具体值待确认）。
- 页面展示明细：作业结果、备注；明细字段待确认。

## TP-07-04 点检・修理报告生成
- 所属模块与能力：FEAT-07；数据创建 / 页面渲染展示 / 数据联动。
- 功能操作描述：针对一次产品受付，汇总产品、受付、NG、作业快照，发行正式点检・修理报告（PDF）。预期："F10"仅为历史内部技术代号，业务统一称点检・修理报告；不要求所有工作组都已登记、不要求大番号已完成、不要求返送已确认；报告可在业务过程中生成和修正。【正常】【联动：多源快照汇总】
- 数据溯源：产品快照来自产品管理，受付 / NG 快照来自 FEAT-06，作业快照来自作业记录。
- 数据枚举清单：—。
- 页面展示明细：报告业务编号、所属产品受付、正式版本号、产品快照、受付快照、NG 快照、作业快照、正式 PDF、发行人、发行时间。

## TP-07-05 报告版本修正
- 所属模块与能力：FEAT-07；数据创建 / 数据联动。
- 功能操作描述：报告内容需要修正时重新发行。预期：生成新版本号（版本号 + 1），不覆盖旧版本；历史版本永久保留。【联动：修正触发新版本】
- 数据溯源：基于原报告对应产品受付。
- 数据枚举清单：版本号 = v1 / v2 / v3……
- 页面展示明细：版本列表及各版本 PDF。

## TP-07-06 原产品最终处理（返送 / 回收 / 报废）
- 所属模块与能力：FEAT-07；数据创建 / 数据联动。
- 功能操作描述：受付负责人汇总结果后决定原产品的最终处理。预期：三种结果为返送、回收、报废，互斥地对应一次最终处理；系统只处理本次返厂的原产品，不建设替代品 / 替代品订单发货；选择返送时确认返送出库（出库产品明细来源 = RETURN）；返送出库不自动解除产品订单关系、不自动修改订单、不自动修改受付判断。【联动：不同结果触发不同确认节点】
- 数据溯源：返送写入出货领域；回收 / 报废确认结果作为大番号完成依据。
- 数据枚举清单：最终处理 = 返送 / 回收 / 报废；出库来源 = 返送（RETURN）。
- 页面展示明细：确认回收、确认报废、返送客户并确认返送出库；具体页面字段待确认。
