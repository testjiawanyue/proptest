# 2026-11-19

## JaCoCo 测试门禁方案调研（只做只读测量，未改任何 pom / 源码）

用 `mvn -pl <module> org.jacoco:jacoco-maven-plugin:0.8.16:prepare-agent test :report -Dmaven.test.failure.ignore=true`
临时挂载 agent，得到项目首个真实覆盖率基线（产物只在 gitignore 的 `target/` 下）：

| 模块 | 用例 | LINE | BRANCH | INSTRUCTION |
|---|---|---|---|---|
| ruoyi-prop | 1000 | 75.6% | 52.5% | 65.3% |
| ruoyi-admin | 90 | 19.3% | 7.7% | 26.4% |
| 其余 5 模块 | 0 | 0% | 0% | 0% |

关键事实：
- **当前单测不是全绿的**：ruoyi-prop 1000 用例中 9 failure + 139 error（集中在 PDF/模板校验和「テンプレートのチェックサムが一致しません」「テンプレート資源の整合性を確認できません」）；ruoyi-admin 90 用例中 4 failure + 2 error（临时文件权限）。与 `openspec/ROADMAP.md` 里「模板/PDF 未定版、C03 WP4 暂停」一致，也印证 `AGENTS.md` §测试现状「尚未建立稳定的一方自动测试基线」。
- 因此**现在不能直接开 JaCoCo 硬门禁**，否则 `verify` 在测试阶段就长期全红，对应 `测试架构能力评估_通用视角_v1.0.md` 的 S2 / P0-2「门禁渐进启用」。
- ruoyi-prop 存在 18 个「0% 但 0 可执行行」的 mapper 接口包 → check 规则必须用 `element=BUNDLE`，不能用 PACKAGE。
- LINE 75.6% 与 BRANCH 52.5% 差距大 → 建议以 BRANCH 为主指标（负向/失败路径），LINE 为辅。
- 环境：Maven 3.9.6 / JDK 21（pom target 17），Surefire 实际取 3.2.2（Maven 3.9 超级 POM 默认）；仓库无 jacoco/surefire 显式配置、无 CI 配置，远端 `cnb.cool`。
- 部署入口 `E:/proptest/update-prop.ps1` 用 `-DskipTests package`：package 不含 verify，且 skipTests 会让 jacoco.exec 缺失导致 check **静默跳过并 BUILD SUCCESS**，是门禁的隐蔽漏洞。

方案要点：三档开关 OFF / OBSERVE / ENFORCE（根 pom 的 `jacoco.skip` + `jacoco.check.skip` + profile `coverage` / `coverage-gate`）；阈值随 pom 版本管理，开关放脚本参数/CI 变量；check 只挂 ruoyi-prop 试点；阶段 0 只观察不改默认行为。
