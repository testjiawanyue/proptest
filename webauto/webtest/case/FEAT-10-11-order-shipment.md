# 订单管理（订单列表 / 运单生成）测试契约卡

> 依据：`spec10-28` 的 FEAT-10 订单、FEAT-19 送り状一括生成 + 2026-11-04 页面实测。
> 标记：`[Spec]` 来自需求；`[实测]` 来自当前 `http://localhost:8090`；`【待确认】` 表示 Spec 未明确或与页面不一致。

## 1. 页面与测试文件

| 页面 | 路由 | 页面对象 | 用例 |
|---|---|---|---|
| 订单列表 | `/orders/index` | `pages/order_list_page.py` | `tests/test_order_list_mainflow.py` |
| 订单创建 | `/orders/new` | `pages/order_form_page.py` | 由订单列表“＋ 注文を作成”进入 |
| 订单详情 | `/orders/{orderId}` | `pages/order_detail_page.py` | 由订单列表“詳細”或创建成功进入 |

## 2. 数据关联设计

1. `production_chain_data()` 生成唯一衣体编号，`ProductionFlow.prepare_inspected_products()` 完成入库、组装与质检。
2. `customer_data()` 通过 UI 新建唯一客户，客户自带一个地址和一个联系人。
3. 订单数量取 `len(production.eligible_products)`，不写死台数；订单商品名从页面启用商品中动态选择。
4. 订单创建后进入详情，寄送抽屉录入相应已质检制造番号，形成“生产 -> 订单 -> 寄送 -> 面单”的同一数据链。
5. 后续查询、反查与复核均复用该链路生成的订单号、寄送号、制造番号，不重新造号。

## 3. 订单列表主流程

1. 创建客户和订单，保存成功提示 `注文を作成した。`，跳转 `/orders/{orderId}` `[实测]`。
2. 进入寄送抽屉，逐台加入已质检产品并选择承运商，形成“准备中”寄送。
3. 订单列表按客户订单号查询，命中唯一订单；核对订单管理番号、客户、商品/颜色/数量、类型、日期与未出荷进度。
4. 按订单管理番号查询，仍命中同一订单。
5. 重置后按制造番号查询，准备中的寄送产品也能反查订单。
6. 从列表进入详情，订单编号一致，有效出荷数仍为 0。

## 4. 运单生成主流程

1. 批量页只列出“准备中”的订单寄送，默认承运商 `ヤマト運輸`。
2. 勾选目标寄送后，汇总显示 `選択 N 件｜製品 N 台｜{carrier} 送り状 N 枚`。
3. 面单张数默认 1，范围 1～99；修改后汇总按张数累加。
4. 切换 `佐川急便` 不筛除表格行，只改变生成参数与汇总承运商。
5. 点击生成打开 `発送書類の生成`，确认后自动下载 `.xlsx`。
6. 成功提示包含 `{carrier}の送り状を{count}枚生成した（発送は確定されない）`。
7. 生成后原寄送仍为准备中，承运商被改写为本次选择值，产品清单与订单有效出荷数不变。

## 5. 页面契约与实测定位

- 订单列表标题 `注文一覧`，关键词占位 `注文管理番号／お客様注文番号／注文先／納品先`，制造番号占位 `製造番号を入力`。
- 订单行订单管理番号位于 `.mono`；行操作为 `詳細`。
- 订单创建页客户选择弹窗标题 `会社・支店／現場を選択`，直販客户选择注文先后自动复制纳品先。
- 客户仅一个地址/联系人时，订单页自动选中该地址和联系人 `[实测]`。
- 详情页“出荷”按钮文案实际为 `出 荷`，定位时需忽略中间空格。
- 单个商品名的订单打开寄送抽屉后会自动创建寄送准备 `[实测]`。
- 批量页行来源列显示订单号与寄送号；份数输入为行内 `.ant-input-number-input`。
- 生成后文件由浏览器自动下载，测试用 Playwright `expect_download()` 捕获。

## 6. Spec 未明确 / 待确认

1. **详情页重复出荷入口**：已存在准备中寄送时，再次点击订单详情“出荷”会新建另一笔寄送，而不是打开原寄送 `[实测]`。【Spec未明确，需确认】测试改用批量页“作業票を変更”复核原寄送。
2. **寄送准备自动创建**：订单仅一个商品名时打开抽屉自动建准备，页面不再显示“発送準備を作成”按钮 `[实测]`。【Spec未明确，需确认】
3. **面单张数归属**：批量页按寄送设置张数，生成文件内如何分页由后端 Excel 模板决定；当前用例只校验下载文件与成功提示。【Spec未明确，需确认】
4. **承运商改写时机**：生成成功后后端改写寄送承运商；页面未单独提示“承运商已更新”，通过重新打开寄送复核。【Spec未明确，需确认】
5. **测试数据清理**：订单、寄送、面单文件与质检产品均保留；当前无 UI 清理路径，依赖唯一数据避免冲突。

## 7. 后续可扩展点

- 订单列表：更多组合筛选（订单类型、客户区分、履约进度、状态、日期范围）、分页、空态、取消订单后列表展示。
- 订单创建：代理店客户、手输地址/联系人、多颜色行、非法数量、重复提交与并发修订冲突。
- 寄送：超订单剩余数量、重复制造番号、未质检/已绑定产品、删除寄送、登记寄出。
- 运单生成：未勾选禁用、份数边界 0/100、跨页选择、选择后寄送失效、下载失败重试、无权限访问。
