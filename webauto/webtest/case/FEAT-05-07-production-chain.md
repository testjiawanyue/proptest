# FEAT-05~07 产品生产链路：Web 自动化契约卡

> 依据：`spec10-28` 的 FEAT-05 衣体入库、FEAT-06 部件组装、FEAT-07 质检工作台 + 2026-11-03 页面实测。
> 标记：`[Spec]` 来自需求；`[实测]` 来自当前 `http://localhost:8090`；`【待确认】` 表示 Spec 未明确或与页面不一致。

## 1. 路由与页面

| 模块 | 路由 | 页面标题 | 主要动作 |
|---|---|---|---|
| 衣体入库 | `/production/intake` | `今回の入庫設定` / `今回の入庫候補` | 选衣体资料、单个/范围加入、确认入库 |
| 部件组装 | `/production/assembly` | `部品組立` | 选衣体、范围检索、设默认部件、逐格保存 |
| 质检工作台 | `/production/inspection` | `組立検査待ちの製品を検索` | 范围/单件筛选、勾选、确认质检通过 |

## 2. 实测稳定定位

### 2.1 衣体入库

- 衣体资料选择：`#intake-profile`（AntD Select）
- 单个编号输入：`#intake-number`，页面展示 `前缀 + 后缀` `[实测]`
- 范围输入：`#intake-start`、`#intake-end`
- 页签：`番号入力`、`連続入力`
- 加入按钮：`追 加`
- 候选区：`.candidate-panel`，行 `.ant-table-row`，状态 `.ant-tag`
- 状态值：`入庫待ち`、`登録済み`
- 确认按钮：`すべて入庫する`；确认弹窗标题 `入庫の確認`，确认键 `入庫する`
- 成功提示：`成功 3件、スキップ 0件、失敗 0件`

### 2.2 部件组装

- 衣体选择：`#assembly-jacket`
- 范围：`#assembly-start`、`#assembly-end`
- 默认部件：`#assembly-airbag-profile`、`#assembly-sensor-profile`、`#assembly-firmware`、`#assembly-inflator_1-profile`、`#assembly-inflator_2-profile`
- 进入按钮：`検索して組立入力へ`
- 结果行：`.assembly-card .ant-table-tbody tr.ant-table-row`（不是旧版 `table.sheet`）
- 每行四列输入：`td input`，索引 0~3 分别为气囊、传感器、发生器1、发生器2
- 部件编号输入为“前缀 + 后缀”，前缀由默认资料决定 `[实测]`
- 完成计数：`必須部品の取付完了 X/Y台`
- 保存反馈：单元格保存标记；失败为 `.cell-error`

### 2.3 质检工作台

- 前缀选择：`.filter-panel .ant-select`（对应 `#inspection-prefix`）
- 范围：`#inspection-start`、`#inspection-end`
- 单件：`#inspection-number`
- 页签：`連続入力`、`番号入力`
- 检索按钮：`検 索`
- 待检行：`.list-panel .ant-table-row`
- 状态：`検査登録可`
- 勾选：行内 `.ant-checkbox-wrapper`
- 确认按钮：`検査合格を登録（N台）`；弹窗标题 `組立検査合格の登録`
- 成功提示：`成功 2台、失敗 0台`

## 3. 当前可用前置数据

| 类别 | 当前值 |
|---|---|
| 衣体资料 | `PTG` |
| 气囊资料 | `AQ｜气囊 A型` |
| 传感器资料 | `SN｜传感器 A型` |
| 传感器固件 | `85cm` |
| 发生器资料 | `IG｜充气发生器 A型` |

测试启动时若这些选项缺失，应直接失败并提示前置数据不满足，不在主流程中临时维护主数据。
这些值集中在 `production_master_data()` 中，可通过环境变量覆盖：

```text
WEBTEST_PROD_JACKET_PREFIX
WEBTEST_PROD_AIRBAG_PROFILE
WEBTEST_PROD_SENSOR_PROFILE
WEBTEST_PROD_FIRMWARE
WEBTEST_PROD_INFLATOR_PROFILE
```

未设置时使用上表默认值；页面选择器、按钮文案和提示文案属于被测系统契约，不属于测试业务数据。

## 4. 主流程

### 4.1 衣体入库

1. 选 `PTG`。
2. 单个加入第一台，候选状态 `入庫待ち`。
3. 重复加入同一编号，提示 `この番号はすでに今回の入庫候補に含まれています。`。
4. 连续范围覆盖 3 台，已存在候选不重复加入，候选数变为 3。
5. 确认全部入库，提示成功 3 件，候选清空。
6. 组装页按同一范围检索，能查到 3 台产品。

### 4.2 部件组装

1. 选 `PTG`，设置气囊/传感器/固件/发生器默认资料。
2. 范围检索 3 台。
3. P1 录入气囊、传感器、发生器1；P2 再录发生器2；P3 只录气囊。
4. 完成计数为 `2/3台`，无行内错误。
5. 重新进入页面检索，已保存部件仍存在，P3 传感器为空。

### 4.3 质检工作台

1. 选 `PTG`，按 P1~P3 范围筛选。
2. 只有 P1/P2 出现，状态 `検査登録可`；P3 不满足最低构成，不进入清单。
3. 勾选 P1/P2，已选 2 台。
4. 确认质检通过，提示成功 2 台、失败 0 台，两台从清单移除。
5. 单件筛选已质检编号，出现不可登记提示，清单不被替换为可质检行。

## 5. 测试数据与关联方式

- 衣体编号：衣体主数据前缀 + 8位时间戳，按测试计划生成连续编号。
- 部件编号后缀：由同一时间戳派生的唯一数字；最终编号为资料前缀 + 后缀。
- `production_chain_data()` 生成 `ProductionProduct` 计划，每台产品包含 `parts`、槽位和编号后缀；测试中的“齐全台数”“可质检台数”均由计划属性计算，不写死 2 或 3。
- `ProductionFlow.intake_products()`、`assemble_products()` 和三个测试文件共用同一份 `ProductionChainData`：入库生成的编号直接用于组装检索，组装结果直接用于质检筛选，不跨模块重新造号。
- 质检通过不可撤回，已质检产品会永久保留在测试环境；依赖唯一编号避免重复，不依赖自动清理。

## 5.1 硬编码审计结论

- 业务编号、部件编号、产品数量、齐全台数和质检通过台数均由计划动态生成或计算，未写死。
- 生产主数据名称有默认值，但集中在 `production_master_data()` 并支持环境变量覆盖。
- 页面路由、按钮日文文案、字段标签和提示文案属于页面契约，保留为页面对象常量或直接定位文本。
- 生产计划当前固定为“2 台齐全 + 1 台不完整”，这是测试场景设计，不是业务数据硬编码；后续可在 `production_chain_data()` 中扩展产品计划。

## 7. Spec 未明确 / 与页面不一致

1. **单个入库输入口径**：Spec 写输入完整编号；页面实际为“资料前缀 + 后缀” `[实测]`。脚本按页面实现。
2. **空前缀衣体资料**：Spec 允许范围前缀留空并生成纯数字编号；当前页面要求资料必须有前缀，否则提示先在部件资料设置 `[实测]`。主流程不覆盖。
3. **组装表格 DOM**：旧脚本使用 `table.sheet`，当前实际为 AntD `.assembly-card .ant-table-tbody tr` `[实测]`。
4. **质检不可登记提示文案**：由后端返回，当前脚本只断言提示出现和清单不被替换，不断言固定文案 `【待确认】`。
5. **部件编号前缀语义**：页面单元格实际按“默认资料前缀 + 输入值”提交；后续编辑用例需沿用该口径，避免重复前缀。
6. **测试数据清理**：质检通过后产品禁止删除，当前无界面清理路径；测试数据会累积。
