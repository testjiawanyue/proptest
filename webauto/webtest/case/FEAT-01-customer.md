# FEAT-01 客户管理：Web 自动化契约卡

> 用途：作为编写页面对象与主流程脚本的唯一入口，避免每次重读整份 Spec、前端源码和完整 DOM。
> 依据：`spec10-28/spec/docs/features/FEAT-01-customer/spec.md`（Current Truth）+ 2026-11-03 页面实测。
> 标记说明：`[Spec]` 来自需求；`[实测]` 来自当前 `http://localhost:8090`；`【待确认】` 表示 Spec 未明确或与页面不一致。

## 1. 模块与路由

| 对象 | 路由/入口 | 说明 |
|---|---|---|
| 客户列表 | `/customer` | 主导航「客户管理」；新建公司的唯一入口 |
| 客户详情 | `/customer/detail/{subjectId}` | 列表行「表示」进入；公司详情含支店卡、地址、联系人、关联业务 |
| 新建公司 | 列表「＋ 会社を追加」 | 弹窗标题 `[实测]`「会社を追加」 |
| 编辑公司 | 详情「会社情報を編集」 | 与新建共用工作区，标题 `[实测]`「会社情報を編集」 |
| 新建支店/现场 | 详情「＋ 支店／現場を追加」 | 弹窗标题 `[实测]`「支店／現場を追加」；所属公司由上下文带入且只读 |

## 2. 页面特征与稳定定位

### 2.1 列表页 `[实测]`

- 页面标题：`顧客管理`
- 查询区输入框 placeholder：
  - `顧客番号・会社名・支店／現場名`
  - `郵便番号・住所`
  - `氏名・電話番号・メール`
- 客户区分下拉选项：`直販`、`代理店`
- 按钮：`検索`、`リセット`、`＋ 会社を追加`、`過去の顧客を登録`
- 表头：`顧客番号`、`会社名・支店／現場名`、`住所情報`、`連絡先情報`、`操作`
- 行内展示：编号、名称、区分、`〒XXX-XXXX`、地址、`住所 N件`、`担当者 N名`、`表示`
- 公司行前有展开图标；展开后显示其支店/现场行 `[实测]`

### 2.2 新建/编辑公司弹窗 `[实测]`

- 基础信息字段标签：`会社名`、`顧客番号`、`標準の顧客区分`、`資料の保存先`
- 客户编号只读，显示 `保存時に自動採番`；不可编辑
- 区分默认 `直販`
- 提示文案：`資料の保存先は記録・表示用。フォルダーを自動で同期したり、開いたりすることはない。`
- 地址区按钮：`＋ 住所を追加`
- 地址字段标签：`郵便番号`、`住所1`、`住所2（任意）`；邮编 placeholder `3710817`
- 地址块按钮：`削除`、`＋ 担当者を追加`
- 联系人字段标签：`氏名`、`役職（任意）`、`電話番号`、`ファックス（任意）`、`メール（任意）`、`備考（任意）`
- 底部按钮：`キャンセル`、`保 存`（注意“保 存”中间有空格）

### 2.3 新建支店弹窗 `[实测]`

- 字段标签：`所属会社`、`支店／現場名`、`顧客番号`、`資料の保存先`
- `所属会社` 为只读输入框，带入当前公司名称
- `顧客番号` 只读，显示 `保存時に自動採番`
- 无 `標準の顧客区分` 字段
- 地址、联系人字段与公司弹窗一致

### 2.4 详情页 `[实测]`

- 公司卡按钮：`会社情報を編集`、`＋ 支店／現場を追加`、`過去の支店／現場を登録`
- 公司卡字段：`顧客番号`、`会社名`、`標準の顧客区分`、`資料の保存先`
- 地址组头：`〒XXX-XXXX` + `住所1` + 可选 `住所2`
- 联系人表：姓名 + `役職`、`電話番号`、`ファックス`、`メール`、`備考`、`登録日`
- 支店卡：`支店／現場名`、`顧客番号`、`資料の保存先`，按钮 `編集`、`削除`
- 无联系方式时显示 `担当者の登録なし`
- 关联业务：`注文`、`受付`、`案内`，各带 `表示` 跳转
- 公司无删除入口 `[Spec]` `[实测]`

## 3. 主流程（脚本建议）

**主链路：新建公司（含地址+联系人）→ 详情校验 → 新建支店（含地址+联系人）→ 编辑公司 → 列表查询命中并展开层级**

| 步骤 | 动作 | 系统反馈 | 关键业务校验 |
|---|---|---|---|
| 1 | 打开 `/customer`，点击 `＋ 会社を追加` | 弹出 `会社を追加` | 默认区分 `直販`；编号只读 |
| 2 | 填公司名，添加地址与联系人，点击 `保 存` | 成功提示（文案待采集）并跳转 `/customer/detail/{id}` | 邮编 7 位数字；地址1、联系人姓名必填；空地址/联系人不应阻塞保存 |
| 3 | 详情页读取公司卡 | 展示公司名、区分、`〒XXX-XXXX`、地址、联系人 | 编号格式 `C + 数字`；邮编展示带 `〒` 与连字符；创建信息不展示 |
| 4 | 点击 `＋ 支店／現場を追加` | 弹出支店弹窗，`所属会社` 只读带入公司名 | 支店无客户区分字段；编号同为 `C + 数字` |
| 5 | 填支店名，添加地址与联系人，保存 | 跳转支店详情或刷新公司详情（`【待确认】`） | 支店地址、联系人独立于公司 |
| 6 | 返回公司详情，点击 `会社情報を編集`，修改公司名并保存 | 停留详情并刷新 | 客户编号不变；修改后名称与列表同步 |
| 7 | 返回列表，按唯一公司名查询 | 命中公司行；搜索时自动展开命中项 `[Spec]` | 列表显示新名称、区分、首地址、地址/联系人计数 |
| 8 | 展开公司行（若未自动展开） | 展示支店行 | 支店行读取所属公司客户区分 `[Spec]` |

### 3.1 建议断言集

- `expect(page).to_have_url(re.compile(r"/customer/detail/\d+"))`
- 公司编号正则：`^C\d+$`
- 邮编展示正则：`^〒\d{3}-\d{4}$`
- 详情公司名、支店名、联系人姓名精确命中
- 编辑后编号与编辑前一致
- 列表查询后目标公司行可见，且仅命中目标唯一前缀
- 支店行区分等于所属公司区分

## 4. 分支流程（按需补脚本，不进首条主流程）

| 分支 | 触发 | 预期 |
|---|---|---|
| 公司名称必填 | 空名称保存 | 提示 `会社名を入力` `[实测]`；弹窗不关闭，已填内容保留 |
| 地址半填 | 只填邮编或只填地址1 | 提示 `住所1の郵便番号と住所1を入力` `[实测]` |
| 邮编长度错误 | 输入 `123` | 提示 `住所1の郵便番号は半角数字7桁で入力` `[实测]` |
| 联系人半填 | 添加联系人但不填姓名 | 提示 `住所1の担当者1の氏名を入力` `[实测]` |
| 仅基础信息保存 | 不添加地址/联系人 | 应允许保存 `[Spec]` |
| 新增地址后移除 | 本次新加地址点 `削除` | 不弹确认，直接从草稿移除 `[Spec]` |
| 移除已有地址 | 编辑时删除已保存地址 | 弹确认，说明连带联系人数与历史业务不受影响 `[Spec]` |
| 删除支店 | 支店卡 `削除` → 确认 | 支店及其地址、联系人一并删除；历史业务快照不变 `[Spec]` |
| 取消编辑 | 弹窗 `キャンセル` | 关闭且不写数据 `[Spec]` |

## 5. 核心字段规则

| 字段 | 规则 |
|---|---|
| 客户编号 | 系统自动生成 `C + 连续数字`；公司与支店共用序列；不可编辑、终身不变；历史导入使用原编号 `[Spec]` |
| 公司名称 | 必填，可编辑 `[Spec]` |
| 默认客户区分 | 必填，固定 `直販`/`代理`；新建默认 `直販`；支店读取所属公司值 `[Spec]` |
| 资料存放路径 | 可选，仅记录展示，不同步、不打开 `[Spec]` |
| 支店名称 | 必填；所属公司由上下文确定且不可更换 `[Spec]` |
| 邮编 | 仅 7 位半角数字；不接受 `〒`、空格、连字符；保存/展示统一 `〒XXX-XXXX` `[Spec]` `[实测]` |
| 地址1 | 地址一旦开始填写则必填 `[Spec]` |
| 地址2 | 可选 `[Spec]` |
| 联系人姓名 | 联系人一旦开始填写则必填 `[Spec]` |
| 职称/电话/传真/邮箱/备注 | 可选，按文本保存；邮箱不做格式校验 `[Spec]` |
| 所属关系 | 地址只能属于一个公司或支店；联系人不支持换地址；地址不支持换所属 `[Spec]` |
| 历史业务 | 订单/通知/受付/出货/返送保存当时快照；主档更正或删除不回写 `[Spec]` |

## 7. Spec 未明确 / 与页面不一致

1. **客户区分选项文案不一致**：Spec 为 `直販／代理`，页面实测为 `直販／代理店`。脚本应按页面 `代理店` 定位，并提请确认以哪个为准。
2. **保存成功提示文案**：已实测为 `顧客情報の保存が完了。`，公司与支店保存、公司编辑共用该文案。
3. **新建支店保存后的去向**：已实测为停留在所属公司详情页并刷新支店卡，不跳独立支店详情。
4. **列表搜索自动展开**：已实测按公司名查询后自动展开命中公司，支店行同时出现在结果中；脚本可直接断言支店行，但建议保留“必要时手动展开”的兼容分支。
5. **客户编号连续序列的并发口径**：Spec 为“当前最大号 +1”，未说明并发取号与失败回滚是否占号；自动化只断言格式，不断言严格连续。
6. **支店行在列表中的展开层级 DOM**：实测展开后有独立行，但需确认稳定选择器，避免依赖 AntD 内部类名之外的文本。
7. **编辑公司时移除已有地址的确认文案**：Spec 只描述说明内容，未给出固定日文文案；需实测采集后再做精确断言。
8. **“过去の顧客を登録 / 過去の支店／現場を登録”**：页面存在入口，但 Spec 未描述历史导入流程；本模块主流程不覆盖。

### 7.1 实测补充结论

- 公司保存后跳转 `/customer/detail/{id}`，成功提示为 `顧客情報の保存が完了。`。
- 支店保存后仍停留在公司详情页，支店卡随刷新出现；支店编号与公司编号共用 `C+数字` 序列。
- 公司编辑弹窗标题为 `会社情報を編集`，保存后停留详情页，客户编号保持不变。
- 列表按公司名查询会自动展开公司行，公司行与支店行合计显示；支店行客户区分等于所属公司值。
- 公司详情公司卡使用 `.subject-card` 第 1 个；支店卡使用按支店名过滤的 `.subject-card`。

## 8. 明确不做（避免误写用例）

- 启用/停用、更正履历、字段级历史
- 公司删除
- 支店独立客户区分
- 地址换所属、联系人换地址
- 邮箱格式校验、疑似重复提示
- 关联业务件数统计
- 得意先コード（SMILE BS）管理
- 价格、正式請求書、收款、对账、财务
- 订单/通知/受付等业务侧客户快照内容校验
