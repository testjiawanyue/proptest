# AI 开发项目质量保证体系文件索引

本目录给出 PROP 项目在 AI 辅助开发模式下，从需求进入到线上反馈的质量保证全流程、可介入时点、架构验证体系、门禁设计、度量方法以及效果不佳时的优化和降级方案。分析依据包括《质量执行方案》、`prop_new` 当前工程结构、`测试流程 v3.0`、`ai-test` 三方对齐资产、`auto-explore` 运行时验证资产和 `测试用例汇总_V5.xlsx`。

## 核心结论

当前项目已经具备较完整的质量素材，主要短板不是“缺测试”，而是缺少一条能够自动执行、统一取证、按风险阻断和失败后降级的质量运行链。建议以变更为主线，建立“七阶段流程、七层验证、六道门禁、一套证据账本和一组可量化指标”，先在一个高风险业务纵切面试点，再逐步推广。

截至 2026-11-23 15:50，`W1-01` 至 `W1-05`、`W1-07`、`W1-08` 已完成。标准测试环境已重新采集运行态指纹，四个必需端口 4/4 可达，后端固定 JDK 17；首轮门禁模式和例外审批规则已确认；G2 已完成首次有效影子运行，但 3 项失败仍需按 `12-W1-08-G2影子编排与失败分类.md` 修复。`W1-06` 仍等待首个真实变更号和提交号。

不建议直接建设大而全的平台。第一阶段应优先串联现有 Maven、npm、JUnit、Node Test、Playwright、MySQL 探针和 V5 用例映射，先把确定性检查、业务结果断言、人工裁定和证据留痕做成闭环。

## 建议立即执行的五件事

1. 质量负责人和订单链路负责人由贾婉月担任，平台负责人、业务负责人、安全接口人和开发负责人由张树旸担任，发布负责人和运维或 SRE 负责人由李旸担任；详见 `00-责任人与审批台账.md`。
2. 冻结当前质量基线：测试数量、执行状态、失败清单、耗时、误报、未执行用例和线上缺陷口径。
3. 先用“影子模式”接入编译、前端构建、类型检查、Lint、单元测试、Secret 扫描和依赖扫描，观察两周后再决定是否阻断。
4. 把 V5 中 P0/P1 用例、`ai-test` 的 REQ/BR 证据和 `auto-explore` 的 UI/API/DB 断言统一到一条证据链。
5. 为每个发布保留可回退门禁：任何新增阻断项都必须支持降为告警或人工替代，不能出现工具故障导致业务无法交付且无替代路径的情况。

## 使用边界

本目录是项目外质量治理与验证资产，不修改 `E:\proptest\prop_new` 的任何源码、目录或元数据。后续若需把 CI 配置、测试钩子或质量脚本纳入源码仓库，应作为独立受控变更评审后实施。
