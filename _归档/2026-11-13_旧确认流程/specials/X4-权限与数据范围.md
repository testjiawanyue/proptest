## 1. 风险来源

`spec/测试风险评估文档.md`：P-01、P-02、P-04、C-03

**当前最薄弱的一环**：所有现有 E2E 与验证脚本一律使用 admin 账号，等于 P-01/P-02 从未被验证。菜单隐藏 ≠ 接口拒绝，这是最典型的越权缺口。

## 2. 场景清单

**账号矩阵**（4 类 × 22 个页面入口）

| 账号类型 | 构造方式 |
|---|---|
| admin | 全权限 |
| 只读 | 赋予查询权限，不给写 |
| 单页面维护 | 只给一个页面的维护权限 |
| 无权限 | 不分配任何业务角色 |

**每个入口 × 每个账号的探测链**（5 步，不可跳步）：

| 编号 | 步骤 | 预期 |
|---|---|---|
| XC4-01 | 菜单是否可见 | 无权限不显示 |
| XC4-02 | 直达 URL 是否拦截 | 无权限跳转或 403 页 |
| XC4-03 | 页面刷新后是否仍被拦 | 不出现"刷新后权限失效" |
| XC4-04 | 直接调写接口（绕过前端） | **401/403**（核心断言） |
| XC4-05 | 改 HTTP 方法（GET→POST/PUT/DELETE）调用同一 URL | 仍拒绝，不能靠方法白名单绕过 |

补充场景：

| 编号 | 场景 | 预期 | 证据 |
|---|---|---|---|
| XC4-06 | 只读账号调所有写接口 | 全部拒绝 | 请求响应全集 |
| XC4-07 | 单页面账号调其他页面接口 | 全部拒绝 | 同上 |
| XC4-08 | 共享查询接口被无权限账号调用 | 不泄露数据（返回空或拒绝，不能返回全量） | 响应体 |
