## 为什么需要单独一层

FEAT-11 的"确认寄出"同时改变：寄送记录、订单当前关系、有效交付数量、产品归属、生命周期基准月、事件时刻。
任何一个**单模块准出卡都无法独立证明这 6 件事同时正确**——每张卡只能看到自己那一面。
所以跨模块风险必须单独成卡，由"多模块同时可用"这个条件触发。

## 与发布门禁的关系

发布判定中，**X1 / X2 / X4 为硬条件**：未通过即阻断，不接受条件通过。
其余三张卡可条件通过，但残余风险必须进放行报告。

原因：X1 涉及不可逆事实、X2 涉及数据正确性、X4 涉及越权——这三类是"上线后无法用业务操作补救"的问题。

## 执行纪律

1. **触发即进 `验证中`**，台账"专项卡台账"同步更新，不允许"还没到时候"拖到发布前一周；
2. **一张卡一次判定**，不按模块拆开判；判定结论只有三种：`通过` / `未通过` / `条件通过`；
3. **硬条件卡不存在 `条件通过`**，卡内已写明；
4. 判定依据必须落盘（证据路径），不接受口头结论——与模块门同一纪律。
