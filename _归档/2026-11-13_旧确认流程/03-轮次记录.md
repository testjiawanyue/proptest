## 二、R2 起每轮固定动作

```
① git -C prop_new rev-parse --short HEAD → 填 commit，新建一行
        ↓
② 回归验证
   - 对象：上表所有「本轮验证模块」里状态为 ☑ / ◐ 的 FEAT
   - 优先级：按本次改动文件路径反查对应 FEAT，涉及的先跑；其余至少跑一次主流程 smoke
   - 结果落盘，证据路径填进 01
        ↓
③ 修改问题验证
   - 对象：02 里状态为「已修待复验」的条目
   - 逐条复验 → 通过改「已关闭」+ 填轮次；未通过退回「待修」+ 附现象
   - 把复验编号与结果填进本表「复验问题编号」列
        ↓
④ 新模块 / 新功能 → 按 README 第二节走新单元验证
        ↓
⑤ 更新 01（验证状态）、02（问题状态）、本表（新增问题 / 结论），测试人员在 01 底部确认
```

**回归范围判定规则**（替代旧流程的「基线池 / M 集 / smoke 集」）：

| 情况 | 回归范围 |
|---|---|
| 改动落在某个 FEAT 对应的代码目录 | 该 FEAT 全量验证 + 相邻 FEAT 主流程 smoke |
| 改动是公共层（框架、权限、时间、模板、DB） | 全部已验证模块至少跑 smoke，全局 L0 单测必跑 |
| 只是修复上轮问题 | 该问题所属 FEAT + 该问题本身的复验用例 |
| 无代码改动、只更新文档 | 不跑回归，在结论列注明 |
