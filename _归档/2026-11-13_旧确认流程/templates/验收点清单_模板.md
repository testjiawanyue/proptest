## 1. 提取规则

### 第 0 步：先枚举 VAL，再拆 VP（v1.1 新增，强制）

> 坑 1：两模块 VAL 粒度差异极大（FEAT-02 只有 5 条，FEAT-08 有 44 条且含空标题/指针/重复段），不先枚举就会漏拆或重拆。

**必须执行以下命令，把结果粘到本节下方：**

```bash
cd prop_new/docs/spec/docs/features/{FEAT-XX}
grep -oP "VAL-[A-Z0-9]+[a-c]?" validation.md | sort -u | tr '\n' ' '
grep -oP "VAL-[A-Z0-9]+[a-c]?" validation.md | sort -u | wc -l
```

枚举结果（原样粘贴）：`______________________`　共 ____ 条

**再逐条核对，把三类异常单独标注**：

| 异常类型 | 判定 | 标准处理方式 |
|---|---|---|
| **空标题** | VAL 编号存在但无正文（如只有 `VAL-02` 一行） | 不计为独立 VP；若其后紧跟场景叙述，以叙述首句为准，在"原文位置"注明 `VAL-02(正文缺失)` |
| **指针/引用** | 内容为"见 VAL-xx"或"同 VAL-xx" | 不新建 VP，在源 VP 的"原文位置"附加 `(含 VAL-09a 指针)`，并在备注写"合并" |
| **跨段重复** | 同一 VAL 编号出现两次（如 VAL-29/30） | 拆成两条 VP 时在编号后加 `-A`/`-B`，原文位置写 `VAL-29(第一段)` / `VAL-29(第二段)` |
| **独立附录** | 如 `VAL-BASE20` 独立成段 | 正常拆，编号用 `VP-XX-0xx`，原文位置写 `VAL-BASE20` |

### 第 1～5 步：拆解与定级

1. **一条验收点一个 VP 编号**，格式 `VP-{FEAT}-{三位序号}`，重新编号，不复用原文序号（原文会变，编号不能变）。
2. `validation.md` 中的"验收项 / 检查点 / 预期结果"拆成独立可判定项；一句里含两个预期就拆两条。
3. **优先级判定**（不按原文顺序，按风险）：
   - **P0**：关联高风险编号，或涉及不可逆动作 / 跨模块事实 / 权限 / 时间 / 文件冻结；
   - **P1**：主流程功能正确性，错了有 workaround；
   - **P2**：显示、文案、排序、易用性。
4. **验证方式**：`自动-L1` / `自动-L2` / `人工` / `双人复核`（涉及不可逆动作或对外文件的，标双人复核）。
5. 原文中标注【待确认】的，优先级按"高"计，并在备注写明待谁确认。
