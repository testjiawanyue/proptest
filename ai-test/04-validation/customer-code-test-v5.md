# V5客户管理测试点与代码行为支撑判定

- 分析时间：2026-10-19（CST）
- 代码依据：`ai-test/02-code-analysis/customer-code-behavior.md` 中的 BR-001～BR-079
- 用例依据：`case/outputs/测试用例汇总/测试用例汇总_V5.xlsx` 的“客户管理”工作表
- 用例数量：115 条（工作表共 116 行，首行为表头）
- 判定性质：静态代码行为支撑判定，不是测试执行结果。

## 1. 判定口径

| 判定 | 含义 |
|---|---|
| 支撑 | 代码行为模型中有明确 BR 证据，当前前后端行为与测试点核心预期一致。 |
| 部分支撑 | 当前模块实现了一部分核心行为，但用例还依赖下游模块、角色数据或运行环境，不能判定完全满足。 |
| 冲突 | 测试点核心预期与代码行为明确相反，或依赖当前代码明确不存在的能力。 |
| 无法确认 | 当前客户模块代码证据不足，无法判断测试点是否满足。 |

限制说明：

1. V5 用例的“测试结果/执行状态”不作为本文判定依据；本文只判断代码是否支撑测试点。
2. 不根据 Spec 反推代码；V5 与需求基线冲突时，在判定依据中明确指出。
3. 下游历史业务快照、登录态、角色授权和菜单展示不能仅凭客户模块代码判为支撑。

## 2. 总体结论

| 支撑 | 93 | 80.9% |

主要结论：

1. 客户查询、排序、分页、公司/支店新建、整体编辑、地址联系人校验和支店级联删除的代码支撑较强。
2. 明确冲突集中在：名称重复拦截、邮箱格式校验、并发编辑提示、业务引用删除拦截、更正履历、受付/通知跳转。
3. 跨模块历史业务快照和真实权限环境不能用客户模块代码证明，需要后续模块分析或运行环境验证。

## 14. 高风险冲突与未确认行为

### P0

- 客户编辑-009、客户回归-002：跨模块历史业务快照无法确认；需要订单、通知、受付、出货、返送模块代码证据。
- 客户删除-003、客户删除-006：代码不做业务引用检查，若产品要求引用拦截，当前实现会物理删除主档。

### P1

- 客户编辑-010：并发编辑没有版本检查，后提交可能静默覆盖先提交。
- 客户联动跳转-002、003、005：受付和通知入口不可跳转。
- 客户更正履历-001～003、客户删除-008：更正履历完全未实现。

### P2

- 公司维护-007、支店现场维护-004：名称重复不拦截。
- 客户权限-001～004：接口权限表达式存在，但真实登录、角色和菜单效果需要环境验证。
- 客户列表查询-006、019：历史编号独立展示未实现。

### P3

- 客户编辑-008：邮箱格式用例与 REQ-012 明确规则冲突；代码不校验邮箱格式。建议先修正用例或变更需求。

## 15. 建议补充或调整测试用例

1. 先组织需求裁决：名称唯一性、业务引用删除拦截、更正履历、并发编辑提示是否为正式需求；当前 V5 与需求基线/代码存在明显口径差异。
2. 为 REQ-017 增加订单、通知、受付、出货、返送五个下游模块的快照字段和保存/查询链路验证，不使用客户模块删除弹窗文案作为通过证据。
3. 若保留引用删除拦截需求，补充“被订单引用地址/支店”数据构造和后端拦截断言；当前代码会失败。
4. 若保留并发编辑要求，补充同一客户基于旧详情连续两次提交的测试，并断言第二次不能静默覆盖。
5. 将邮箱非法格式用例与 REQ-012 对齐：当前应预期“按文本保存且不校验格式”，或先修改需求并实现校验。
6. 权限用例应绑定明确测试角色、菜单授权和未登录路由守卫证据；不要只测接口注解。
7. 历史编号用例需先确认导入实现和数据模型：若只使用 `customer_no`，应删除“业务编号下另显示历史编号”的预期。
