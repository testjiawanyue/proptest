## 14. 高风险未覆盖与需补证行为

1. **部署与授权未确认（P1）**：`c06_history_entry.sql` 标注 `REVIEW ONLY`，`c06_history_entry_menu.sql` 明确未执行、不授予角色（BR-082）。代码存在不等于目标环境已具备表、菜单和页面权限。
2. **“此前已回收”人工确认留痕不足（P1）**：前端对所有 `rental_repeat` 恒传 `previousRecoveryConfirmed=true`（BR-050），服务端只校验布尔值，无法证明逐台人工核对，也无法追溯确认人/时刻。
3. **基准 clear 全路径未验证（P1）**：历史/外部首次基准解除时日期、月份及全部来源是否同步清空，静态代码只能确认分支存在（BR-061/062），需数据库断言。
4. **下游通知、生命周期、受付未端到端验证（P1）**：通知候选、旧 PDF 冻结、生命周期首次月、案内生成及补录后新受付均跨越本模块（BR-083/084/085），现有证据不足以判定联调结果。
5. **并发时序未注入（P2）**：ended 补录与新增维修/准备/当前 B、基准确认后变化、末尾失败等场景只有锁与重验代码（BR-052/058），没有真实并发执行证据。
6. **历史质检展示口径（P2）**：真实质检登记晚于历史出货时，页面是否明确区分“历史认定依据日”和“本次登记审计时刻”未逐页确认（BR-051/064）。

## 15. 建议补充测试用例

1. 增加历史/外部基准 clear 的数据库断言：清除后首次日、首次月、寄送来源、外部事实来源均应为空，旧通知/PDF 快照保持不变。
2. 增加 repeat 后下游联调用例：履约台数、生命周期首次月、案内生成、受付新快照、旧质检与登记履历分别断言，不只看订单保存成功。
3. 增加 ended 补录并发注入：提交期间新增维修、返送准备、当前 B 关系，验证锁后重验、整单回滚及不反向补锁。
4. 增加“此前已回收”人工确认留痕用例：逐台确认、确认人/时刻可追溯，禁止前端无条件自动传 true。
5. 增加历史质检页面展示用例：同时展示历史认定依据日与本次登记审计时刻，已有质检不新建/不覆盖且首检标记保持。
6. 增加部署验收用例：迁移脚本执行、菜单注册、角色授权、普通角色仅页面权限直达刷新及无权限接口拒绝。
