# V5订单管理测试点与代码行为支撑判定

- 分析时间：2026-10-26（CST）
- 代码依据：`ai-test/02-code-analysis/order-code-behavior.md`（BR-001～BR-052）
- 用例依据：`case/outputs/测试用例汇总/测试用例汇总_V5.xlsx` 工作表「订单管理」（FEAT-10 订单、FEAT-11 寄送、FEAT-19 订单批量打印）
- 用例数量：139 条
- 判定性质：静态代码行为支撑判定，不是测试执行结果

## 1. 判定口径

| 判定 | 含义 |
|---|---|
| 支撑 | BR 中有明确证据，当前前后端行为与测试点核心预期一致。 |
| 部分支撑 | 当前模块实现一部分，仍依赖其他模块、登录态/菜单框架、角色数据或运行环境。 |
| 冲突 | 测试点核心预期与代码行为明确相反，或依赖当前代码明确不存在的能力。 |
| 无法确认 | 当前模块代码证据不足。 |

## 2. 总体结论

| 判定 | 数量 |
|---|---|
| 支撑 | 123 |
| 部分支撑 | 14 |
| 冲突 | 1 |
| 无法确认 | 1 |
| 合计 | 139 |

- 唯一冲突为「订单列表查询-006」（关键词搜索产品名称与颜色）：代码关键词仅匹配四项（BR-001），用例备注自身亦标注与 FEAT-10 §4.4 口径不一致、待裁决。

- 订单写操作与寄送全流程（含幂等、锁、快照、编号、级联删除）在代码中有完整支撑。

## 13. 高风险冲突与未确认行为

1. 【冲突】订单列表查询-006：代码关键词不支持产品名称/颜色检索（BR-001）。用例备注标【待确认】且与 FEAT-10 §4.4 口径不一致，需需求裁决后调整用例或代码。
2. 【部分支撑】发货管理-017：auto 自动保存允许无产品，与“保存失败”预期不一致；explicit 保存与文件生成在无产品时被拒。建议用例区分保存模式。
3. 【部分支撑】订单权限-003：系统无只读角色设计，所有写操作共用 prop:order:page；用例所述“只读角色”场景无对应实现。
4. 【无法确认】订打补充-012：产品摘要超长省略与完整查看入口无代码证据。

## 14. 建议补充或调整测试用例

1. 调整订单列表查询-006：待需求裁决关键词范围；若维持四项口径，应将“产品名称/颜色检索”从预期移除或拆为独立待裁决用例。
2. 拆分发货管理-017：区分 auto 自动保存（允许无产品）与 explicit 保存/文件生成（拒绝）两个场景。
3. 调整订单权限-003：按实际权限模型改写为“无 prop:order:page 权限的账号全部订单写操作被服务端拒绝”。
4. 补充解除关联的基准处理用例：keep/clear 两种选择对产品首次出货/基准月的不同影响（BR-024/026，Spec 未覆盖）。
5. 补充寄送创建幂等与并发用例：同 requestId 重放、已发足订单新建寄送被拒（BR-027/029）。
6. 补充已取消订单的寄送限制用例：准备中寄送不可确认、不可生成文件，但已寄出记录仍可生成文件（BR-020/048）。
