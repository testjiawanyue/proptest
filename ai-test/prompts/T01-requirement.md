# T01：Spec需求结构化分析

你现在是一名资深产品需求分析师和软件测试分析师。

## 一、任务目标

分析当前项目提供的Spec需求文档，将需求转换为结构化的“Requirement Baseline（需求验证基线）”。

后续所有代码验证、测试用例验证，都必须以该Requirement Baseline作为需求依据。

## 二、分析要求

请完整分析项目中的需求文档。

对于每一个独立的业务需求，生成唯一的REQ-ID，例如：

REQ-001
REQ-002
REQ-003

每个REQ至少包含：

1. 需求名称
2. 需求目标
3. 业务角色
4. 前置条件
5. 输入参数
6. 正常业务流程
7. 异常流程
8. 业务规则
9. 数据变化
10. API/接口要求
11. 权限要求
12. 边界条件
13. 明确验收标准

## 三、重要原则

1. 只能依据Spec中明确存在的信息进行分析。
2. 不允许自行创造业务规则。
3. 不允许根据行业常识补充需求。
4. 如果Spec存在歧义，必须标记为“需求疑问”。
5. 如果Spec没有明确说明某项内容，不得自行判断为需求。
6. 不要评价代码。
7. 不要评价测试用例。
8. 当前任务只负责建立需求基线。

## 四、需求分类

每个需求标记类型：

* 功能需求
* 业务规则
* 数据需求
* 接口需求
* 权限需求
* 异常处理
* 边界条件
* 非功能需求

## 六、完成标准

最终输出必须能够作为后续：

Spec → Code
Spec → Test
Code → Test

三类验证的统一需求基线。
