### 1.3 核心业务主线

- 产品形成：衣体入库（FEAT-05）→ 部件组装（FEAT-06）→ 质检（FEAT-07）→ 正式产品（FEAT-08）。首次质检通过前属于产品生产，通过后进入正式产品。
- 订单出货：订单（FEAT-10）创建时不绑定具体产品；寄送（FEAT-11）确认寄出时才建立产品订单关系，并将首次出货月登记为生命周期基准月。
- 返厂闭环：定期管理（FEAT-12）/通知（FEAT-13）→ 受付（FEAT-14，大番号→包裹→小番号）→ 作业（FEAT-16，五组登记+报告+回收/报废确认）→ 返送（FEAT-17）。
- 闭环三种出口：返送回客户（关系不变）、确认回收（结束订单关系）、确认报废（生命周期终结）。
- 箭头仅表示常见业务衔接：订单可不经过通知直接来件；产品可先入库再下订单；报告不是返送的硬前置；返厂不自动解除订单关系。

## 2. REQ-001

### 需求名称

系统范围与边界

### 需求目标

明确 PROP V2.1 系统覆盖与不覆盖的业务范围，作为全部需求的顶层边界。

### 角色

全体系统使用人员。

### 前置条件

无。

### 输入

无。

### 正常流程

1. 系统覆盖客户、部件、生产、订单与寄送、点检与通知、受付、作业、报告、返送业务。
2. 系统具体负责：客户主档及业务快照、部件与产品组成追溯、产品生产与首次质检、正式产品、订单与现实出货、生命周期与通知、返厂受付、专业作业、正式报告、原产品返送、运营统计与业务概览。

### 异常流程

Spec 未明确。

### 业务规则

- 系统不负责正式請求書、收款、对账、会计、税务。
- 系统不在系统内执行逐项生产质检（线下完成，系统只登记结果）。
- 产品生命周期与受付、维修、返送的业务进度必须清楚区分，不能混为同一业务含义。
- 产品显示的当前订单必须与其有效、未结束的订单关联一致。
- Reception 不等于 Work 已完成；WorkExecution 只记录实际专业作业。
- 报告与回收/报废实际处理完全独立：生成报告不等于已回收/已报废。
- 正式物流事实、已发生的部件与产品关系事件及原身份历史保留，文件版本生成后不覆盖。
- 出货/返送准备删除时其全部所属文件和邮件版本随删，不保留该准备业务历史（含单笔发货保障确认书）。
- 同一业务记录在不同页面展示时，内容与业务口径必须一致。

### 数据变化

无（本需求为范围声明）。

### 接口要求

Spec 未明确。

### 权限要求

Spec 未明确。

### 边界条件

金额、收付款、记账及财务审批均不在系统范围内。

### 验收标准

- 系统内不存在請求書、收付款、对账、会计、税务功能入口。
- 系统内不存在逐项生产质检执行功能，仅可登记质检通过事实。

## 3. REQ-002

### 需求名称

看板-订单一览统计

### 需求目标

在首页看板按业务类型展示进行中订单与剩余待发台数，使员工掌握订单整体履约状况。

### 角色

全体员工。

### 前置条件

系统内存在订单记录。

### 输入

无（展示时自动统计）。

### 正常流程

1. 看板展示「租赁订单」「销售订单」「替代订单」三列。
2. 每列展示「进行中」订单数与「剩余待发」台数。
3. 进行中 = 有效发货数 < 订购数的订单数（含一台未发；已发完的订单不计入）。
4. 剩余待发 = 进行中订单的「订购数 − 有效发货数」合计台数。

### 异常流程

无数据时各数字显示为 0。

### 业务规则

- 已结束的订单不参与统计。
- 发完不冻结订单：已发完订单不计入进行中，但仍可继续业务（追加发货、编辑等）。
- 替代订单计入统计，不移除。
- 已删除、已作废的记录不计入。

### 数据变化

无。看板数字不保存，展示时按当前记录统计。

### 接口要求

Spec 未明确。

### 权限要求

本页只读；具体权限 Spec 未明确。

### 边界条件

有效发货数等于订购数的订单不计入进行中；剩余待发不出现负值口径（按 REQ-057 交付口径）。

### 验收标准

- 三列并排展示，每列大数字为进行中单数，下方明细为「剩余待发 N 台」。
- 已发完订单不计入进行中；已结束/已删除/已作废订单不参与统计。

## 4. REQ-003

### 需求名称

看板-待办事项统计

### 需求目标

展示今日应发货与逾期未发货的订单，提示员工及时处理发货。

### 角色

全体员工。

### 前置条件

存在填写了预计发货日且仍有剩余待发数量的订单。

### 输入

无。

### 正常流程

1. 展示「今日要发货」：预计发货日为今天的订单数，附「N 台待发」。
2. 展示「逾期未发」：预计发货日早于今天的订单数，附「N 台待发」。
3. 逾期未发订单数大于 0 时数字显示为红色。

### 异常流程

无匹配订单时显示 0，逾期红色不出现。

### 业务规则

- 只统计仍有剩余待发数量的订单；已发完订单即使预计发货日已过也不计入逾期。
- 未填写预计发货日的订单不参与今日与逾期统计。
- 日期判断按日本业务日。

### 数据变化

无。

### 接口要求

Spec 未明确。

### 权限要求

本页只读。

### 边界条件

预计发货日为空的订单不参与统计。

### 验收标准

- 今日/逾期两项并排展示；逾期单数大于 0 时为红色，为 0 时普通色。
- 底部注明「未填写预计发货日的订单，不参与今日和逾期统计」。

## 5. REQ-004

### 需求名称

看板-厂内作业统计

### 需求目标

展示待清洗、待返送、今日受付三项厂内作业数量。

### 角色

全体员工。

### 前置条件

存在受付及后续作业相关记录。

### 输入

无。

### 正常流程

1. 「待清洗」：本次受付要求需要清洗、尚未登记清洗完成的产品数（台）。
2. 「待返送」：仍存在应返未返产品的大番号数。
3. 「今日受付」：今天新建的有效产品受付数（台）。

### 异常流程

无记录时显示 0。

### 业务规则

- 已回收、已报废的产品不再计入待清洗。
- 「应返未返」= 处置决定为返回客户、尚未实际返送、未回收、未报废。
- 待返送只认实际寄出：返送面单已建立或已打印但尚未确认寄出的产品，仍计入应返未返。
- 日期判断按日本业务日；只认有效记录。

### 数据变化

无。

### 接口要求

Spec 未明确。

### 权限要求

本页只读。

### 边界条件

仅确认寄出（实际寄出）才使产品离开应返未返口径。

### 验收标准

- 三项并排展示且各带一行口径说明。
- 准备中/已打印未寄出的返送产品仍计入待返送。

## 6. REQ-005

### 需求名称

看板-今日作业统计

### 需求目标

按五个工作组展示当日首次登记作业记录的产品台数。

### 角色

全体员工。

### 前置条件

当日存在作业首次登记记录。

### 输入

无。

### 正常流程

1. 五个工作组（縫製／センサ／組立／展開修理／クリーニング）各显示一个数字，横向并排。
2. 每组数字 = 该组今天首次登记作业记录的产品台数。

### 异常流程

无记录时显示 0（Spec 明确：历史日期作业导致当日通常为 0 属正确表现）。

### 业务规则

- 一台产品的同组作业当天只计一次。
- 只看「首次登记时间」属于今天；当天之后的修改不改变归属，不会从今日数字中消失。
- 已作废的作业记录不计入。
- 只按工作组区分，不按作业人员区分。

### 数据变化

无。

### 接口要求

Spec 未明确。

### 权限要求

本页只读。

### 边界条件

不统计员工个人维度工作量。

### 验收标准

- 五组均分一行横排，各显组名与台数。
- 底部注明「按各工作组作业台账的首次登记时间统计当日数量」。

## 7. REQ-006

### 需求名称

看板-厂内库存统计

### 需求目标

展示在制品与成品在库数量，反映厂内库存状态。

### 角色

全体员工。

### 前置条件

存在产品记录。

### 输入

无。

### 正常流程

1. 「在制品」：尚未通过首次生产质检的产品数（台）。
2. 「成品在库」：质检通过、当前无未结束订单关系、未报废的产品数（台）。

### 异常流程

无记录时显示 0。

### 业务规则

- 订单关系无论从哪个入口结束（订单管理解除关联、受付侧确认回收），结束后产品都进入成品在库口径。
- 确认回收的产品不另外要求重新入库质检。
- 已报废产品不计入成品在库。

### 数据变化

无。

### 接口要求

Spec 未明确。

### 权限要求

本页只读。

### 边界条件

仅两个订单关系结束入口：订单管理解除关联、受付侧确认回收。

### 验收标准

- 两项并排展示并各带口径说明。
- 回收产品直接计入成品在库，无重新质检要求。

## 8. REQ-007

### 需求名称

看板-半成品统计

### 需求目标

展示在制产品数量、待质检数量及在制品当前绑定的各类型零件数量。

### 角色

全体员工。

### 前置条件

存在在制产品及其部件绑定。

### 输入

无。

### 正常流程

1. 左侧展示产品数：在制品（与厂内库存卡同口径）、待质检。
2. 右侧展示零件数：在制品当前有效绑定中的气囊、传感器、发生器个体数。

### 异常流程

无记录时显示 0。

### 业务规则

- 待质检 = 部件组装齐全（气囊、传感器、发生器位置 1 均已绑定）但尚未通过首次生产质检的产品数；最低构成定义见 FEAT-07 §3.2。
- 发生器位置 1／2 各算一个。
- 衣体是产品本体不计入。
- 已解除绑定、已过质检产品的绑定不计入。

### 数据变化

无。

### 接口要求

Spec 未明确。

### 权限要求

本页只读。

### 边界条件

发生器位置 2 不计入待质检最低构成。

### 验收标准

- 左侧产品数、右侧零件数，两组件竖向分隔。
- 零件数上方注明「在制品当前绑定的零件」。

## 9. REQ-008

### 需求名称

看板通用规则与跳转

### 需求目标

规定看板统计性质、有效记录口径、日期口径及卡片跳转行为。

### 角色

全体员工。

### 前置条件

用户已进入首页看板。

### 输入

无（页面打开或刷新触发统计）。

### 正常流程

1. 页面打开或刷新 → 按当前全部有效记录统计并展示各卡片数字。
2. 点击卡片右上角或底部跳转链接 → 进入对应模块页面处理业务。
3. 页面顶部显示当前日期（含星期）与「数据根据当前记录自动统计」说明。

### 异常流程

本页纯统计展示，无输入与校验，无异常流程。

### 业务规则

- 统计而非存储：看板数字不保存为独立数据，不存在「看板数字与业务数据不一致需要同步」。
- 有效记录：已删除、已作废的记录一律不参与统计。
- 业务日：「今日」「逾期」等日期判断按日本业务日。
- 口径唯一来源：每个数字口径以 FEAT-00 spec §3 为准，看板不单独发明口径。
- 本页只读，不提供任何修改入口。

### 数据变化

无。本页不建立、更正或删除任何业务记录。

### 接口要求

Spec 未明确。

### 权限要求

登录后默认页；具体角色权限 Spec 未明确。

### 边界条件

明确不做：「需核对」订单节点；「不再关注」人工标记；员工个人维度统计；绩效/任务中心/派工；看板数字保存、快照与历史趋势。

### 验收标准

- 任一模块记录变化后，看板下次展示即随之变化。
- 每张卡片均可一键跳转对应模块；页面无任何写入入口。
## 10. REQ-009

### 需求名称

客户主档-公司资料

### 需求目标

建立可复用的公司级客户主档，为订单、通知、受付、出货、返送提供客户资料来源。

### 角色

营业/事务；员工填写，系统自动记录创建与修改信息。

### 前置条件

用户进入客户管理并新建公司。

### 输入

公司名称（必填）、默认客户区分（必填）、资料存放路径（选填）。

### 正常流程

1. 员工在客户列表点击「新建公司」，进入客户编辑工作区。
2. 填写公司名称，选择默认客户区分，可填写资料存放路径。
3. 保存时系统自动生成客户编号，记录创建人、创建时间。

### 异常流程

必填项缺失或校验失败时整体不提交，保留已填写内容。

### 业务规则

- 客户编号两个来源：系统新建自动生成，格式为 C + 连续数字（例 C00012），公司与支店/现场共用同一条连续序列，取当前最大号 +1；历史导入客户直接使用原系统编号（例 NS-0001）。
- 编号一经确定终身不变（改名、改地址均不换号），界面不可编辑。
- 默认客户区分固定两个选项：直販／代理；新建默认直販；不提供自定义维护。
- 资料存放路径仅作记录展示，不自动同步、不自动打开。
- 创建人、创建时间、最近修改人、最近修改时间由系统自动记录，详情页不展示。
- 公司名称不设唯一性约束，允许同名公司并存，主体以客户编号区分；不提供疑似重复提示。（2026-10-19 决策，已经运行时验证确认：同名公司可正常创建并存档。）
- 并发编辑不提供版本冲突检测与提示：多名用户同时编辑同一客户时，后保存者覆盖先保存者的修改，双方均无提示。（2026-10-20 决策，已经双会话运行时验证确认。）

### 数据变化

新建公司主档；系统分配编号并记录创建信息。

### 接口要求

Spec 未明确。

### 权限要求

客户列表「新建公司」为建立公司的唯一入口；具体角色权限 Spec 未明确。公司无删除入口。

### 边界条件

客户编号不可编辑；不支持自定义客户区分。

### 验收标准

- 保存成功后系统生成 C 开头连续编号（或沿用导入编号），编号不可编辑。
- 客户区分仅可在直販／代理中选择。

Spec 未明确。

### 权限要求

地址不可单独删除入口外的权限 Spec 未明确；不提供地址换所属。

### 边界条件

邮编严格 7 位数字；地址归属不可更换。

### 验收标准

## 64. REQ-063

### 需求名称

案内受付匹配与超期判断

### 需求目标

规定案内中每台产品的受付匹配规则与发行日 +30 天超期规则。

### 角色

系统（自动判断）；事务（查看跟踪）。

### 前置条件

案内已发行。

### 输入

受付事实（小番号及所属大番号实际受付日）。

### 正常流程

1. 受付日期必须在案内发行日当天或之后。
2. 一次受付只满足该产品在受付发生时已发行且包含该产品的最新一份案内；无需手选案内番号。
3. 超期日期 = 发行日 +30 天，不按自然月，按日本业务日期判断，到达即开始判断超期。
4. 到达超期日仍无匹配有效受付，该产品计入超期未受付；未到达为未受付；有匹配后显受付済み与实际受付日，不再计入超期。

### 异常流程

- 受付被删除或作废后：如有其他匹配有效受付显其中最早日期；如无则恢复未受付并按原发行日 +30 天判断是否超期；不得将其他案内受付转来填补。
- 实际受付日期更正后按更正事实重新判断。

### 业务规则

- 受付发生后新发行的案内不能使用此前受付满足；新案内不转移已匹配旧案内的受付。
- 同一产品在多份案内中时，匹配最新案内的受付不同时满足更早案内；旧案内不因新案内发行或被受付满足而解除超期，无匹配受付的旧案内允许一直显超期。
- 「最新」先按发行日由近到远，同一发行日按实际生成先后取最后一份，生成先后须唯一确定；未来发行日案内在到达发行日前不参与匹配。
- 匹配不限制案内種類或受付类型（点检与廃棄案内均候选）；仅表示产品实际来件，不表示已完成点检或确认报废。
- 有效受付指已建立且未删除、未作废的小番号；仅空包裹或空大番号不算受付；不要求完成登记、作业、报告或返送。
- 受付日使用所属大番号实际受付日；补填较早发行日不能使后生成案内满足过去受付。
- 最新案内已有受付后，之后受付不向前补配旧案内；同一案内多次匹配显最早一次受付日。
- 例：产品先后收到 9/1、9/10 发行案内，9/15 受付，只满足 9/10 案内；9/1 案内 10/1 起超期。

### 数据变化

案内中产品受付状态随受付事实变化。

### 接口要求

Spec 未明确。

### 权限要求

具体权限 Spec 未明确。

### 边界条件

受付状況按每份案内每台产品分别判断，不以产品历史是否曾受付为依据。

### 验收标准

- 匹配、超期、删除恢复、日期更正各场景均符合上述规则。

## 105. REQ-104

### 需求名称

## 109. 需求依赖关系

### 109.1 业务主线依赖

- 产品形成线：REQ-025（衣体入库/产品成立）→ REQ-026（部件组装绑定）→ REQ-028（质检通过）→ REQ-029（产品正式档案）。
  - REQ-026 依赖 REQ-025 已成立产品；REQ-028 依赖 REQ-026 满足最低构成；REQ-031/032 依赖产品已成立及质检状态。
- 订单出货线：REQ-041（订单）→ REQ-051/052（寄送准备）→ REQ-055（确认寄出）。
  - REQ-055 确认时才建立产品订单关系（依赖 REQ-028 质检通过取得出货资格），并写入生命周期基准月。
  - REQ-103（订单批量打印）依赖 REQ-051 准备中寄送，仅产生面单不改变事实。
- 生命周期线：REQ-055（首次出货产生基准月）→ REQ-059（候选判定）→ REQ-057/058（案内生成）→ REQ-064/065（通知查看跟踪）。
- 返厂闭环线：
  - REQ-066/067（大番号/包裹）→ REQ-068（单台受付/小番号）→ REQ-080～088（五组作业登记）→ REQ-089/090（报告）/ REQ-091（回收/报废确认）→ REQ-094～101（返送）。
  - REQ-102（返送批量打印）依赖 REQ-097 准备中返送面单。

### 109.2 主档/字典依赖

- REQ-018/019（部件资料）被 REQ-025、026、085、086 引用；个体采用后资料后续修改不回写。
- REQ-020（对外产品名称字典）被 REQ-041/042/048 引用（一个订单一种名称）。
- REQ-021（固件版本字典）被 REQ-087（固件升级）及 REQ-026（组装默认固件）引用。
- REQ-023（作业 NG/处置清单）被 REQ-080 引用，现场输入不回写清单。
- REQ-024（受付 NG 快捷选项）被 REQ-068/075 引用，仅作输入辅助。
- REQ-009～016（客户主档）被订单/通知/受付/出货/返送在成立时快照引用（REQ-017），主档后续变化不回写。

### 109.3 关键互斥/独立关系

- REQ-055（寄送确认寄出）与 REQ-047（解除产品关联）：确认建立关系，解除用于错误交付并扣减履约数。
- REQ-091 确认回收（结束关系、不扣减履约数）与 REQ-047 解除关联（否定交付、扣减履约数）为两个不同动作，不可混用。
- REQ-091 确认报废（终结产品/衣体编号、不级联部件）与 REQ-032 删除产品（退出当前范围、历史保留）语义不同。
- REQ-089/090（报告）独立于 REQ-091（回收/报废实际处理）：生成报告不代表已处理。
- REQ-098（返送确认寄出）不建立/结束订单关系；返送资格（REQ-101）排除已回收/报废产品。
- REQ-034/088（更换衣体事件）不改变身份、编号、绑定；与删除/重入库路径互斥。

### 109.4 删除依赖（阻断关系）

- 产品删除（REQ-032）阻断：当前部件绑定、质检记录、出货记录（含准备）、受付记录。
- 部件删除（REQ-040）阻断：仅当前有效绑定。
- 小番号删除（REQ-076）阻断：作业记录、报告、返送记录、确认回收、确认报废。
- 包裹/大番号删除（REQ-076/079）阻断：下层存在受付产品（小番号）。
- 寄送/返送准备（REQ-056/100）可随时删除并级联其全部文件版本；正式寄出后禁止删除。
