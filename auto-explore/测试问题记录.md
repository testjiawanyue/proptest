## 0. 使用规则（先查再报）

### 0.1 新增问题前必须做三步

1. 按「模块 + 用例编号」检索本文件，例如搜索 `产品列表查询-011`。
2. 再按「指纹关键词」检索行为特征，例如 `排序`、`并发覆盖`、`通用错误通知`、`加载态`。
3. 命中已有问题时，只在原问题下追加「复验记录」，不新建问题编号，不重复录入飞书。

快速检索命令：`rg -n "关键词|用例编号" E:\proptest\auto-explore\测试问题记录.md`

### 0.2 什么情况才算新问题

- 已有问题在**不同页面**出现，但根因相同：归入原问题，注明影响范围。
- 已有问题已被飞书标记「不修改」：仍可复验，但结论写「不修改已确认」，不得再次提交。
- 已有问题已被产品裁定「改用例/改基线」：更新用例口径，不再作为缺陷跟踪。
- 同一问题换一个用例编号再次出现：先比对根因和证据，确认不是同一问题后再新建。

### 0.3 状态口径

| 状态 | 含义 | 是否继续跟踪 |
|---|---|---|
| 新增 | 已录入飞书，待开发处理 | 是 |
| 修复中 | 开发已接单 | 是 |
| 待验收 | 开发称已修复，待测试复验 | 是 |
| 验收通过，待上线 | 已复验通过，等待发布 | 发布后关闭 |
| 已上线 | 已发布并验证 | 否 |
| 不修改 | 产品/业务确认保持现状 | 否，仅保留结论 |
| 未复现 | 无法稳定复现，需补证据 | 视情况 |
| 已撤销 | 用例删除或问题撤回 | 否 |
| 待确认 | 尚未人工审核或尚未录入飞书 | 是 |

### 0.4 每次测试结束必须登记

在「3. 测试批次索引」新增一行，至少写清：测试日期、模块、批次、执行条数、通过/不通过/部分验证/阻塞、新增或复验的问题编号、报告路径。没有登记批次的测试结果，不视为完成闭环。
