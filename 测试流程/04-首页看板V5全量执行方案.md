## 一、执行方式（两类验证）

| 类型 | 覆盖用例 | 怎么验 |
|---|---|---|
| **后端统计 API 验口径** | 订单一览 / 待办事项 / 厂内作业 / 今日作业 / 厂内库存 / 半成品（共 ~36 条） | 直接调 `GET /prop/dashboard`（或单测 `PropDashboardService.read()`），用种子数据断言六卡数字；适合跨日/报废/作废等需精确构造的场景 |

> 口径用例优先用后端 API + 种子数据自动断言（快、可回归）；UI 用例走 E2E。两条线都跑完才算 59 条全量执行。

## 二、测试环境 + 造数要求（前置）

- **活的测试环境**：部署 prop_new 后端 + ruoyi-ui 前端，连测试库。
- **跨模块造数**：口径用例需在测试库构造——订单(租赁/销售/替代，含部分发货/已发完/已结束/未填发货日)、受付(清洗/返送/今日)、作业(五组首次登记)、产品(在制品/成品/报废/作废/invalid)、绑定(气囊/传感器/发生器)。建议先写**种子数据 SQL/脚本**，按 VAL 分组准备数据集。
- **日本业务日**：环境时区按 `Asia/Tokyo`；跨日用例需能拨动 `businessToday()` 或造历史日期数据。
- **4 类权限账号**（D 组历史缺口）：管理员 / 普通角色 / 数据范围受限 / 未登录——用于页面跳转-006/008 权限显隐与页面展示-004。
